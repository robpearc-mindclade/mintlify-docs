## 1. Scope and non-goals

In scope: one checked `TargetBundle` emits four more public products, `public/openapi.json`, `public/echo.proto`, `public/mcp.json` and `public/README.md`. The field numbers in the Proto come from explicit current and previous authored registries. The current registry must cover exactly the current public payload. The comparison checks only field numbering and reservation compatibility. Output is a 13-file publication profile with a downgrade guard.

Non-goals (a candidate that includes any of these is out of scope):

- Proto is **messages-only**: no `service`/`rpc`, HTTP annotations, imports, options or requestId envelope. It is not a runtime ingress validator; proto3 cannot express JSON requiredness, literal codes, Unicode length, `maxItems` or byte limits, and B2b must not claim it does.
- `mcp.json` is tool **metadata**, not an MCP server, handler, transport or authorization.
- No runtime validator, HTTP adapter or RuntimeKit work (B3b); no OpenAPI/JSON-Schema validator dependency (consumer checks are structural comparisons against an independent fixture).
- **v1 only**: namespace `Mindclade.Public` at revision `v1`, mapped by a closed table to package `mindclade.public.v1`; other revisions are rejected, never relabelled.
- The registry comparison proves neither semantic/HTTP compatibility nor owner acceptance of the previous registry.
- No change to TypeSpec, SemanticInput@v1, the MindcladeGraph@v1 schema or `graph.json` bytes, the TS/Rust products, `contracts/protobuf/` (Proto-first), `generated/protobuf/` or `protocols/`; no Cargo or pnpm dependency.

## 5. Registry contract

The current registry is `contracts/registries/vs001-proto-fields.yaml`. The previous registry is `contracts/registries/vs001-proto-fields.previous.yaml`. Initially both hold these **identical** bytes, which the implementer copies exactly:

```yaml
schema: ProtoFieldRegistry@v1
messages:
  Mindclade.Public.EchoRequest: {fields: {message: 1, urgent: 2, tags: 3}, reserved_names: [], reserved_numbers: []}
  Mindclade.Public.EchoResponse: {fields: {message: 1}, reserved_names: [], reserved_numbers: []}
  Mindclade.Public.IdempotencyConflict: {fields: {code: 1, message: 2}, reserved_names: [], reserved_numbers: []}
  Mindclade.Public.InvalidInput: {fields: {code: 1, message: 2}, reserved_names: [], reserved_numbers: []}
  Mindclade.Public.Unavailable: {fields: {code: 1, message: 2}, reserved_names: [], reserved_numbers: []}
```

Codegen never writes either file. Changing the previous registry requires a reviewed change. The diagnostics are located at the supplied logical path with a positive 1-based line and column. Their messages are fixed and redacted: they never echo scalars.

| Rule | Code |
| --- | --- |
| Any strict-YAML violation (duplicate decoded key, anchor/alias, tag, merge key, multiple documents, non-string key, invalid UTF-8, NUL, any limit) | _existing_ `yaml-*` |
| Container shape and non-number positions only: root must be a mapping with exactly `schema` and `messages`; `schema` must be the string `ProtoFieldRegistry@v1`; `messages` a non-empty mapping; each message a mapping with exactly `fields` (mapping), `reserved_names` (sequence of strings) and `reserved_numbers` (sequence). A wrong node type in any of these positions. | `proto-registry-schema` |
| Message keys must be exactly `Mindclade.Public.<[A-Za-z_][A-Za-z0-9_]*>`, checked at structural parse before coverage. That rejects `Mindclade.Internal.RunReference`, package names, `@v1` suffixes and case conversion. Field and reserved names must be `[A-Za-z_][A-Za-z0-9_]*`. | `proto-registry-name` |
| In a number position (a `fields` value or a `reserved_numbers` item), any non-Integer node fails here, whether quoted, float, bool or null; the strict adapter classifies plain `0x1`, `1e1` and `1.0` as String. An Integer must be spelled `0\|[1-9][0-9]*`, within 1..536870911 and outside 19000..19999. That rejects `0`, `-1`, `+1`, `01`, `"1"`, `1.0`, `1e1`, `0x1`, `true`, `null`, `536870912`, `19000` and `19999`. It accepts `1`, `18999`, `20000` and `536870911`. | `proto-registry-number` |
| An active number may appear only once per message. Reserved names and reserved numbers may each appear only once. The same number in different messages is valid. | `proto-registry-duplicate` |
| An active name may not also be a reserved name, and an active number may not also be a reserved number. | `proto-registry-reserved` |
| The current registry's messages must equal the current payload closure (§6), and each field set must match exactly. This check applies only to the current registry. | `proto-registry-coverage` |
| The current and previous logical path strings are equal. | `proto-registry-source` |
| Read failures | _existing_ `source-path`/`source-root`/`source-type`/`source-size`/`source-io` |

Both registries get full structural validation. The previous registry is **not** checked for coverage, because no historical SemanticInput exists to check it against. Reads use the _existing_ bounded Unix reader: normalized relative path, confinement to the root after resolution, a regular file, an `O_NOFOLLOW|O_NONBLOCK` open, and a limit of 1 MiB inclusive. There is **no inode or alias rule**.

**Comparison** (runs after both parses and the current coverage check succeed; each rule is keyed by message):

1. If a previous message is missing from current, the finding is `message-removed`, class _unsupported_. Whole-message removal is unsupported.
2. A previous active field that is still active must keep its number. Otherwise the finding is `field-number-changed`.
3. If a previous active field is gone, the current registry must reserve **both** its old name and its old number. If it does, the finding is `field-removed-reserved`. If either is missing, the finding is `removed-field-unreserved`.
4. Every previous reserved name and number must still be reserved. Returning one to active use, or dropping it, gives `prior-reservation-lost`.
5. A new field gives `field-added` and a new message gives `message-added`. A new reservation that rule 3 does not explain gives `reservation-added`.

`field-added`, `field-removed-reserved`, `reservation-added` and `message-added` are _compatible_. `field-number-changed`, `removed-field-unreserved` and `prior-reservation-lost` are _incompatible_. An _unsupported_ finding takes precedence over an _incompatible_ one.

Each change item is exactly `{message, field: string|null, number: int|null, code, class}`, with content fixed per code:

| Code | `field` | `number` |
| --- | --- | --- |
| `message-added`, `message-removed` | null | null |
| `field-added` | field name | new number |
| `field-number-changed` | field name | previous number |
| `field-removed-reserved`, `removed-field-unreserved` | removed field name | previous number (one item per removed field) |
| `reservation-added`, `prior-reservation-lost` (one item per reserved name) | reserved name | null |
| `reservation-added`, `prior-reservation-lost` (one item per reserved number) | null | reserved number |

Items are sorted by message, then field (null first), then code, then number (null first). A report with any non-compatible item blocks generation. It then becomes a located `proto-registry-compatibility` diagnostic, or `proto-registry-unsupported` for a message removal, at the current registry.

A rename is a removal plus an addition. Changing only the order of entries changes nothing.

## 6. Product contracts

**Payload closure.** The closure is built from the resolved request body, the success response and each error response body of the single public operation, following public named references transitively. Membership is decided by graph Identity, never by a list of names to exclude. For the base input it is exactly `Mindclade.Public.{EchoRequest, EchoResponse, InvalidInput, IdempotencyConflict, Unavailable}`. The envelopes `InvalidResponse`/`ConflictResponse`/`UnavailableResponse`, the scalar `Tag` (resolved and inlined) and the operation `echo` are not payload messages and get no registry entry, component or message.

The supported field shapes form a closed set: required string or string literal, optional string, required bool, optional bool, and required array of string. Any other shape fails as `protocol-profile`. That includes int32, enums, unions, fields of named models, optional arrays, and a `format` on a payload string. `protocol-profile` also covers any package or payload declaration whose version is not `v1`, and any namespace other than `Mindclade.Public`.

**Leakage rule.** An internal declaration reached from a public declaration, directly or transitively, fails compilation or lowering with the _existing_ located `public-internal-reference` diagnostic. It must not be silently pruned. None of the four products may contain `Mindclade.Internal`, or any internal declaration name from the actual input as an exact-case whole token.

**Schema objects.** These are the independent expectation values, authored from `contracts/typespec/public/echo.tsp`. They are **not** copied from emitter output.

- `EchoRequest` = `{"type":"object","properties":{"message":{"type":"string","maxLength":4096},"urgent":{"type":"boolean"},"tags":{"type":"array","maxItems":128,"items":{"type":"string","maxLength":64}}},"required":["message","tags"],"additionalProperties":false}`.
- `EchoResponse` = `{"type":"object","properties":{"message":{"type":"string","maxLength":4096}},"required":["message"],"additionalProperties":false}`.
- `InvalidInput`, `IdempotencyConflict` and `Unavailable` each = `{"type":"object","properties":{"code":{"type":"string","const":C},"message":{"type":"string"}},"required":["code","message"],"additionalProperties":false}`, where `C` is `invalid_input`, `idempotency_conflict` and `unavailable` respectively.

In every schema, `required` is sorted and always present. Optional never means nullable.

**`public/openapi.json`** is canonical JSON (_existing_ `canonical::to_bytes`).

- Its top-level keys are exactly `openapi`, `jsonSchemaDialect`, `info`, `x-mindclade-transport-profile`, `paths` and `components`.
- `openapi` is `3.1.0`.
- `jsonSchemaDialect` is `https://json-schema.org/draft/2020-12/schema`.
- `info` is `{title: "Mindclade.Public", version: "v1", description: <non-empty>}`.
- `x-mindclade-transport-profile` is `{identity: "VS001TransportProfile@v1", max_body_bytes: 65536}`.
- `components` has exactly `{schemas: {<the five objects above, keyed by short name>}}`.
- `paths` has exactly `/echo/{requestId}` → `post`, which contains:
  - `operationId: "echo"`.
  - `parameters`: one entry, `{name:"requestId", in:"path", required:true, schema:{type:"string", pattern:"^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$"}}`.
  - A `requestBody` that is required, with `application/json` → `$ref` `#/components/schemas/EchoRequest`.
  - `responses` exactly `200/400/409/503`. Their descriptions are `Success`, `Invalid input`, `Idempotency conflict` and `Unavailable`. Each has `application/json` → a local `$ref` to `EchoResponse`, `InvalidInput`, `IdempotencyConflict` and `Unavailable` respectively.
- A `$ref` has no sibling keys. The document has no servers, security, remote references or other operations.

**`public/echo.proto`**:

- UTF-8, LF, one trailing newline; `syntax = "proto3";` and `package mindclade.public.v1;`; no imports, options, services, enums or extensions; a do-not-edit header comment with no timestamp or host.
- The five messages in order of full semantic identity, fields in ascending number: `message`/`code` are `string`, `urgent` is `optional bool` (proto3_optional), `tags` is `repeated string`.
- Reservations: one `reserved` numbers statement (ascending), then one names statement (lexicographic); each omitted when empty.

**`public/mcp.json`** is labelled custom metadata, canonical JSON, with exactly these top-level keys (each tool entry is a spec-valid MCP Tool; custom data lives only in the tool's `_meta`):

- `schema: "McpToolCatalog@v1"`; `transport_profile` identical to the OpenAPI extension value.
- `tools`: one tool with keys exactly `name` (`echo`), `description` (non-empty), `inputSchema`, `outputSchema`, `_meta`:
  - `inputSchema` is `{$schema:<2020-12>, type:"object", properties:{requestId:<the path schema above>, body:<the EchoRequest object, inline>}, required:["body","requestId"], additionalProperties:false}`.
  - `outputSchema` is the EchoResponse object plus `$schema`.
  - `_meta` has exactly `http` = `{method:"POST", route:"/echo/{requestId}", media_type:"application/json"}` and `errors`, which maps `"400"`, `"409"` and `"503"` to `{code, description, schema:<the error object plus $schema>}`.
- It contains no `$ref`.

**`public/README.md`** has one H1 containing `Mindclade.Public`, `echo` and `v1`, followed by these H2 sections in this order:

1. `Operation`: must contain `POST /echo/{requestId}`, `application/json` and the requestId pattern, plus links to `openapi.json`, `echo.proto` and `mcp.json`.
2. `Request`: a table with the header `| Field | JSON type | Required | Constraints |` and exactly these rows, ordered by registry field number: `message | string | yes | maxLength 4096`, `urgent | boolean | no | none` and `tags | array of string | yes | maxItems 128; items maxLength 64`.
3. `Responses`: a table with the header `| Status | Code | Body | Description |` and exactly these rows: `200 | none | EchoResponse | Success`, `400 | invalid_input | InvalidInput | Invalid input`, `409 | idempotency_conflict | IdempotencyConflict | Idempotency conflict` and `503 | unavailable | Unavailable | Unavailable`.
4. `Validation`: must contain the phrases `Unicode scalar values`, `65536 bytes`, `malformed Unicode is rejected`, `unknown properties are rejected` and `omitted urgent is distinct from false`.
5. `Projection limits`: must contain the phrases `messages-only`, `not a runtime ingress validator`, `requestId is carried by HTTP and MCP metadata`, `not an MCP server` and `no running service, deployment or qualification`.

The tests compare the cells and phrases (case-sensitive) within each section. They do not snapshot other prose.

## 7. Publication

The protocol profile owns exactly **13** files under `SOURCE_ROOT/generated/vs001`: `graph.json`, `public/{README.md,client.ts,echo.proto,mcp.json,openapi.json}`, `rust/{internal,mod,public,wire}.rs`, `service/{config.rs,descriptor.json}` and `manifest.json`. The manifest hashes the **12** other outputs, never itself. The only new variable input is the registry bytes: registries are not TypeSpec sources or generator inputs, and `graph.json` does not change.

These transitions are allowed: fresh → 13; any valid complete 7-file (legacy) or 9-file (service) predecessor → 13, directly; and 13 → 13.

Downgrade guard: under the _existing_ writer lock, `check_ownership` calls `check_profile_transition(prior, new)` **before staging**. `recover` calls the same check **before any removal or replacement**. It takes the prior manifest from the journal's `prior_manifest` bytes if present. Otherwise it uses the on-disk manifest, while that manifest still matches the digest of the journal entry's `previous`. These fail `projection-profile`, preserving bytes, journal and stage: a Protocol prior with an Unlabelled target; an unknown `product_profile` on either side; a Protocol label whose output names are not exactly the 12 above. With no `prior_manifest` and the on-disk manifest already equal to the target, the transition is already committed and recovery completes (tested in B2b-19).

The existing behaviour for legacy ↔ service transitions, stale-output cleanup and cross-catalog journal rejection (`publication-journal`) does not change. There is no second lock, publisher or journal schema.

The stage entries for 13 files are `entry-0`..`entry-12`. Whatever single vs001 `entry-[…]` line is on the base (`entry-[0-6]` at `06a903f`; `entry-[0-8]` after pending PR #12) becomes exactly `/generated/vs001/.publication/stage-[0-9]*-[0-9]*/entry-[0-9]` and `/generated/vs001/.publication/stage-[0-9]*-[0-9]*/entry-1[0-2]`.

## 8. Acceptance criteria

Every negative case exits 1 with the named code, located as §5 specifies (a panic, traceback, signal, timeout or other code does **not** satisfy it), and leaves absent/existing output, any pending journal and receipts unchanged (snapshot-compared). Expected values come only from the authored fixture `protocol_expectations.json` and this document, never from emitter output or another generated product. Targets (proposed): **U** `//codegen:unit_tests` (crate-unit modules); **P** `//tests/conformance/vs001:protocol_products`; **D** `…:proto_descriptor`; **R** `…:protocol_driver` (real codegen binary, temporary checkouts); **S** `scripts/{test_projection,test_protocol_wrapper}.py` via `just verify-fast`.

| ID | Criterion: positive control, then negatives | Pinned by |

## 6. Product contracts

**Payload closure.** The closure is built from the resolved request body, the success response and each error response body of the single public operation, following public named references transitively. Membership is decided by graph Identity, never by a list of names to exclude. For the base input it is exactly `Mindclade.Public.{EchoRequest, EchoResponse, InvalidInput, IdempotencyConflict, Unavailable}`. The envelopes `InvalidResponse`/`ConflictResponse`/`UnavailableResponse`, the scalar `Tag` (resolved and inlined) and the operation `echo` are not payload messages and get no registry entry, component or message.

The supported field shapes form a closed set: required string or string literal, optional string, required bool, optional bool, and required array of string. Any other shape fails as `protocol-profile`. That includes int32, enums, unions, fields of named models, optional arrays, and a `format` on a payload string. `protocol-profile` also covers any package or payload declaration whose version is not `v1`, and any namespace other than `Mindclade.Public`.

**Leakage rule.** An internal declaration reached from a public declaration, directly or transitively, fails compilation or lowering with the _existing_ located `public-internal-reference` diagnostic. It must not be silently pruned. None of the four products may contain `Mindclade.Internal`, or any internal declaration name from the actual input as an exact-case whole token.

**Schema objects.** These are the independent expectation values, authored from `contracts/typespec/public/echo.tsp`. They are **not** copied from emitter output.

- `EchoRequest` = `{"type":"object","properties":{"message":{"type":"string","maxLength":4096},"urgent":{"type":"boolean"},"tags":{"type":"array","maxItems":128,"items":{"type":"string","maxLength":64}}},"required":["message","tags"],"additionalProperties":false}`.
- `EchoResponse` = `{"type":"object","properties":{"message":{"type":"string","maxLength":4096}},"required":["message"],"additionalProperties":false}`.
- `InvalidInput`, `IdempotencyConflict` and `Unavailable` each = `{"type":"object","properties":{"code":{"type":"string","const":C},"message":{"type":"string"}},"required":["code","message"],"additionalProperties":false}`, where `C` is `invalid_input`, `idempotency_conflict` and `unavailable` respectively.

In every schema, `required` is sorted and always present. Optional never means nullable.

**`public/openapi.json`** is canonical JSON (_existing_ `canonical::to_bytes`).

- Its top-level keys are exactly `openapi`, `jsonSchemaDialect`, `info`, `x-mindclade-transport-profile`, `paths` and `components`.
