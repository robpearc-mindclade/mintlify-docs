This page defines the frozen acceptance criteria for the T1 transport engine swap. It specifies how RuntimeKit's synchronous `std::net` HTTP/1.1 engine becomes hyper 1.x on tokio, behind the existing `Handler` interface, after C4 and before C5.

<Warning>
  These criteria are draft and await fresh criteria review and Rob's checkpoint A. Nothing here is implemented or run. It grants no dependency approval, admission, acceptance, or qualification.
</Warning>

## 1. Scope and non-goals

In scope: the engine only. Accept, connection I/O, framing handoff, response writing, deadlines, admission, and drain move onto hyper's HTTP/1 server connection and a tokio runtime owned by RuntimeKit, plus one additive trace-header accessor pair (section 3.3). The B3b framing, limit, and shutdown tests stay the conformance suite (ADR-017 section 2).

Unchanged unless section 3.5 lists a reviewed amendment (all existing): `serve`, `RunningService::{address, shutdown}` and its draining `Drop`; `Handler`, `Request`'s four accessors, `Response::{json, empty, with_allow}`, `RequestScope::{deadline, cancelled}`; every `RuntimeError` variant, `ShutdownFailure::Overrun` and `OverrunWorkers::{len, is_empty, join}` with its joining `Drop`; `EventKind::ALL` (14), `Reason::ALL` (21) and the seven-field `Event`; `config.rs`; Echo's `Stopped`, receipts and exit codes 0/1/3/4/5; and `max_in_flight` bounding both connections read and concurrent `Handler::handle` calls, with the permit taken before `accept` and released after the terminal event.

Non-goals, each a boundary: keep-alive, pipelining and response streaming (Q1); HTTP/2, h2c, HTTP/3, in-process TLS (ADR-017 section 3), WebSockets, `Upgrade`; MCP or gRPC transport; new `ServiceConfig` fields; any trace field in telemetry (ADR-008 amendment, decided at C0); any change to the Echo contract, the generated adapter or its emitter; consolidating `postgres` onto RuntimeKit's runtime (ADR-017 Consequences).

## 3. Interfaces

### 3.1 Contract baseline

`VS001TransportProfile@v1` (`generated/vs001/public/openapi.json` `x-mindclade-transport-profile`, `mcp.json`, generated README, TS client) publishes `max_body_bytes: 65536` and eleven empty-body rejections: 400, 404, 405 (`Allow`), 411, 413, 415, 417, 431, 500, 501, 505. It does not publish `connection: close` or one request per connection; those are "current service behaviour beyond the contract" and frozen B3b behaviour asserted by frozen tests.

### 3.2 Byte-compatibility contract (normative)

Every response the new engine writes equals, byte for byte, what `serialize` writes today for the same `Response`:

```text
HTTP/1.1 <status> <reason>\r\n
[content-type: application/json\r\n]          only for Response::json and a valid status
[allow: <value>\r\n]                          only if with_allow and is_allow_value, valid status
content-length: <body length>\r\n
connection: close\r\n
\r\n
<body>
```

- **Reason phrases** are RuntimeKit's table, not `http`'s: 413 is `Content Too Large` (http 1.5.0: `Payload Too Large`), 422 `Unprocessable Content`, and an unlisted status has an empty phrase (`HTTP/1.1 418 \r\n`; hyper writes `<none>`).
- **Headers** exactly as above: lowercase, in that order, no `date`, nothing else. A status outside 200-599 or a panic gives an empty 500 with `allow` dropped.
- **Limits, unchanged:** `MAX_HEAD_BYTES = 8192`, `MAX_HEADER_FIELDS = 32`, `LINGER_EXTRA_BYTES = 8192`, `max_body_bytes` 65536; 413 before any body byte; B3b section 3.3's four absolute deadlines on `std::time::Instant`, clipped to drain start + `shutdown_timeout`; the bounded lingering close.

What may change: nothing on the wire. Internally only: thread names after the `mindclade-rt-` prefix, the listen backlog, scheduling inside the B3b tolerances (-50 ms/+1500 ms), and how drain wakes the accept loop.

### 3.3 Trace-header exposure (proposed)

C Amendment 3 (A3.2, seventh C0 item) needs "a RuntimeKit accessor for the raw `traceparent` and `tracestate` fields" feeding `TraceContext::from_fields(traceparent: &[&[u8]], tracestate: &[&[u8]])`. T1 proposes it (Q3):

```rust
impl Request {
    /// Every `traceparent` field of the head, in received order, OWS-trimmed.
    pub fn traceparent_fields(&self) -> Vec<&[u8]>;
    /// Every `tracestate` field of the head, in received order, OWS-trimmed.
    pub fn tracestate_fields(&self) -> Vec<&[u8]>;
}
```

Names match ASCII case-insensitively. One element per field line: no comma splitting, joining, dedupe, validation or decoding; an absent header gives an empty `Vec`. Validation stays in C's `TraceContext` (A3.1: two parsers never coexist). Values are bounded by the existing head limits and hold only bytes the pre-scan admits. Nothing else widens: no generic `header(name)`, no header map, no hyper, `http`, `tokio` or `bytes` type in a public signature. `Request` retains exactly method, target, content type, body and these two lists. No trace text enters telemetry, `RuntimeError` text or any RuntimeKit-written body. The adapter, `AdmissionPort::execute`, the contract and telemetry stay C0's (A3.2); the emitter does not change in T1.

### 3.4 Engine requirements (normative, each observed by section 5)

- **E1** hyper's `server::conn::http1` connection with `keep_alive(false)` and `auto_date_header(false)`; no `http2`, `server-auto` or upgrades. Handler bodies reach hyper only through RuntimeKit's own `http_body::Body` impl.
- **E2** RuntimeKit's existing grammar (`Scanner`, `is_origin_form`, `parse_length`, `parse_head`) decides every head before hyper or the handler acts on it, and its frozen unit tests keep calling the functions the engine calls.
- **E3** Every RuntimeKit thread name starts with `mindclade-rt-` (runtime threads included). `Handler::handle` runs on a RuntimeKit-owned thread outside any async execution context, so a handler may `block_on` its own runtime (the synchronous `postgres` client does, C section 3 OD-2).
- **E4** Socket deadlines are absolute and derived from `std::time::Instant`; tokio `test-util` and paused time are absent; the injected `Clock` stamps telemetry only.
- **E5** Workers: the accept task and one worker per accepted connection (its task plus its handler thread, if any). `worker_exit` for a connection is recorded only after both finished, so the B3b-12 count `accepted + 1` is unchanged. A worker alive at drain limit + 250 ms is an overrun, never dropped with the runtime.

Recommended shape (Q5, not normative): one current-thread runtime on `mindclade-rt-io`; a gate judges the head and writes a rejection itself or hands prefix and stream to hyper; each handler call on a `mindclade-rt-conn` thread; `.without_shutdown()` returns the stream for lingering.

## 5. Acceptance criteria

Conventions: B3b section 5's harness bounds (10 s; 60 s for the transfer guard) and tolerance (-50 ms/+1500 ms) apply unchanged. Base is the post-C4 source with the section 4 lock landed. **RED** is a behavioural failure on base; **Regression** is GREEN on base and must stay GREEN; a missing API's compile error is wiring, not RED (B3b C2). Targets exist unless marked.

**T1-01 Engine identity.** RED: base serves on `std::net` with no hyper.

- P: the scanned sources call `hyper::server::conn::http1::Builder` and `serve_connection` with E1's settings, and the serving path has no `std::net::TcpStream` I/O or socket timeouts.
- N: keeping the `std::net` engine and only adding dependencies fails.
- Target: `//platform/runtimekit:transport_tests` (section 3.5 item 4 scan).

**T1-02 Idle connections cost no thread.** RED: base spawns a `mindclade-rt-conn` per connection.

- P: at `max_in_flight = 64`, 64 accepted idle connections leave the thread census (Linux `/proc/self/task/*/comm`, macOS `ps -M` count) equal to its value with none; with 8 handlers gated it is at most that value + 8.
- N: base (+64); runtime threads under tokio's default `tokio-runtime-w` name.
- Target: `//platform/runtimekit:shutdown_tests` (single-test binary; new phase).

**T1-03 Responses are byte-identical.** Regression.

- P: golden bytes built from section 3.2's template (not recorded from a draft engine) for every row of the table, 404, 405 `allow: POST`, 415, a handler panic (500), status 1000 (500, `allow` dropped), JSON 200/400/409/503, statuses 413 and 422 from a handler, and status 418 (`HTTP/1.1 418 \r\n`). The raw socket bytes up to EOF equal the golden.
- N: a `date` header; `Payload Too Large`; `<none>`; a reordered or title-cased header; `content-type` on an empty body; missing `connection: close`.
- Targets: `:transport_tests`; `:unit_tests` (section 3.5 item 5).

**T1-04 HTTP versions.** Regression.

- P: HTTP/1.1 is served; `HTTP/1.0` gets section 3.2's exact 505 and no handler call.
- N: `HTTP/1.2`, `HTTP/2.0`, `PRI * HTTP/2.0\r\n\r\nSM\r\n\r\n` and `GET /x\r\n` get 400 `malformed`; `Upgrade: h2c` on 1.1 gets 200, never 101; hyper's defaults fail. `:transport_tests`.

**T1-05 Expect never produces an interim response.** Regression.

- P: a head with `Expect: 100-continue` and `Content-Length: 10`, sent without a body, reads exactly the 417 bytes, then EOF; no `HTTP/1.1 100` bytes; telemetry `rejected/expectation`.
- N: `Expect: foo`, an empty `Expect` and two `Expect` fields get the same; hyper answering `100 Continue` fails. Target: `:transport_tests`.

**T1-06 One request per connection.** Regression.

- P: two pipelined valid requests on one socket give one response with `connection: close`, then EOF, and one handler call; `Connection: keep-alive` still gets `connection: close`.
- N: hyper's default `keep_alive(true)`; a second handler call from the same socket.
- Target: `:transport_tests` (with B3b-06's CL 10 + 70 000 bytes case).

**T1-07 Framing no more permissive than today.** Regression over the whole B3b-05/06 corpus, plus the cases where hyper or httparse defaults diverge, each with its section 3.2 status and reason:

- N: a leading empty line and bare LF (httparse skips or accepts them) gives 400; chunked with and without Content-Length (hyper decodes chunked) gives 411; `Transfer-Encoding: identity` gives 501; 33 fields (hyper's default is 100) gives 431; an 8193-byte head gives 431; `CONNECT a:1 HTTP/1.1` gives 400 `target`; `Content-Length: 65537` with the head only gives 413 before any body byte; a header name with a space before the colon gives 400.
- P: B3b-05's exact 8192-byte, 32-field head is accepted. Target: `:transport_tests`.

**T1-08 Deadlines and admission under async.** Regression: B3b-07/08/09/11/14 as written.

- P, reactor independence: `max_in_flight = 2`; connection A's handler blocks on a test gate, ignoring `scope`; connection B trickles its head one byte per 50 ms with `request_timeout` 300 ms. B closes at `Dh` with `deadline/header` while A is still blocked.
- N: `Handler::handle` on the runtime thread (B closes only after the gate). `:transport_tests`.

**T1-09 Handler context and the permit bound.** Regression.

- P: a handler that builds a tokio current-thread runtime and `block_on`s an empty future returns 200 (what C5's synchronous `postgres` calls do).
- P: `max_in_flight = 1`. A's client disconnects while its handler is gated. B connects and sends a full request. B's `accepted` follows A's `write_failed`, which follows the gate opening; at most one handler call is ever in progress.
- N: a handler inline on the runtime or under `block_in_place` (panics "Cannot start a runtime from within a runtime"); releasing the permit when hyper drops the service future.
- Target: `:transport_tests`.

**T1-10 Cancellation semantics.** Regression: B3b-10 and B3b-12's cooperative handler.

- P: a client disconnect never sets `scope.cancelled()`; the handler completes once, the write is `write_failed`, no retry. `cancelled()` turns true at drain start, on the lifecycle `ShutdownSignal` and after the handler deadline. Each inbound connection a drain closes records one `deadline/shutdown` and one `worker_exit`. A client that shuts down its write half after a complete request still gets the full response and `completed`.
- N: aborting tasks (`abort_all`, dropping a `JoinSet`) without that accounting.
- Target: `:transport_tests`, `:shutdown_tests`.

**T1-11 Finite shutdown; no leaked task or thread.** Regression, with section 3.5 item 2.

- P: B3b-12's five held connections, at capacity and above, plus a backlog connection: `shutdown` is `Ok` within `shutdown_timeout + 1000 ms`; `worker_exit` = `accepted` + 1; one terminal event per `accepted`; a later connect is refused; the backlog connection is never served; the census is back to baseline, with no `mindclade-rt-` or `tokio-` thread on Linux.
- N: `Runtime::shutdown_background` or `shutdown_timeout`; polling wake-ups (`time::sleep(`, `interval(`); returning before every `worker_exit`; dropping a live task with the runtime.
- Target: `:shutdown_tests`; static part in `:transport_tests`.

**T1-12 Overrun is truthful.** Regression, with section 3.5 item 2.

- P: a non-cooperative handler makes `shutdown` return `Err(Shutdown(Overrun(w)))` within `shutdown_timeout + 1000 ms`, with no `worker_exit` for it. After the gate opens, `w.join()` returns, `worker_exit` appears, and the census returns to baseline. Dropping `RunningService` instead emits `overrun` and blocks until the handler returns (B3b-13's drop test).
- N: `Ok`; a detached thread or `mem::forget`; `OverrunWorkers` that no longer owns what keeps the handler running; a `Drop` that returns before it finishes.
- Target: `:overrun_tests`.

**T1-13 Failures before serving leave nothing running.** Regression: B3b-04.

- P: an occupied port gives `RuntimeError::Bind`, `bind_error`, no `ready`; an identity mismatch gives `RuntimeError::Identity` before binding; after each the census equals its pre-`serve` value. A runtime or thread build failure maps to `transport_failed`/`accept` and `RuntimeError::Transport(kind)` (reviewer; no new variant).
- N: building the runtime before the identity check and leaving its thread. Targets: `:transport_tests`, `:shutdown_tests`.

**T1-14 Trace fields reach the handler, and nothing else does.** New API: its compile error is wiring, not RED; the negatives below are the discriminating evidence.

- P: one `traceparent` and two `tracestate` fields (mixed-case names, values padded with SP and HTAB) reach a recording handler as the exact trimmed values, in order; none gives empty.
- N: two `traceparent` fields give two elements; a malformed value arrives unchanged; a 0x80 byte in `traceparent` is still 400 `malformed` with no handler call.
- N: `traceparent`/`tracestate` canaries appear in no telemetry line, `RuntimeError` `Display`/`Debug` or RuntimeKit-written body (extends B3b-15).
- N: `request.header("authorization")` does not compile (beside a compiling `traceparent_fields` sibling); no `pub` item in `src/**` names `hyper`, `http::`, `http_body`, `tokio`, `bytes` or `HeaderMap`.
- Targets: `:transport_tests`; `:unit_tests`; new `//platform/runtimekit:doc_tests` (parent-added).

**T1-15 Closed sets and exit codes unchanged.** Regression.

- P: `EventKind::ALL` and `Reason::ALL` equal B3b section 3.4's lists in order, strings and levels; `config.rs` and `telemetry.rs` are byte-identical to base. N: any new event or reason (for example a hyper error kind). Targets: `:transport_tests`; `//services/foundation_echo:process_tests`.

**T1-16 Dependency direction.** RED once section 3.5 item 3 lands: base lacks the new crates.

- P: `cargo metadata --locked` gives RuntimeKit normal deps exactly `{mindclade-core, httparse, hyper, hyper-util, http, http-body, tokio, bytes}`; Bazel direct deps are `//core:core` plus those seven `@crates//` labels; the closure has no `//services`, `//codegen`, `//platform/testkit`, `//tests`, `//generated` or `saphyr` label; Echo's set is C section 5.6(1)'s.
- N: `http-body-util`, `tokio-macros`, `h2` or a seventh new package. Target: `:dependency_tests`; K3.

**T1-17 Consumers unchanged end to end.** Regression.

- P: `//services/foundation_echo:composition_tests` (B3b-19-25, 27: generated client, exit 3 probes, process bounds matrix, drain exit 0 within 7 s, no restart state) and `//tests/conformance/vs001:all` (B3b-18, K1-15, K1-30, `connection: close`) pass unmodified; regenerated products are byte-identical except the two manifests. Targets: those; K7.

## 7. Stop conditions

- **S1** T1-11 or T1-12 cannot be proven on either host; never weaken it (ADR-017 section 5).

- **S5** `unsafe` in a repository crate, or a crate not in section 4.1.
- **S6** A test needs a sleep outside `pace`, a longer harness bound or a wider tolerance.
- **S7** The emitter must change, or a generated product byte other than a manifest changes.
- **S8** C0's approved criteria define a different RuntimeKit trace accessor, or C0 lands first.
- **S9** crate_universe re-splice or `MODULE.bazel.lock` fails on either host.
- **S10** A frozen B3b test needs an edit that section 3.5 does not list.
