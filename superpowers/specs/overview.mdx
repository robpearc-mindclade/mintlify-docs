This directory holds the acceptance criteria that bound each gate, plus the VS-001 design they elaborate. A WorkPacket binds a criteria file by path and SHA-256 (\`spec.path\`, \`spec.sha256\`; checked against the committed bytes by \`tools/engineering/admission.py\`), so moving or editing a bound file breaks that binding. \`docs/specs/\` is a separate, reserved blueprint path.

A criteria file's status says whether the criteria are settled. It does not say whether the gate is implemented; the [current task register](/developer/agent-handoff#current-task-register) owns that.

This table only names the criteria that bind each pending item and says whether a fresh implementer can start from tracked files:

- READY: frozen criteria give the IDs, paths, checks and stop conditions, and nothing blocks the next test-author or implementer pass. The parent still runs every check.
- NEEDS-OWNER: blocked on a named decision by Rob or the contract owner.
- NEEDS-CRITERIA: no frozen criterion covers the work yet. The linked plan or record defines it; criteria are written, reviewed and frozen first.
- OPERATOR: not code work. The parent or Rob runs it.
- INTEGRATION: focused source/review evidence exists; the whole candidate and required CI remain pending.

Start a READY item from current \`main\`, and re-check its cited lines there before RED, as its criteria require.
