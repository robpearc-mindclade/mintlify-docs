## 1. Scope and non-goals

In scope: the pure checked `ServiceConfig` ABI; a bounded HTTP/1.1 transport in RuntimeKit that serves one generic, product-neutral handler; TestKit deterministic collaborators; a Codegen-emitted Echo HTTP adapter; the Foundation Echo composition and binary using the generated config; real-socket and generated-client evidence on Apple Silicon and Linux.

Non-goals, each an explicit boundary rather than a pending promise:

- **Non-durable.** `TestAdmission` is an in-memory, stateless, explicitly non-durable collaborator. It stores nothing, implements no idempotency store and never produces 409; state is lost on restart. Nothing is labelled durable.
- No PostgreSQL connection, migration, outbox, lease, worker or Run. C1–C5 own those. `dependencies.postgres.required` stays `false`.
- **Socket disconnect is not Run cancellation.** A client disconnect never cancels admitted domain work. Cancellation observed by domain code comes only from service shutdown or the service's own deadline, never peer behaviour.
- No TLS, HTTP/2, keep-alive, pipelining, chunked or other transfer codings, `Expect: 100-continue`, HTTP health route, MCP server, deployment or multi-replica topology. There are no new `ServiceConfig` fields.
- No `unsafe` code (workspace lint `unsafe_code = "forbid"`). Therefore no POSIX signal handler; graceful supervisor control uses stdin (§3.6).

## 2. Transport decision

Question: which transport can _prove_ absolute header and body deadlines, byte limits, pre-header admission bounds and finite shutdown, including for connections already handed to handlers, without abandoning threads?

### 2.1 Capability matrix

### 2.2 Evidence

- tiny_http `Server` docs say `recv_timeout` is "Same as `recv()` but doesn't block longer than timeout". The source implements it as `self.messages.pop_timeout(timeout)`, which bounds only the queue wait. The Drop docs say "Requests that have already been returned by the `recv()` function will not close". This confirms the plan's warning. Sources: [Server docs](https://docs.rs/tiny_http/0.12.0/tiny_http/struct.Server.html); [lib.rs](https://github.com/tiny-http/tiny-http/blob/master/src/lib.rs): the accept loop is started with a `thread::spawn` whose handle is dropped, and Drop self-connects to wake `accept`.
- The tiny_http pool is unbounded and never joined. Its source says: "If no thread is available, spawns a new one". Its Drop only stores a sentinel and calls `notify_all` ([task_pool.rs](https://github.com/tiny-http/tiny-http/blob/master/src/util/task_pool.rs)). The eagerly read body of ≤1024 B and the unconditional chunk decoder for any TE value are in [request.rs](https://github.com/tiny-http/tiny-http/blob/master/src/request.rs). [client.rs](https://github.com/tiny-http/tiny-http/blob/master/src/client.rs) sets no socket read or write timeouts.
- tiny_http advisories: CVE-2026-66752 (TE smuggling; CVSS 4.0 6.3 / 3.1 5.4) and CVE-2026-66753 (CR/LF injection; 4.0 6.3 / 3.1 3.7), both "through 0.12.0", NVD status Deferred ([66752](https://services.nvd.nist.gov/rest/json/cves/2.0?cveId=CVE-2026-66752), [66753](https://services.nvd.nist.gov/rest/json/cves/2.0?cveId=CVE-2026-66753); [OpenCVE](https://app.opencve.io/cve/CVE-2026-66752)). Both are open issues ([#287](https://github.com/tiny-http/tiny-http/issues/287), [#288](https://github.com/tiny-http/tiny-http/issues/288)). RustSec lists only RUSTSEC-2020-0031 for tiny_http, so `cargo-audit` will not flag them. Maintainer request: [#286](https://github.com/tiny-http/tiny-http/issues/286). Releases: [crates.io versions](https://crates.io/crates/tiny_http/versions).
- hyper's header deadline is armed once in `Conn::poll_read_head` as `timer.now() + h1_header_read_timeout` and is not reset by incoming bytes (local source `hyper-1.11.1/src/proto/h1/conn.rs`). See [Builder::header_read_timeout](https://docs.rs/hyper/1.11.1/hyper/server/conn/http1/struct.Builder.html#method.header_read_timeout), which "Requires a Timer", and [GracefulShutdown](https://docs.rs/hyper-util/0.1.20/hyper_util/server/graceful/struct.GracefulShutdown.html).
- Tokio's runtime docs: "Blocking functions spawned through `spawn_blocking` keep running until they return … When the timeout is reached, spawned work that did not stop in time and threads running it are leaked" ([Runtime § Shutdown](https://docs.rs/tokio/1.53.1/tokio/runtime/struct.Runtime.html#shutdown)). So (b) does not remove the amendment's cooperative-handler requirement.
- Rust std: `TcpStream::shutdown` "will cause all pending and future I/O on the specified portions to return immediately". A second call returns `NotConnected` on macOS and `Ok` on Linux. `set_read_timeout` returns `Err` for a zero Duration, and Unix reports timeouts as `WouldBlock`. `try_clone` shares one socket ([TcpStream](https://doc.rust-lang.org/std/net/struct.TcpStream.html)). Implementations must treat `WouldBlock` and `TimedOut` as deadline expiry, never pass a zero timeout, and tolerate `NotConnected` on a repeated close.
- httparse ([docs](https://docs.rs/httparse/1.10.1/httparse/), [repo](https://github.com/seanmonstar/httparse)) tokenizes only; it does no framing, body handling or I/O. It uses internal `unsafe` (SIMD), and its build.rs runs `$RUSTC --version` to gate features (1.59). It accepts bare LF, leading empty lines, and `#`, `{` and 0x80–0xFF bytes in the request target (local source `httparse-1.10.1/src/lib.rs`, e.g. `skip_empty_lines`), hence RuntimeKit's **required pre-scan** rejecting all of these before tokenizing. A fixed header array bounds the header count (`TooManyHeaders`).
- Bazel today uses one `crate.from_cargo` over root `Cargo.toml`/`Cargo.lock` for `aarch64-apple-darwin`, `x86_64-apple-darwin` and `x86_64-unknown-linux-gnu`, and packages consume `all_crate_deps`. Any new crate or workspace member changes `Cargo.lock`, `MODULE.bazel.lock` and the generator source fingerprint/`dependency_locks` in `generated/vs001/manifest.json`, so generated output must be regenerated through Codegen (parent-owned).

### 2.3 Recommendation

**Option (c): an in-house, bounded, synchronous HTTP/1.1 server over `std::net::TcpListener`/`TcpStream`, using `httparse` only to tokenize the request head.**

Only (b) would supply the I/O half of the bounds (deadlines, framing, connection teardown) from a library, and even (b) cannot finish a synchronous callback, so handler finality is RuntimeKit code in every option. (c) adds one widely used, fuzzed, dependency-free tokenizer to the smallest correct design and keeps it deterministic, boring Rust. **Rob must approve exactly: `httparse = "=1.10.1"` (default features, `std`), with no transitive crates.**

- **Fallback if declined:** option (d). The criteria below are unchanged: a closed-grammar tokenizer (~200 lines) replaces httparse and gains the extra tokenizer corpus in B3b-05.
- **Escalation:** if the finite-shutdown probe (B3b-12/13) fails on either host, **stop** and prepare a reviewed amendment that evaluates (b). Do not weaken the criteria.
- tiny_http is rejected on the evidence above.

## 3. Interfaces (proposed; exact paths confirmed at criteria review)

### 3.1 Configuration

Configuration is `mindclade_runtimekit::config` exactly as in service-config-v1 §1–§2 (`ServiceConfig::new`, eleven arguments, `ConfigError`, the zero-argument generated `build_service_config`). B3b adds nothing to it. RuntimeKit depends only on `std`, `mindclade_core` and (for `http`) `httparse`.

### 3.2 Lifecycle (`mindclade_runtimekit::lifecycle`)

Preserved traits, all `Send + Sync`: `Clock::now_millis() -> u64`, `IdentityProvider::identity() -> Identity`, `ShutdownSignal::requested() -> bool`. Additions: production `SystemClock`, `ConfiguredIdentity::new(Identity)` and `ShutdownLatch` (Clone; idempotent `request()`; `wait_timeout(Duration) -> bool`); `Lifecycle::new(Arc<dyn Clock>, Arc<dyn IdentityProvider>, Arc<dyn ShutdownSignal>)` plus `with_telemetry(self, Arc<dyn TelemetrySink>)` (default: stderr JSON lines). `serve(config: ServiceConfig, handler: Arc<dyn Handler>, lifecycle: Lifecycle) -> Result<RunningService, RuntimeError>` **amends** the plan's `Arc<dyn EchoCapability>` as the binding amendment requires. `RunningService::address() -> SocketAddr` returns the _bound_ address; `shutdown(self) -> Result<(), RuntimeError>`; dropping it performs the same drain and never detaches a thread (on overrun, Drop emits `overrun` and blocks joining). `ShutdownLatch` implements `ShutdownSignal`.

- **Clock rule:** the injected `Clock` stamps telemetry and domain observations only. Socket deadlines always use `std::time::Instant`, so a frozen `ManualClock` can neither disable nor accelerate them.
- **Identity rule:** under `AdmissionMode::Test`, `serve` requires `lifecycle.identity.identity() == config.service()` before binding, else `RuntimeError::Identity`. No request byte ever contributes to identity.

### 3.3 Transport (`mindclade_runtimekit::http`)

`Request` (private fields; `method()`, `target()`, `content_type()`, `body()`); `Response::json(status, Vec<u8>)` / `Response::empty(status)` / `Response::with_allow(self, &'static str)` (the only extra header a handler can set; needed for 405 `allow: POST`); `RequestScope` (`deadline() -> Instant`, `cancelled() -> bool`, true once drain begins, when `lifecycle.shutdown.requested()`, or after the handler deadline — never set by a client disconnect); `trait Handler: Send + Sync + 'static { fn handle(&self,
request: &Request, scope: &RequestScope) -> Response; }`. Here **"protocol-neutral" means product-neutral**: the handler sees HTTP/1.1 framing concepts only — no Echo route, DTO, schema, Codegen type, YAML or TestKit — and no separate transport-agnostic envelope is introduced.

Fixed transport-profile constants (proposed; not configuration): head ≤ 8192 bytes and ≤ 32 fields; header deadline `Dh = t_accept + request_timeout`; body deadline `Db = t_head_complete + request_timeout`; advisory handler deadline `Dx = t_body_complete + request_timeout` (exposed only through `scope`; a handler cannot be preempted); write deadline `Dw = t_response_ready + request_timeout`; during drain every deadline is clipped to `S = t_drain + shutdown_timeout`. These are `pub const`s in `http`. Composite bound: a permit is held for at most 2×`request_timeout` before the handler, plus handler time, plus `Dw`. Every response carries `connection: close` and `content-length`, no `date`; bodies are `application/json` or empty. After an error response sent before the body was consumed, RuntimeKit performs a bounded lingering close: half-close write, then discard input until EOF, 8192 + `max_body_bytes` bytes, or the current phase deadline, whichever comes first. Deliberate RFC 9112 deviations, recorded here: `chunked` is not supported (→ 411), other transfer codings → 501, and a leading empty line before the request line is rejected rather than ignored.

### 3.4 Errors and telemetry

`RuntimeError::{Config(ConfigError), Identity, Bind(io::ErrorKind),
Transport(io::ErrorKind), Shutdown(ShutdownFailure)}`. `Transport` is only a non-transient accept failure, reported at shutdown; transient accept errors are retried. `ShutdownFailure::Overrun(OverrunWorkers)` owns the unfinished `JoinHandle`s; `OverrunWorkers::join(self)` joins them and its Drop also joins (blocking), so a handle is never dropped unjoined. `Display` is fixed text and never echoes input. `TelemetrySink::record(&Event)`: `Event` fields are only `ts_ms`, `level`, `event`, `conn` (sequence number), `status`, `reason`, `code`. `event` is one of `ready accepted rejected completed deadline disconnect
write_failed shutdown_begin shutdown_complete worker_exit config_error bind_error
transport_failed overrun`; `reason` and `code` are closed sets (`code` = `ConfigError::code()` values). No address, target, header, body, requestId or Identity text appears. `worker_exit` is emitted only after `join` returns. `accepted` is recorded after the permit is acquired; a connection's terminal event (`completed`/`rejected`/`deadline`/`disconnect`/`write_failed`) is recorded before its permit is released; "closed" means any terminal event. `TelemetrySink` lives in RuntimeKit.

### 3.5 TestKit and Codegen products

**TestKit** (`mindclade_testkit`, `testonly`; depends on RuntimeKit for its traits, never the reverse): `ManualClock::new(u64)` / `advance(u64)` (panics on overflow, never wraps); `FixedIdentity::new(Identity)`; `FaultBarrier` — `arrive(name)` blocks until `release(name)` (a permanent, idempotent per-name latch, so arriving after release passes), `arrive_or_cancel(name, &dyn
ShutdownSignal) -> Arrival { Released, Cancelled }`, `wait_arrivals(name, count,
harness_timeout) -> bool`; internal condvar re-check slices (≤10 ms) are a liveness bound only, never an ordering mechanism; `RecordingSink` implements `TelemetrySink`.

**Codegen-emitted HTTP adapter** **[reconcile after B2b merge]**: output `generated/vs001/service/http.rs`, a module body the composition includes as `generated_service_http` (it includes `rust/mod.rs` as `generated_dto`, which the adapter uses via `super::generated_dto::public::…`). Entry point: `pub fn echo_handler(capability: Arc<dyn EchoCapability>) -> Arc<dyn mindclade_runtimekit::http::Handler>`. Everything is emitted from `TargetBundle` operation data — route, method, path field and rule, request/response models, success status, media types, error alternatives — and the transport profile's `max_body_bytes`. The checked descriptor's `operation` must equal the bundle operation, or emission fails. `rust/mod.rs` stays free of RuntimeKit. Publication uses a **new closed profile variant**, provisionally `Composition` (13-file protocol catalog + `service/http.rs` = 14 files, 13 output hashes), through the existing publisher and `MindcladePublicationLock@v1`; no forked publisher.

### 3.6 Service (`services/foundation_echo`)

`ports.rs`: `AdmissionContext` (private tenant, environment, identity and descriptor digest; public accessors; `pub(crate)` constructor used only by composition); `trait AdmissionPort: Send + Sync { fn execute(&self, context:
&AdmissionContext, request_id: &str, request: EchoRequest) -> Result<EchoResponse,
EchoError>; }`; `TestAdmission` returns `EchoResponse{message}`. `composition.rs`: `compose(config, clock, identity, latch: ShutdownLatch, telemetry, admission:
Arc<dyn AdmissionPort>) -> Result<ComposedService, RuntimeError>` builds the `Lifecycle` with that same latch, wraps the port in an `EchoCapability` bound to the trusted context, and serves the generated adapter. `ComposedService` exposes `address()` and `shutdown(self)`, which calls `latch.request()` before `RunningService::shutdown`. `EchoCapability` has no scope, so the latch is the only cancellation channel reaching admission ports (test ports use `FaultBarrier::arrive_or_cancel(name, &latch)`). `main.rs` builds the generated config, `SystemClock`, `ConfiguredIdentity(config.service())` and a `ShutdownLatch`, then composes.

- **stdout** carries exactly two receipts: `{"address":…,"admission":"test","descriptor_digest":…,"schema":"FoundationEchoReady@v1"}` and `{"outcome":"drained"|"overrun","schema":"FoundationEchoStopped@v1"}`. **stderr** carries only telemetry lines.
- **stdin control:** a `shutdown` line or EOF requests shutdown; repeats are ignored. The stdin reader thread returns after the first `shutdown` line or EOF and is joined. A `transport_failed` event also triggers shutdown.
- **Overrun:** `main` writes the overrun receipt, flushes stdout, and calls `process::exit(5)` while still holding `OverrunWorkers` (process termination, not thread detachment).
- **Exit codes:** 0 drained, 3 config, 4 bind or identity, 5 overrun, 1 other. The binary does not depend on TestKit.

## 5. Acceptance criteria

Each criterion lists a positive control (P), negative cases (N) and a Bazel target. Real-socket waits use bounded harness timeouts (default 10 s) that fail with a distinct "harness timeout" message; a harness timeout is never product success. Deadline tests assert that closure happens no earlier than `D − 50 ms` and no later than `D + 1500 ms`. `//services/foundation_echo:composition_tests` is a `test_suite` of `:composition_rust` (B3b-19–21) and `:process_tests` (B3b-22–25).

### Stage A — pure configuration ABI (implemented first)

**B3b-01 Config positives.**

- P: Every accessor over IPv4 `127.0.0.1`/`127.0.0.2` and `[::1]`; ports 0 and 65535; max_in_flight 1 and 64; both durations at 1 and 30000 ms; all three log levels (service-config-v1 §4.3). Negatives are B3b-02.
- Target: `//platform/runtimekit:tests`.

**B3b-02 Config direct-call negatives.**

- N: every §4.4 case with its exact variant and `code()`: wrong service, tenant or environment; wildcard or external IPv4/IPv6; IPv4-mapped; nonzero scope or flow; body 0, 65535, 65537 or `usize::MAX`; concurrency 0, 65 or MAX; both durations at 0, 1 ns, 999999 ns, 1 ms + 1 ns, 30000 ms + 1 ns, 30001 ms and `Duration::MAX`. Multiple-invalid inputs prove the validation order, with no side effects. P: the B3b-01 set.
- Target: `//platform/runtimekit:tests`.

**B3b-03 Generated constructor against the real crate.**

- P: compile the actual `generated/vs001/service/config.rs` via the declared runfile against real RuntimeKit, call `build_service_config()`, and assert every accessor equals `descriptor.json`.
- N: temporary mutations (§4.5) — malformed socket, each malformed identity component, malformed Digest — produce the exact mapped `ConfigError` with no panic. Compile-fail tests show config cannot be forged (public fields, `Default`, `Deserialize`, `Durable`). A DTO-only consumer of `rust/mod.rs` compiles without RuntimeKit.
- Target: `//tests/conformance/vs001:service_config`.

### Stage B — RuntimeKit transport (generic test handler, raw std sockets; no TestKit)

**B3b-04 Loopback ephemeral bind.**

- P: config port 0 gives an `address()` with a nonzero port and the same IP, and a request succeeds there. The same holds for `[::1]:0`. `ready` is emitted only after binding.
- N: binding an occupied port returns `RuntimeError::Bind` with no thread left (no `worker_exit` pending) and no telemetry `ready`. An identity provider that disagrees with `config.service()` returns `RuntimeError::Identity` before binding (the port stays free).
- Target: `//platform/runtimekit:tests`.

**B3b-05 Head framing.**

- P: a well-formed `POST /x HTTP/1.1` with Host and Content-Length reaches the handler exactly once.
- N, each closed with its exact status, the handler never invoked and the permit released. **400:** bare LF; leading empty line; obs-fold; NUL or other control byte in the head; invalid method token; absolute-form or `*` target; target bytes `#`, `{` or 0x80–0xFF; missing or duplicate Host; duplicate Content-Type; HTTP/2 preface; any version other than `HTTP/1.1` and `HTTP/1.0`. **505:** only `HTTP/1.0`. **431:** an 8193-byte head or 33 header fields. **417:** any `Expect` header.
- Positive boundary: a head of exactly 8192 bytes with exactly 32 headers is accepted. The tokenizer corpus (tchar and field-value grammar, whitespace around the colon, empty name) applies under both (c) and (d).
- Target: `//platform/runtimekit:tests`.

**B3b-06 Body framing and byte limit.**

- P: `content-length: 65536` with exactly 65536 bytes is delivered intact. CL 0 delivers an empty body.
- N (handler not invoked, connection closed): CL 65537 → 413, sent **before any body byte is read** (the client sends the head only, then reads). Missing CL → 411. Duplicate CL (even when equal), a signed value, leading zeros, inner whitespace, non-digits or u64 overflow → 400. `Transfer-Encoding` whose final coding is `chunked` → 411; any other `Transfer-Encoding` value (including `identity`), with or without CL → 501. Error responses sent before the body is consumed use the bounded lingering close (§3.3).
- N: CL 10 followed by 70 000 bytes — the handler receives exactly 10 bytes and no second request is parsed from the connection.
- Target: `//platform/runtimekit:tests`.

**B3b-07 Absolute header deadline (slowloris).**

- P: a head completed by `Dh` succeeds.
- N (request_timeout 300 ms): a client trickling one head byte every 50 ms, which would defeat any idle timeout, is closed at `Dh` (tolerance above) with telemetry `deadline/header`; the handler is not invoked and the permit is released. A client that connects and sends nothing is also closed at `Dh`.
- Target: `//platform/runtimekit:tests`.

**B3b-08 Absolute body deadline.**

- P: a body completed by `Db` succeeds.
- N: a complete head followed by a body trickled every 50 ms, and a body that stops short of CL, are each closed at `Db` with `deadline/body` and the handler not invoked. Header trickle time does not extend `Db`.
- Target: `//platform/runtimekit:tests`.

**B3b-09 Write deadline.**

- P: normal responses are fully written.
- N: a test handler returns an 8 MiB body to a client that never reads. The write stops at `Dw` with `deadline/write`, and the worker exits (`worker_exit`).
