**Workflow ordering.** Split the current "Immutable foundation checks" shell block immediately after its `cargo fetch --locked` and `bazel fetch //... --lockfile_mode=error` provisioning. **Scratch construction and command sequence.** A reviewed, untracked scratch package in a newly allocated owned directory under the checkout supplies one `rule(..., test = True)` Bazel target and a fixed Python script run through the declared `@nix_python//:bin/python3` interpreter/runfile. The rule follows the existing custom-test pattern in `tools/build/{typespec,vs001}.bzl`; it does not assume native `sh_test`. The script uses Python standard-library sockets only, no dependency installation, no shell-selected endpoint and no access to project or host credentials. It first records the runner's allowlisted identity and `/proc/self/ns/net` link, then in the sandbox action records its own network namespace link. It binds and connects a local loopback socket with a bounded successful accept/round-trip control. It next attempts a single TCP `connect` to `192.0.2.1:9`, with a monotonic duration and at most five seconds for that attempt, retaining the exact errno and exception category. The parent records its own namespace link for comparison. The driver runs the scratch target once, uncached, with `--batch` and `--output_user_root=<new owned root>` for a dedicated Bazel output root. Fixed test arguments include `--spawn_strategy=linux-sandbox --strategy=TestRunner=linux-sandbox --sandbox_default_allow_network=false --sandbox_debug --nocache_test_results --local_test_jobs=1 --lockfile_mode=error`, an explicit `--build_event_json_file` under `r2/`, and `--test_output=all`; the driver imposes an independent 300-second outer bound around Bazel and its owned child. Retain the exact argv, stdout/stderr and BEP file. The driver deletes the untracked scratch test _before_ the following `just verify` and confirms that deletion; a scratch target must not enter the aggregate or candidate source.

**Allowed observations.** Retain source commit, workflow/runner OS/arch, Nix/Bazel identity and selected rule/interpreter paths; exact diagnostic argv/logs; BEP `testResult.executionInfo.strategy`; parent and action network namespace symlink targets; loopback connect/accept result; TEST-NET connect errno/duration; startup/exit status; and scratch/output cleanup result. Any root/environment inspection is restricted to `uname`, numeric uid, known namespace links and relevant readable `/proc` sysctl values. Do not dump the environment, event payloads, kernel logs or broad `/proc`; do not read credentials, use sudo, write sysctls or alter AppArmor/host settings. A helper or sandbox startup failure is recorded as its actual error and stage, without guessing a cause.

**Result categories.** PASS requires a fresh uncached PASSED `testResult` proving `linux-sandbox` action execution, successful in-sandbox loopback control and a failed TEST-NET connect within five seconds with EPERM/EACCES, or ENETUNREACH with nonempty, unequal actual action/parent namespace identities. Actual namespace records are retained in every case; a missing record cannot PASS. An actual connection is semantic **FAIL**. Refusal (for example ECONNREFUSED), timeout, missing/malformed observation or BEP, unsupported namespace, strategy fallback, failed loopback, or runner/helper startup error is **BLOCKED** for isolation, with the actual error captured and no guessed cause. An uncertain owned-process termination or failed cleanup is a collector **FAIL**, with owned roots and evidence preserved. Only after confirmed owned batch-process exit may scratch and newly created output roots be removed. Neither PASS nor another category changes R-2 or C1 eligibility without the separate candidate-bound both-host prerequisite and review record.
