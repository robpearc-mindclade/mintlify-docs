## Interfaces

### `github_audit.observe_queue(variables: dict) -> dict`

This function is transport. It lives in the audit module because the binding module does no I/O. It mirrors `get_review_threads`.

**Inputs:** `variables` is exactly `{owner, name, number, after}`, validated before any process launches.

**Command:** `gh api --hostname github.com graphql --method POST --input -`, with `GH_HOST` and `GH_DEBUG` unset and a 25 s timeout.

**Output:** at most 1 MiB, parsed with `load_json`.

**Query:** exactly the constant below. The tests hold an independent literal copy and assert that the two are equal.

```graphql
query MergeQueueSnapshot($owner: String!, $name: String!, $number: Int!, $after: String) {
  repository(owner: $owner, name: $name) {
    databaseId nameWithOwner isPrivate
    pullRequest(number: $number) {
      fullDatabaseId number state isDraft baseRefName headRefOid baseRefOid updatedAt
      mergeQueueEntry { id }
    }
    mergeQueue(branch: "main") {
      id
      configuration { mergeMethod }
      entries(first: 100, after: $after) {
        totalCount
        pageInfo { hasNextPage endCursor }
        nodes {
          id position state enqueuedAt
          enqueuer { login }
          baseCommit { oid }
          headCommit { oid }
          pullRequest { fullDatabaseId number headRefOid baseRefOid }
        }
      }
    }
  }
}
```

The query uses only supported `MergeQueueEntry` fields and none of the deprecated `baseOid` or `headOid`. `configuration.mergeMethod` selects the parent shape to check (G2-15) and is never membership evidence.

### Retained snapshot `mindclade.queue-snapshot.v1`

The snapshot has exactly these keys:

| Key | Description |
| --- | --- |
| `schema` | Schema identifier |
| `repository_id` | Repository database ID |
| `repository` | Repository full name |
| `pr_number` | Pull request number |
| `pr_database_id` | Pull request database ID |
| `base_sha` | The operator's `--base` |
| `source_head_sha` | The operator's `--candidate` |
| `policy_sha` | Policy SHA |
| `packet_sha256` | Packet SHA-256 |
| `observed_at` | RFC 3339 UTC, taken from the injected `now` |
| `queue` | `{id, merge_method, total_count}` |
| `entries[]` | Ordered list of entries |

Each entry has exactly `id`, `position`, `state`, `enqueued_at`, `enqueuer`, `base_sha`, `head_sha`, `number`, `pr_database_id`, `pr_head_sha`, and `pr_base_sha`. If GitHub returns a null value, the snapshot keeps it as null.

The file bytes are `json.dumps(record, sort_keys=True, separators=(",", ":"))`, encoded as UTF-8 and followed by `\n`, at most 64 KiB in total. `queue_snapshot_digest` is the SHA-256 hex digest of exactly those bytes.

### `github_binding.verify_queue_binding(expected: dict, observations: dict) -> dict`

This function is pure: it does no I/O and never mutates its inputs. It never recomputes the snapshot digest. It uses G1's `Unknown` and `Violation` and reuses these G1 helpers, extended for `stage == "queue"`.

**`expected`**

- Exactly G1 `EXPECTED_KEYS` plus `enqueuer`
- For the queue stage, `base_sha` is the queue base, `source_head_sha` is the PR head, and `tested_sha` is the merge-group head
- `enqueuer` is the accepted policy's `acceptance_owner`. No CLI flag supplies it
- The PR and main stages keep their exact G1 key set

**`observations`**

- The G1 keys plus `queue` (the decoded snapshot whose custody the adapter already checked) and `queue_snapshot_sha256`
- A missing key, or a `KeyError`, `TypeError`, or `IndexError`, raises `Unknown`
- Extra keys are ignored and can never cause a pass

**Check selection.** Only checks that meet both conditions count:

- `check_suite.id` equals `run.check_suite_id`
- The `details_url` locator points to the `merge_group` run

Checks from other runs on the same SHA are excluded; they are never a fallback.

**Return value.** Exactly `queue_entry_id`, `queue_base_sha`, `queue_head_sha`, `queue_pr_head_sha`, `queue_run_id`, `queue_run_attempt`, `queue_snapshot_digest`, and `queue_observed_at`.

`verify_run_binding` and `verify_primary_observations` never succeed for the queue stage.

### Audit wiring

`--stage` accepts `pr|queue|main`. In the queue stage, `--candidate` is the reviewed PR head. The approval and review-thread checks keep their meaning.

#### Queue-stage `pull-request` check

It requires: PR head == `--candidate`, base == `--base`, and not a draft.

| PR state | Result |
| --- | --- |
| Open | PASS |
| Merged with `merge_commit_sha` == queue head | PASS |
| Closed and unmerged | FAIL |
| Merged at another SHA | FAIL |

#### Capture mode (`--stage queue --queue-snapshot-out PATH`)

1. Read the repository and the PR over REST before and after paginating `observe_queue`. The PR's REST `base.sha` must equal `baseRefOid`; otherwise the result is Unknown.
2. The PR's `mergeQueueEntry.id` must equal the selected entry's `id`; otherwise the result is Unknown and no file is written.
3. Validate the complete snapshot bytes before calling `open`.
4. Create `PATH` with `O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW` and mode 0600. If a write fails after the file is created, unlink only this capture's file and report BLOCKED.
5. Record `bindings["queue_capture"] = {queue_snapshot_digest, queue_entry_id, queue_observed_at}`.

Capture mode emits exactly these checks: `policy`, `packet`, `repository`, `pull-request`, `queue-capture`, `execution-binding` (BLOCKED), and `supervised-readiness` (BLOCKED).

#### Verification mode (`--stage queue` without the output flag)

1. Read the snapshot only through the keyword-only reader `retained_queue(repository_id, pr_number, policy_sha, packet_sha256) -> (opaque_id, sha256, bytes)`. Its production default raises `Unknown("O3 has not adopted independent queue snapshot custody")`.
2. Validate it with G1 `retained_bytes` and `strict_json`, check the exact schema, and confirm that re-serializing it canonically reproduces the same bytes. Raise `Violation` if `repository`, `pr_number`, `base_sha`, `source_head_sha`, `policy_sha`, or `packet_sha256` differs from the CLI arguments.
3. Select checks:
   - Count only required-context/App checks on the queue head whose locator run has event `merge_group` and a `head_branch` equal to the snapshot's queue branch, `gh-readonly-queue/main/pr-<pr_number>-<entry base_sha>`.
   - Exclude checks from other events on the same SHA. They are never a fallback.
   - Select the newest. A tie or no match gives Unknown.
4. Call `verify_queue_binding` and record `bindings["queue_binding"] = result + {queue_snapshot_custody_id}`.

In the queue stage, `required-checks`, `execution-transport`, and `execution-binding` report BLOCKED with the detail "evaluated by queue-binding in queue stage", and never PASS.

**Fixture dependencies.** The new keyword-only dependencies are `queue_graphql` (the capture transport) and `retained_queue`. Supplying any dependency marks the report `fixture`. An omitted dependency resolves to `_missing_fixture`, never to a live call.

**Unchanged:** the GovernanceReport@v1 top level, the PASS/FAIL/BLOCKED statuses, and the 0/2/3 exit codes.

### (C) Ruleset applicability in `protection_check` (fail-closed)

Only the classification step changes. It runs in this order:

1. Check identity as today.
2. `target` must be `branch`, `tag`, or `push`; anything else is Unknown. Skip `tag` and `push` rulesets whatever their conditions, rules, or bypass actors.
3. For `branch`, `source_type` must be `Repository` or `Organization`; anything else is Unknown. Skip non-active enforcement as today.
4. The `conditions` keys of an active branch ruleset must be exactly `{ref_name}` (either source type) or `{ref_name, repository_name}` (`Organization` only). Any other key, including `repository_id`, `repository_property`, and `organization_*`, is Unknown.
5. `repository_name` must have the keys `{include, exclude}` plus an optional boolean `protected`.
   - Both lists are string arrays, and `include` is non-empty.
   - Patterns are evaluated against the name part of `--repository` (`mindclade-vnext`).
   - A pattern is either `~ALL`, which matches every name, or a subset of GitHub's fnmatch syntax: the characters `[A-Za-z0-9_.-]` plus `*`, which matches any run of characters, including none.
   - Any other metacharacter (`?`, `[`, `]`, `{`, `}`, `\`, `!`, `/`) is Unknown.
   - Patterns are non-empty and match the whole name. Any `~` pattern other than `~ALL` is Unknown.
