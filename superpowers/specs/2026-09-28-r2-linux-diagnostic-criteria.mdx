The R2 diagnostic determines actual pinned Linux sandbox startup and denial behavior before any runner remedy. It specifies the bounded Linux sandbox diagnostic and its evidence limits. Audience: independent test author, implementer, integration owner and reviewers. Status: experimental.

**Status:** Frozen 2026-09-28 for the bounded diagnostic; Rob approved scope in session. Execution evidence remains pending.

**Task:** Determine actual pinned Linux sandbox startup/denial behavior, before any runner remedy.

**Base:** `a8be3e03238d1258e5e714f8133fa9652d84d812`.

## Scope and non-goals

One independent diagnostic after CI provisioning. No host privilege/security mutation, locks, new packages, product implementation, aggregate replacement or qualification. Preserve existing failure semantics and retain diagnostic BLOCKED separately. User approval of this concrete route was received 2026-09-28; independent technical criteria review still precedes implementation.

## Paths

Proposed implementer: `scripts/r2_diagnostic.py`. Independent test author: `scripts/test_r2_diagnostic.py`. Parent only: `.github/workflows/foundation.yaml`, `scripts/test_ci_policy.py` transition coordinated with independent author, `docs/architecture/REPOSITORY_TREE.md`, `docs/developer/agent-handoff.md`. All other paths excluded. Actual disposable scratch package created at runtime in checkout and deleted before aggregate; never a tracked test target or permanent scaffold activation.

## Interfaces

Proposed stdlib Python CLI:

```bash Terminal
python3 -B scripts/r2_diagnostic.py --repo PATH --output NEW_LEAF
```

Default none: both paths explicit. Only Linux x86_64 real execution; other host reports BLOCKED without Bazel/probe execution. Exit 0 means diagnostic collection/cleanup complete (outcome may be PASS/FAIL/BLOCKED and must be read), exit 1 means collector/evidence/cleanup failure. Output exclusive/new, outside disposable roots, no overwrite.

Proposed fixed result JSON with schema `mindclade.r2-diagnostic.v1`; status PASS/FAIL/BLOCKED; qualification not-qualified; exact candidate SHA, dirty state, file digests (`.bazelrc`, `flake.nix`, `flake.lock`, `MODULE.bazel.lock`, script), tool identity, allowed runner identity, observed strategy, bazel exit, probe observation, cleanup disposition, relative artifact paths+sha256. No claims of independent trusted execution.

Fixed probe emits a single JSON observation of connect errno name/number and monotonic duration to 192.0.2.1:9 under 5s. Include a local loopback server/client success control in same sandbox, joined and closed under bounded deadline; a socket creation/bind failure is not network connect denial. Record `/proc/self/ns/net` and parent ns identity where readable to distinguish ENETUNREACH in isolated namespace. No external service success expected.

Bazel uses repository pinned wrapper and locked runfile Python from `@nix_python`. Proposed transient BUILD/custom `.bzl` test rule can be generated by diagnostic driver; action source remains scratch. Tags `external`, explicit `nocache_test_results`, no shared disk cache receipts. Dedicated new `output_user_root`, `--batch`, `--spawn_strategy=linux-sandbox --strategy=TestRunner=linux-sandbox --sandbox_default_allow_network=false --sandbox_debug`, `--local_test_jobs=1`, fixed target, `test_timeout` 30. Whole Bazel child bound 300s, process-group cleanup only own launch, retain logs/BEP before root cleanup. Invocations recorded as argv. No broad environment read/dump, no ambient host tools as replacements, no network fetch beyond existing provisioning. Tool unavailable yields BLOCKED, not semantic RED.

## Acceptance criteria

### R2D-01

Evidence classifier accepts only exact one uncached PASSED target result with strategy `linux-sandbox`, independent positive loopback control, allowed connect denial within 5s and namespace evidence for ENETUNREACH. Cached/fallback/missing/duplicate/malformed/mismatched target/duration/namespace cannot PASS. A real connection is FAIL; timeout/refusal/unsupported/startup failure BLOCKED.

### R2D-02

Launch preserves exact flags, pinned inputs and bounded owned roots. Refuse dirty/unsupported checkout or collisions without deleting existing files. Cleanup removes only current owned scratch roots after child exit is established; parent group timeout/uncertain cleanup yields explicit failure and preserved evidence.

### R2D-03

Redacted allowlist identity and bounded logs/JSON. Missing upstream support is diagnosed with actual helper error log, not presumed AppArmor/sysctl cause. No token/event/environment/secret collection.

### R2D-04

Tests independently exercise classifier positive/negative observations, real temporary filesystem collision/exclusive output/cleanup behavior, and timeout/failed-child collection boundaries. Fake executables can exercise subprocess ownership but do not count as real Linux isolation proof. Parent RED against missing diagnostic via explicit feature absence assertion; then GREEN after implementation. Do not count ImportError as behavioral RED; use deferred module lookup and fail with absent expected callable/behavior.

### R2D-05

Parent workflow step added after existing locked provisioning before aggregate, retains output through existing always artifact, existing required checks still execute if diagnostic outcome is BLOCKED. Collector failure terminates step/job; diagnostic semantic result stays separate and does not silently waive C1. CI policy checks verify concrete invocation/integration and unmodified security/action pins/required recipes.

## Checks the parent runs

Focused Python tests and CI policy tests, pinned just verify on Darwin, Linux CI on candidate, inspect actual source-bound diagnostic logs+BEP. Darwin unit tests are not Linux startup evidence. Task/fresh whole-candidate review before commit/PR. Both-host uncached socket/PG+aggregate and K2/K3 still required after any later remedy; diagnostic PASS alone not C1 authorization.

## Stop conditions

Permission/checkpoint not approved; unsupported host; unowned path; unexpected credentials/security need; new lock/pin; unable to join child or establish cleanup; missing actual strategy. Preserve failure, no workaround. No automatic sysctl/security correction.

## Dated amendments

2026-09-28 technical freeze: integration parent /root is criteria author; independent reviewer /root/r2_diagnostic_criteria_review; independent test author /root/r2_diagnostic_tests; fresh implementer /root/r2_diagnostic_author. Actual review found six bounded clarifications, all adopted verbatim below and taking precedence over draft shorthand above. Scope approval is Rob's explicit "Approve diagnostic scope" response to Task1 M0B-03 on 2026-09-28. It does not approve security/privilege remedies. All R2D-01 through R2D-05 trace to approved M0B-03; R2D-04 additionally traces to repository independent test/parent execution rules. No admission, acceptance or qualification grant.

Pinned Bazel 9.1.1 retained uncached BEP evidence establishes expected run=1, shard=1, attempt=1 even for an unsharded test. Missing identity fields cannot match these values. Cache booleans are `testResult.cachedLocally` and `testResult.executionInfo.cachedRemotely`; absent means false, wrong types or true never pass.

Exact observation format for independent author/implementer agreement: prefix `R2_PROBE_JSON=` followed by one JSON object with `schema`=`mindclade.r2-probe.v1`, `nonce`=32 lowercase hex, `phase`=`external_connect` on a completed external connect, `destination`=`192.0.2.1:9`, `errno_number` integer or null, `errno_name` string or null, `duration_seconds` finite nonnegative number, `loopback_success` boolean, `netns` actual namespace string or null, `connected` boolean. Success means connected true and errno fields null; accepted denial must have connected false and consistent Linux errno pairs EPERM/1 EACCES/13 ENETUNREACH/101. Observation phase is `control` on socket/bind/loopback error; such error never proves denial. Collector validates exactly one matching prefix/schema/nonce in the exact target test log before calling classifier. Classifier independently validates fields/types; malformed observations BLOCKED. Ephemeral nonce binds this attempt, not a credential.

Concrete bounds: 300s combined provision+test child budget; all metadata commands bounded individually 10s inside that budget; connect timeout 4.5s with hard 5s acceptance ceiling, loopback control 2s, test_timeout 30. Combined child stdout/stderr log and BEP each capped at 8MiB, test log 1MiB, one observation 16KiB. A limit hit cannot PASS; retain capped bytes and explicit truncation. Additional termination/cleanup allowance at most 10s after main budget (TERM 5s, KILL 5s); uncertain termination is collector FAIL with owned roots preserved. No unbounded join/wait/copy. Close/cleanup ordinary filesystem operations scoped to new roots; no manual server kill or directory deletion of preexisting paths. Diagnostic-generated convenience symlinks are disabled via `--symlink_prefix=/`.

Proposed receipt has `schema`=`mindclade.r2-diagnostic.v1`, semantic `status`, `reason`, `collector_status`, `stage`, `qualification`=`not-qualified`, `candidate_sha`, `candidate_dirty`, input hashes, tool/runner identity, exact command phase/argv/exit/timing, raw observed strategy or null, parsed observation or null, parent_netns, nonce/target, cleanup disposition, and relative evidence paths/digests with missing/truncated markers. Do not include arbitrary environment, events, credentials or service logs. Unknown schema/key/value receipt output is not trusted execution proof. Public function result dictionaries need stable required keys, not a broad schema library. Proposed private launch seam `_run_command(argv, *, cwd, log_path, deadline) -> dict` returning `exit_code`, `timed_out`, `terminated`, `truncated`; it launches only owned process groups and bounds logs. Tests may replace this narrow seam; main offers no executable override. `classify_evidence` returns only status/reason. Stable reason categories: `denied`, `connected`, `bazel_failed`, `missing_result`, `invalid_evidence`, `cached`, `wrong_strategy`, `control_failed`, `not_denied`. Additional collector-specific diagnostic reasons allowed, but never emit arbitrary exception/secret values.

CLI output path may be relative to invocation cwd (the CI invocation is at repo); `collect` takes resolved absolute paths. Output leaf must be fresh with existing safe parent or safely created parents; no symlink path components; no repo/disposable-root replacement. `collect` returns finalized receipt even when semantic BLOCKED; main writes exclusive result.json after cleanup (or collect may write it once; one owner only) and prints minimal status. Unsupported hosts exit 0/BLOCKED without Bazel or scratch creation, with evidence storage available. Refused dirty/collision/symlink inputs preserve caller files and exit 1; no fabricated output overwrites.

The following independent review clarifications are binding, with concrete format/bounds above resolving open examples:

### Clarification 1: Traceability and roles (draft 1–13, 27–43)

Remove stale "pending scope approval" title; link every R2D criterion to M0B-03 (R2D-04 also independent test responsibilities). Record actual criteria author, reviewer, independent test author and implementer before dispatch; retain parent execution ownership. State no new dependencies or locks and no admission/acceptance/qualification grant. Keep stable IDs. The CLI/schema remain explicitly proposed.

### Clarification 2: Small testable interface (17–23, 27–30)

Freeze proposed `classify_evidence(*, target: str, bazel_exit: int | None, bep_events: list[dict], observation: dict | None, parent_netns: str | None) -> dict` returning `{"status": "PASS|FAIL|BLOCKED", "reason": <stable code>}`; `collect(repo: Path, output: Path) -> dict` returning the finalized receipt; `main(argv: list[str] | None = None) -> int`. Tests may patch a private launch adapter to supply a fake child; no production CLI for overriding the pinned launcher/probe. Write `result.json` after cleanup disposition is known. Include `collector_status` and stage (`preflight|provision|test|collect|cleanup`), so semantic outcome and process exit cannot be conflated. Exit 0 means complete evidence collection plus established cleanup even for semantic FAIL/BLOCKED; exit 1 means collector, evidence-storage or cleanup failure. A startup/helper failure with retained available logs and no BEP is semantic BLOCKED/exit 0, not an evidence-write failure. Do not require nonexistent startup artifacts; record their absence.

### Clarification 3: Scratch identity and probe (21–23, 27)

Use one exclusively created scratch package, a target label computed from its actual package path (fixed target name `probe`), and the same exact label in command, receipt and BEP check. Generate a custom `test=True` Starlark rule with explicit `@nix_python//:bin/python3` executable-config input and probe source in runfiles. Use explicit stable runfiles aliases or actual `File.short_path`; never guess the Bzlmod canonical repository directory or run host `python3` from the test launcher. Preserve generated BUILD/rule/probe/launcher texts or digests before removal. Bind the observation to a per-attempt nonce and a fixed schema. Probe exits zero after a complete observation regardless of semantic connect result; classifier owns PASS/FAIL. Record `phase`, destination, errno number/name, finite nonnegative monotonic duration, loopback success, and probe network namespace. Only errno from external `connect` counts; socket/bind/listen/control errors are BLOCKED. Bound external connect below five seconds (e.g. a 4.5s socket timeout with a hard acceptance ceiling of 5s); give loopback its own bounded deadline and joined/closed resources. Require EPERM/EACCES, or ENETUNREACH with nonempty unequal actual parent/probe namespace identities. Connection success is FAIL; refusal, timeout, unknown errno, missing control or malformed observation is BLOCKED. Do not infer isolation from unreachable destination alone.

### Clarification 4: BEP and uncached execution (23, 27)

Retain bounded raw JSON BEP and stdout/stderr, plus probe observation extracted from exactly one nonce/schema-matching record in the exact target's test log. Require Bazel exit 0 and exactly one matching `testResult`, PASSED, expected run/shard/attempt, `executionInfo.strategy == "linux-sandbox"`, and neither local nor remote caching. Normalize omitted protobuf boolean defaults to false; reject wrong types, true cache indicators, missing strategy, duplicate/mismatched results and malformed JSON. Missing run/shard/attempt protobuf defaults are normalized only where the expected numeric value is zero. Summary/command flags alone never establish strategy or execution. A missing result after a failed startup remains BLOCKED. Add positive fixtures using both explicit false and omitted cache defaults, then cached/fallback/duplicate/malformed/mismatch negatives. Keep the observed raw strategy, including absence, in the receipt.

### Clarification 5: Provisioning, bounds and ownership (17–23, 28–30)

A new output root alone does not override the checked-in shared disk cache: pass explicit `--disk_cache=` after the command through the pinned wrapper. Record two distinct phases: locked fetch of the exact scratch target into the same dedicated output root, then forced test; both share a 300s monotonic total budget. This fetch is existing dependency provisioning and may not add modules, pins or packages; unavailable inputs are BLOCKED. Preserve required startup options before `fetch`/`test`, all test flags, `--lockfile_mode=error`, JSON BEP path and 30s test timeout. Disable convenience symlink creation so the diagnostic cannot replace the checkout's existing Bazel links. Validate a clean candidate before creating scratch; do not misclassify own scratch as preexisting dirt. Allow ignored existing evidence/provisioning outputs but refuse tracked modifications and foreign untracked source. Require exclusive new evidence leaf, no symlink traversal or overlap with disposable roots; reject collisions without deleting anything. Track owned directory identity, use only the launched process group, and establish child/group termination before copying final artifacts and deleting owned scratch/output roots. Timeout may become semantic BLOCKED only after termination/cleanup is established; uncertain termination, log-write or cleanup failure is exit 1 with surviving roots recorded/preserved. Never clean another invocation's directory. Set concrete log/JSON size ceilings and truncation indicators; truncated classifier evidence cannot PASS.

### Clarification 6: CI and independent RED/GREEN (30–35)

Split existing workflow provisioning and immutable checks only as needed to insert a distinct diagnostic step between them. Invoke `nix develop --no-write-lock-file -c python3 -B scripts/r2_diagnostic.py --repo "$GITHUB_WORKSPACE" --output target/foundation-verification/r2` with no `continue-on-error`, `|| true`, cache-based skips or semantic BLOCKED gate. Receipt output is covered by the existing always-upload evidence directory. Successful collection of BLOCKED/FAIL must permit unchanged aggregate/PG commands to execute; collector failure retains the failed job and always artifacts. Require cleanup before that continuation. CI policy tests pin ordering, exact invocation, unchanged security/action pins, required recipes and existing failure semantics. Parent runs `python3 -B -m unittest discover -s scripts -p 'test_r2_diagnostic.py'`, matching focused CI-policy discovery, then pinned Darwin `just verify` and exact-candidate Linux workflow. Independent tests use deferred module discovery plus an explicit missing-callable assertion for initial RED; no ImportError-as-RED. A temporary parent-owned classifier stub returning BLOCKED can also yield behavioral RED on the positive fixture, but is unnecessary. Tests must cover output collision, foreign/symlink roots, startup failure with absent BEP, timeout termination, cleanup failure, retained logs and required-check continuation. Fake child results prove collector behavior only.

## Amendment 2 (2026-09-28): runner substrate resolution

Fresh hosted-runner qualification on branch `codex/r2-runner-qualification-20260928` at `9c20f99f5457214955837da017040574c4bec4b1`, run `36451562318`, used the same pinned Nix 2.35.1, Bazel 9.1.1 and R2 collector across GitHub-hosted Ubuntu 22.04, 24.04 and 26.04. Ubuntu 22.04 produced semantic **PASS/denied**: Bazel exit 0, uncached `linux-sandbox`, successful loopback control, `ENETUNREACH` to TEST-NET within the bound, unequal nonempty parent/action network namespaces, and complete cleanup. Ubuntu 24.04 and 26.04 both produced **BLOCKED/bazel_failed** before probe execution because Bazel did not register `linux-sandbox`. Their read-only host records showed `kernel.apparmor_restrict_unprivileged_userns=1`; the passing 22.04 runner recorded 0. This evidence selects an execution substrate; it does not authorize a sysctl/AppArmor write or claim that the sysctl alone is a complete causal proof.

This amendment supersedes only R2D-05's same-job placement and dated clarification 6's placement wording. The diagnostic semantics, classifier, probe, pins, permissions, no-privilege rule, cleanup rules and product boundary remain unchanged:

- a dedicated `r2_linux_sandbox` job runs on `ubuntu-22.04`, with `contents: read`, the existing pinned checkout/Nix actions, locked provisioning, the exact R2 invocation and an always-retained R2 artifact;
- the job records only the already-allowed read-only runner identity/sysctl observations and performs no `sudo`, security write or host mutation;
- an explicit terminal semantic gate fails that prerequisite job unless `result.json.status == "PASS"`; collector failure or missing evidence also fails closed;
- the existing `linux-foundation` job remains on `ubuntu-24.04`, depends on the prerequisite, uses job-level `if: always()` so aggregate/PostgreSQL and retained evidence still execute even when R2 fails, and preserves the protected check name;
- a final always-run step in `linux-foundation` fails unless the prerequisite job concluded success. Thus semantic BLOCKED cannot be hidden by a green aggregate, while an R2 failure also cannot suppress unrelated foundation evidence.

Ubuntu 22.04 is a bounded compatibility substrate, not a permanent platform commitment. Requalification onto a maintained runner that natively registers `linux-sandbox`, preferably an ephemeral managed/self-hosted runner with a reviewed immutable image, is required before this hosted image is retired. No such runner is currently registered directly to this repository. Changing runner administration, org runner groups or host-security settings remains outside this source amendment.

The qualification-branch PASS proves the runner class can satisfy R2; it is not candidate evidence for PR #50. PR #50 must rerun this split workflow on its own new synthetic PR revision, and merge-queue admission still requires exact merge-group evidence.

### Amendment 2a: exact-target provisioning and canary

The runner-split implementation must not pre-create the diagnostic output leaf. The job creates only its parent evidence directory; `r2_diagnostic.py` exclusively creates `target/foundation-verification/r2`. Read-only host capability evidence is written beside that leaf as `r2-host-capability.txt`, so collector exclusivity is preserved. Collector failure remains the job's primary failure; the semantic PASS gate runs only when the collector step itself succeeded, avoiding a second misleading "result missing" failure while preserving fail-closed behavior.

The broad parent provisioning commands `cargo fetch --locked` and `bazel fetch //... --lockfile_mode=error` are not part of the dedicated R2 job. The reviewed collector already provisions exactly its generated scratch target with the pinned Bazel wrapper, `--lockfile_mode=error`, a dedicated output root, `--disk_cache=`, and `--repo_contents_cache=` before executing the forced `linux-sandbox` test. The ordinary Ubuntu 24.04 foundation job retains its own existing R4 provisioning unchanged. This narrows R2 network work without changing B4's aggregate provisioning contract.

A separate non-required `R2 Runner Canary` workflow may run weekly and manually against GitHub-hosted Ubuntu 22.04, 24.04 and 26.04. It uses the same collector, records the same bounded read-only host capability fields, retains evidence for 14 days and summarizes semantic status. Semantic BLOCKED is canary data, not a required-check failure; collector/infrastructure failure remains a workflow failure. The canary has no `pull_request`, `push` or `merge_group` trigger and therefore cannot become an admission signal accidentally.
