## 5. Acceptance criteria

Every criterion has a positive control (P) and negatives (N), so rejecting everything fails; each N names its error variant, exit code or B4 code. RED is the parent observing the named test's assertion fail because a compiling naive skeleton accepts the first N (or the RED a criterion names); a compile error, missing tool or `todo!` panic is not RED (C K4). Database facts come from reserved SQL on C's read-only `observer()`, file facts from reserved byte reads, never return values alone. No skips, `#[ignore]` or `sleep(` in D files (b3b_19 and C §7 unchanged); a harness deadline fails with a distinct timeout message.

### D1 — Provenance and the acyclic capsule

- **D1-01 Corrupted bytes cannot be sealed** (the plan's `corrupted_artifact_cannot_be_sealed`). P: an intact `completed_snapshot()` seals; the digest is sha256 of `capsule.json`; each `outputs/*` file equals the committed bytes (independent SQL) and `compute_echo_artifact`'s output; the test copies the capsule to `$TEST_UNDECLARED_OUTPUTS_DIR/capsule/` for export (KD-9). N: one byte appended to `output_bytes[0].bytes` → `Integrity`; bytes and `reference` changed together → `Integrity` (no longer the stored `ArtifactRecord`); after either, `destination` does not exist. RED: a naive seal copies `output_bytes` without recomputing digests. Target: `//services/foundation_echo:capsule_tests`.
- **D1-02 Typed, immutable references.** P: `capsule.run` converts into kernel `Reference<targets::Run>`, and its digest equals sha256 of the canonical immutable `Admission` bytes in `inputs/admission.json`, recomputed by the test. N: a stored reference with a wrong `target_kind` (`corrupt_reference_kind`) → `InvalidReference`; after `set_run_state_without_event`, `capture` → `Integrity`, since a mutable row is never reference content. RED: a naive capture trusts stored kinds. Target: `:capsule_tests`.
- **D1-03 Exact bindings and canonical bytes.** P: `capsule.json` equals the snapshot's `BuildFacts`, packet, policy, criteria, evaluator, Run and Attempt; identical snapshots sealed twice give byte-identical trees and digests. N: changing exactly one of candidate, base, source, generator, graph, manifest, descriptor, runtime, locks, migration, packet, policy, criteria, evaluator or attempt changes the digest (15 cases); a manifest with a duplicate member or noncanonical bytes → `Integrity`; a candidate or base that is not 40 lowercase hex → `InvalidReference`. RED: a naive seal omits a binding. Target: `:capsule_tests`.
- **D1-04 Acyclic capsule.** P: in `generated/vs001/graph.json`, `QualificationEnvelope.execution_capsule` exists (control) and `ExecutionCapsule` has no field typed `Assessment`, `Decision`, `DecisionReference`, `ClaimReference`, `SignedAssessment` or `QualificationEnvelope`. N: the capsule digest occurs in no byte of the capsule tree. Target: `//tests/conformance/vs001:all`, `:capsule_tests`.
- **D1-05 Exact inventory and paths.** P: every file except `capsule.json` is listed once with correct size, digest and media type; events run 1..n. N, each before any file is written: an output name giving `../x`, `/x`, `a/./b`, a backslash, an empty segment or over 128 characters → `Path`; an event naming an artifact absent from `output_bytes` → `MissingInput`; an `output_bytes` entry no event names → `ExtraInput`; a sequence gap, duplicate or reordering → `Integrity`; a non-terminal Run → `Integrity`. RED: a naive seal writes whatever the snapshot lists. Target: `:capsule_tests`.
- **D1-06 Exclusive, ordered publication** (A1's rules). P: exclusive directory creation; `capsule.json` written, synced and the directory synced last (scan with control); on error the seal removes only files it created. N: an existing destination, empty or not → `Path`, the existing tree byte-identical afterwards (repeat sealing); a destination under a symlinked parent → `Path`. RED: a naive seal uses `create_dir_all`. Target: `:capsule_tests`, `:assurance_boundaries_tests`.
- **D1-07 Payload separate from records.** P: `outputs/<name>.json` holds exactly the fake Clade bytes with their non-scientific marker; the `ArtifactRecord`'s `digest` equals the payload digest, and the record file's own sha256 differs from it. N: no record file contains its own digest; a record whose `digest` differs from its payload → `Integrity`; `RECEIPT_FIELDS` members occur only in `events/*`, never in `outputs/*` (scan). Target: `:capsule_tests`.
- **D1-08 Trace context is never sealed** (C A3.2). P: two Runs with identical input, one admitted with the W3C example `traceparent` and one with none, seal capsules whose `outputs/*`, `evidence/*` and normalized-event and record digests are equal. N: a canary `traceparent` (`00-` + 32 hex `c0ffee...` + `-` + 16 hex + `-01`) and canary `tracestate` occur in no capsule byte, no `capsule.json` binding, and no file of the exported A3 bundle, so no A3 digest covers them; a scan finds no `traceparent` or `tracestate` in `capsule.rs`'s queries. Target: `:capsule_tests`, `:assurance_boundaries_tests`.

### D2 — Fresh-store replay

- **D2-01 Byte-identical replay through the real path** (the plan's `replay_reproduces_exact_artifact_bytes`). P: artifacts, normalized digest and the bytes `read_replayed_bytes` reads equal the sealed ones; both observations `pass`; the replay store's attempts and events were written through §4.4's write paths (counts equal the capsule's); the capsule tree digest is unchanged. N: a capsule re-sealed with a consistently altered payload (bytes, inventory and records together) → `Ok` with `replay.artifacts` = `fail`, `observed_digest` ≠ `expected_digest`, capsule untouched. RED: a naive replay loads `outputs/*` instead of executing and passes the N case. Target: `:replay_tests`.
- **D2-02 Fresh isolated store only.** P: a newly started `PgHarness` is accepted and replay migrates it. N: a harness that already ran `migrate` or holds one admitted Run → `NotFresh`, existing rows unchanged and none added; a scan finds no DSN, `Role` or `PgStore` parameter in `replay` and exactly one `PgHarness::dsn(Role::App)` call (control). RED: a naive replay migrates any harness. Target: `:replay_tests`, `:assurance_boundaries_tests`.
- **D2-03 Inventory verified before any database write.** Each N leaves zero tables in the harness's `public` schema. N: missing `capsule.json` or listed file → `MissingInput`; a truncated or changed byte → `Integrity`; an unlisted file, executable or not → `ExtraInput`; an inventory path with `..`, a leading `/` or an empty segment → `Path`; a symlink, file or directory, even pointing inside → `Path`; `capsule.json` with a duplicate or unknown member → `Integrity`. P: the intact capsule replays. RED: a naive replay opens files lazily. Target: `:replay_tests`.
- **D2-04 Versions and cross-references.** Each N is raised before any write: `schema` other than `ExecutionCapsule@v1` → `Version`; an old `workflow_version` → `Version`; `migration_digest` ≠ the embedded migration checksum → `Version`; `generator_digest` ≠ the replaying build's → `Version`; `policy`, `criteria` or `evaluator` disagreeing with `inputs/packet.json` or an `EvidenceRecord` → `Integrity`. P: a self-consistent re-forged policy replays but reports a `capsule_digest` other than the sealed one, which D3-05 catches. Target: `:replay_tests`.
- **D2-05 Every C4 fault schedule.** Each C4-05 case's terminal Run is sealed and replayed as §4.4 describes. P: artifacts and normalized digest equal; attempt count and artifact generation equal C4-05's table; K-L, K-C1 and K-DB1 fence generation 1 through `reconcile_once` after the database-clock wait; K-X1 and K-X2 reach `cancelled` with zero artifacts, confirmed by the recorded observation's digest. N: K-L's capsule re-sealed with its attempts' fault order swapped → `replay.events` = `fail`; K-X1 with an altered recorded observation → `replay.events` = `fail`. Target: `:replay_tests`.
- **D2-06 Narrow normalization.** P: the literal `RECEIPT_FIELDS` of §4.4 is asserted; changing only a receipt field, or running the same capsule twice under different database-clock times, leaves `normalized_events_digest` unchanged. N: changing state, generation, result digest, event identity, causal sequence, retry delay, lease length or a recorded observation changes it; an unknown event member → `Integrity`, never dropped. Target: `:replay_tests`.
- **D2-07 Repeated, relocated and cross-host.** P: one capsule replayed in two fresh harnesses and again after copying it elsewhere gives identical `ReplayResult`s while process IDs and wall clocks differ (recorded); on each host `replay_capsule` over its exported capsule exits 0. N (parent, KD-7): the hosts' artifact digests or `normalized_events_digest` differ → fail; `capsule_digest` may differ only through `runtime_digest`. Target: `:replay_tests`, KD-7.
- **D2-08 Isolation and write paths.** N (scan): D's replay and capsule files contain no `std::net`, `std::env::var`, `std::process::Command`, `connect_with`, SQL keyword literal, tamper-helper call, `Role::Admin`, DSN literal or `sleep(`; files open only in the capsule reader, which checks `symlink_metadata` and file identity before and after reading. P: the scan finds the reader's opens and the §4.4 write calls. Target: `:assurance_boundaries_tests`.
- **D2-09 Trace context is outside replay equivalence** (C A3.2). P: a capsule from a Run admitted with the canary `traceparent` replays into a store admitted with none (and one with another value): `normalized_events_digest`, artifact digests and record digests are equal and both observations `pass`. N: the canary appears in no `ReplayResult` or `ReplayRecord` byte. Target: `:replay_tests`.

### D3 — Signed assessment and fail-closed decision

- **D3-01 A candidate key cannot approve itself** (the plan's `a_candidate_key_cannot_approve_itself`). P: `owner_signed_pass()` and `owner_signed_failure()` use an owner key made inside the test process from a per-process random source, never a committed seed; they verify and `decide` gives `approved` [`complete_pass`] and `rejected` [`failed_criterion`]; neither is real acceptance. N: the plan's test (a committed candidate key) → `UntrustedKey`. RED: a naive verifier trusts the envelope's own key. Target: `//tools/qualification/vs001:verification_tests`.
- **D3-02 Strict Ed25519 and domain separation.** N → `InvalidSignature`: one bit flipped in payload or signature; a signature without the domain line or with `MindcladeAssessment@v2`; `S` replaced by `S + ℓ`. The precomputed constant (public key and `R` both the identity encoding, `S` = 0; no `hazmat` feature) is asserted accepted by non-strict `verify` and rejected by `verify_strict`, and through the verifier fails `Malformed` at trust loading (small-order key). N → `Malformed`: a signature or key not lowercase hex of the right length, or not a valid point. P: the unmodified owner vector verifies. Target: `:verification_tests`.
- **D3-03 Strict, canonical decoding.** N → `Malformed`: a duplicate or unknown member in envelope or payload; `schema` other than `SignedAssessment@v1`; a validly signed but noncanonical payload (reordered keys, added space, missing or doubled LF); two observations with one `criterion_id`; `Assessment.outcome` inconsistent with its observations. P: the canonical payload verifies. Target: `:verification_tests`.
- **D3-04 Trust, revocation and identity.** N: trust bytes whose sha256 ≠ the published digest → `UntrustedKey`; a bundle holding any `TEST_ONLY_PUBLIC_KEYS` key → `UntrustedKey`, even with a matching digest; zero or two active keys → `Malformed`; `key_id` absent → `UntrustedKey`; key `revoked` → `RevokedKey`; payload `assessor` ≠ the key's bound `assessor` (self-declared reviewer) → `UntrustedKey`; two keys sharing a `key_id` → `Malformed`. P: an active ephemeral key with a matching assessor and digest verifies. Target: `:verification_tests`.
- **D3-05 Exact binding.** N → `WrongBinding`: each of the 12 `CandidateBinding` fields changed by one character (covers wrong revision and capsule); a payload policy, criteria or evaluator digest ≠ the trust bundle's pin even when `expected` agrees (changed criteria, replaced evaluator). P: exact equality verifies. Target: `:verification_tests`.
- **D3-06 Hosted-CI platform evidence.**
  <Warning>
    BLOCKED — not run for acceptance until the GitHub-hosted macOS arm64 job exists (§2); no local bundle substitutes.
  </Warning>
  P: one `PlatformEvidence` per required platform, each an `EvidenceBundle@v1` index whose sha256 is in `Assessment.evidence`, with `metadata.candidate` and `metadata.base` equal to the binding's, `metadata.platform` equal to the requirement, `ci.url` a run of `Mindclade-org/mindclade-internal-monorepo`, `ci.conclusion` = `success` and `status` = `passed`. N → `MissingEvidence`: the Mac or Linux index absent; `ci` null (a local bundle); another candidate, base or platform; conclusion `failure`, `cancelled`, `skipped` or `null`; status not `passed`; a digest absent from `Assessment.evidence`; a duplicate member. That the run used a GitHub-hosted runner is OA-5's check. Target: `:verification_tests`, with fixtures in `negative-assessments.json`.

**D3-07 Fail-closed decision table.** Rows apply top to bottom; `reasons` lists every applicable reason in enum order. Every row, `Err` rows included, carries `Decision.assessment` = the digest of the envelope bytes as received. N: an exhaustive test over every row and variant; only the last row yields `approved`. P: `Decision.policy`'s digest is sha256 of the policy bytes, the identity is §4.5's, and two runs give equal bytes. Target: `:verification_tests`.

| Input | Outcome | Reasons |
| --- | --- | --- |
| `Err(Malformed / UntrustedKey / RevokedKey / InvalidSignature)` | blocked | `untrusted_assessor` |
| `Err(WrongBinding)`, `claim` ≠ the policy's claim, or `envelope_digest` ≠ the verified one | blocked | `wrong_binding` |
| `Err(MissingEvidence)` | blocked | `missing_evidence` |
| verified, any observation `fail` | rejected | `failed_criterion` (+ others that apply) |
| verified, an observed ID not in `required_criteria` | blocked | `wrong_binding` |
| verified, a required ID unobserved or `blocked`, or a required platform uncovered | blocked | `missing_evidence` |
| verified, all required pass, `human_review: true` | needs_human_review | `policy_review` |
| verified, all required pass, platforms covered | approved | `complete_pass` |

- **D3-08 Owner-pinned policy; unconstructible trust types.** N: policy bytes whose sha256 ≠ `trust.policy_digest` (one byte of the candidate policy file changed) → `WrongBinding`; a duplicate or unknown member → `Malformed`; compile-fail pairs, each with a compiling sibling differing only in the forbidden element (error codes unused, as C5-09): a struct literal of `VerifiedAssessment`, `TrustedPolicy` or `DecisionRecord`, and `serde_json::from_slice` into each; a scan finds no `pub` field or `Deserialize`, `Default` or `From` impl. P: owner-pinned bytes load. Target: `:verification_tests`, `//tools/qualification/vs001:compile_fail`.
- **D3-09 The CLI fails closed.** P: with an ephemeral owner key and trust and policy in a temporary directory outside `--candidate-root`, and its digest as `--trust-digest`, `decide` exits 0 printing `approved`; a failing assessment exits 2 with `rejected`; every receipt carries the trust digest. N, each exit 3 with the named `reason` and no `approved` on stdout: `--trust`, `--trust-digest`, `--policy` or `--candidate-root` omitted (`missing_authority`); a self-made trust bundle whose digest is not the one passed (`trust_digest_mismatch`); either path, symlinks resolved, inside `--candidate-root` or the capsule (`authority_inside_candidate`); a committed test key (`test_only_key`); each `AssessmentError` (its snake_case name). A usage error exits 1. Target: `//tools/qualification/vs001:cli_tests`.
- **D3-10 Test keys stay test-only.** P: `TEST_ONLY_PUBLIC_KEYS` equals the public keys derived from every committed fixture seed, and `TrustBundle::load` refuses each (D3-04). N (scan): committed seeds appear only in `tests/verification.rs`; `SigningKey` appears only in `tests/{verification,cli,envelope}.rs`, where every key outside `verification.rs` is ephemeral; `src/**` has no signing function and holds only public keys; no repository file, exported bundle or D test output holds a PEM `PRIVATE KEY` block or a committed seed. Limit: code cannot tell a test key from an owner key. This keeps committed keys out; only custody (OA-2) and the published digest keep other keys out. Target: `:verification_tests`, `:assurance_boundaries_tests`.
- **D3-11 Implementation cannot reach acceptance authority (B4).** P: after the §9 model change, `just verify-boundaries` exits 0 on both hosts and at matrix scope. N (parent scratch procedure as C5-07, one host; each exits 2 with exactly the listed violations and no `facts-*` diagnostic, then is reverted): an Echo → verifier Cargo edge → one `forbidden-dependency`; a verifier → Echo edge → one `forbidden-dependency`; a verifier → TestKit normal edge → two, `forbidden-dependency` and `production-to-test` (TestKit's scope is test); `ed25519-dalek` from Echo → one `unapproved-external`. Genqueries show `:foundation_echo`'s closure excludes `//tools/qualification/...` and `:vs001_qualify`'s excludes `//services/...` and `//platform/testkit/...`. Target: KD-6, `:assurance_boundaries_tests`.

### D4 — Final envelope and closeout (the implementer-passable part)

- **D4-01 Envelope seal.** P: over a verified pass, `seal_qualification` writes the §4.6 layout, and `verify_qualification` with the same trust, policy, claim and expected candidate returns the decision's outcome and the capsule, assessment, decision and trust digests. N: `published_trust` ≠ the assessment's trust digest → `Untrusted`; `decision` not made from this assessment, or `binding.capsule_digest` ≠ `execution_digest` → `WrongBinding`; a different capsule, assessment or decision gives a different digest; an existing destination → `Path`. Target: `//tools/qualification/vs001:envelope_tests`.
- **D4-02 Forgery and relabelling fail at rest.** P: a `blocked` and a `rejected` decision each seal faithfully and verify with that outcome. N, each with every inventory and envelope digest recomputed by the forger: `decision.json` and `envelope.json` relabelled `approved` over an `owner_signed_failure()` → `Integrity` (re-run `decide` differs); a pass signed by a self-made key, verified with the owner's bundle → `Untrusted`, and its own bundle fails `TrustBundle::load` against the published digest (`UntrustedKey`); a committed test key fails `TrustBundle::load` (`UntrustedKey`) even when its own digest is supplied; one changed byte of `assessment.json` → `Untrusted` (signature). Neither `seal_qualification` nor `seal` takes an outcome or label argument (scan with control); `envelope.json` holds no digest of itself; walking capsule → assessment → decision → envelope finds no back-reference. Target: `:envelope_tests`, `:cli_tests`.
- **D4-03 Checkable, credential-free evidence index.** P: `check-index` accepts a fixture with exactly the §4.6 members and values and `retrieval_url` = `https://github.com/Mindclade-org/mindclade-internal-monorepo/releases/tag/evidence/<name>`. N, exit 2 with a located diagnostic: another `access`, `retention`, `classification` or `owner`; userinfo, query or fragment; another host, repository or non-`evidence/` tag; a member name containing `token`, `secret`, `password` or `credential`; a missing or extra member; a duplicate digest. Target: `:cli_tests`.
- **D4-04 Truthful closeout** (parent review). P: the acceptance report lists the exact candidate and base, run URLs and attempts, tools, reviewer identity and reviewed SHA, capsule, assessment, decision, envelope and trust digests, archive identities and each OA item's state. N: no document, maturity entry or commit claims VS-001 complete, accepted or qualified unless an `approved` envelope re-verifies (KD-10) under the **currently** published trust digest (OA-2, OA-10), was signed by the owner (OA-7) and its release re-verified by download; none calls the assessment "independent" while Rob both approves the criteria and signs (X14); a closeout commit never names its own SHA as the assessed candidate.
