## Goal

Implement tranche A of Mindclade's agent platform: Eve-quality filesystem agent authoring compiled deterministically through the existing Rust Codegen into the one immutable `MindcladeGraph` and `AgentIrV1`, without activating a model runtime, tool execution, sessions, sandbox, memory, or a competing execution authority.

## Scope and non-goals

**In scope:**

- Exact capability references with stable digests under graph insertion order changes.
- Agent filesystem discovery and `AgentSourceV1` normalization.
- Compile tools, policies, and explicit child authority.
- Attach agents to the one `MindcladeGraph` via `AgentGraphView`.
- Lower `AgentIrV1` with provider-neutral tool contracts.
- Retained projection, CLI, and drift checking.
- Build integration and independent conformance.
- Architecture docs, maturity updates, and scaffold transitions.
- Whole-candidate verification and governed integration.

**Out of scope:**

- Model execution, durable agent sessions, sandboxing, memory, schedules, channels, provider SDKs, or tool execution.
- Product runtime activation under `agents/` or `services/agent_service`.
- Tranches B--E (runtime, sessions, sandbox, memory, subagent runtime).
- Scientific qualification.

## Global constraints

- Preserve one Codegen and one immutable `MindcladeGraph`; `AgentGraphView` is a borrowed view, never another graph authority.
- Preserve TypeSpec as authority for the capability contract used by the representative fixture.
- Do not activate or place implementation under product `agents/`.
- Do not activate `services/agent_service`.
- Do not introduce model execution, durable agent sessions, sandboxing, memory, schedules, channels, provider SDKs, or tool execution.
- Effectful execution remains the platform Run/Attempt/PostgreSQL/outbox authority.
- Reuse the existing strict YAML parser, canonical serializer, safe filesystem layer and recoverable publisher.
- Do not introduce a policy language. `AgentCompileContext` resolves exact already-typed `Reference<Policy>` values supplied as trusted compiler inputs.
- Tool bindings use exact `Reference<Capability>` values, including content digest.
- Path-derived semantic names are limited to the existing ASCII Mindclade `Component` grammar. Rejecting non-ASCII semantic names eliminates Unicode-normalization ambiguity without adding a Unicode dependency.
- Instructions are exact valid UTF-8 source content. Source digest covers exact bytes; Codegen performs no invisible Unicode or newline rewriting.
- Existing foundation/VS-001 canonical bytes must remain unchanged when no agents are compiled.
- Generated files are never manually edited.
- The dedicated `mindclade-monorepo-engineer` App authors governed repository PRs; `robpearc-mindclade` remains acceptance/CODEOWNER, not the coding author.

## Review focus

1. Transitive capability changes change a capability reference digest; unrelated graph changes do not.
2. Filesystem ambiguity, case-fold collisions, non-ASCII path-derived names, symlink components and traversal fail before bytes are trusted.
3. A child that does not explicitly declare a parent's tool does not receive it in compiled state or IR.
4. Empty agent collections do not alter existing foundation/VS-001 canonical graph bytes.
5. Hand mutation, missing files, stale source/capability references and check-mode writes never appear as valid generated agent output.

## Self-review

Spec coverage: filesystem authoring, exact capability/policy references, child noninheritance, one graph/borrowed view, deterministic IR, retained projection, unsupported runtime slots, provenance/security negatives, conformance, docs/maturity, and protected integration are covered. Tranches B--E remain excluded.

Interface chain:

```text
CapabilityView::reference
-> AgentSourceV1
-> compile_agent + AgentCompileContext
-> CompiledAgent
-> MindcladeGraph::agent_view
-> lower_agent
-> AgentIrV1
-> agent projection/publisher
```

No task defines an alternate capability digest, graph, publisher or semantic parser. No new external dependency is required.

The principal design addition is capability-specific exact-reference derivation in `CapabilityView`, so agent tool bindings do not invent their own digest rule and unrelated graph changes do not invalidate a capability reference.
