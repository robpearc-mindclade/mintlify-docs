## Scope and non-goals

**In scope:**

- Integrating PR #11 and reconciling the baseline (Task 0).
- Gates B2b, G2, B3b, B4, G3, and DX2 (Tasks 1-6).
- Final handoff and GHE Cloud transfer runbook (Task 7).
- Per-gate worktrees, criteria freeze, RED/GREEN cycles, whole-candidate review, and owner-exception merges.
- Reconciliation of all status docs, README, maturity, roadmap, and handoff registers.

**Out of scope:**

- Actual GHE Cloud transfer and O1-O4 execution (Rob performs these after Task 7).
- Code changes outside the specified gate paths.
- Any change to pinned tool versions or committed lock baselines without Rob approval.

## Global constraints

- Authority order is set by `AGENTS.md:5-15`. Stop and fix any authority conflict rather than coding around it.
- Statuses are only PASS, FAIL or BLOCKED. Required unexecuted checks are `BLOCKED — not run`.
- Never edit generated outputs by hand. Regenerate with `just generate-foundation` / `just generate-vs001`, then `just update-tree`.
- No candidate edits to accepted policy (`.agents/policies/supervised.v1.json`). G3's policy revision is a **separate PR left open** for O3 adoption after migration.
- Update SemanticInput@v1 and MindcladeGraph@v1 in place, with no v2 schemas. No `tch-rs` or Triton.
- New third-party dependencies and lock changes need Rob's approval at the gate's criteria checkpoint. The parent alone edits `Cargo.lock`, `MODULE.bazel.lock`, `flake.nix`/`flake.lock` and `pnpm-lock.yaml`.
- Git hygiene:
  - Stage explicit paths only; no `git add -A`.
  - No force-push, reset or squash.
  - Merge with `gh pr merge N --merge`, matching PRs #1-#10.
  - Delete only branches that are ancestors of `main`.
- Each merge needs a **dated one-time owner exception** (CONTRIBUTING.md:54-98), approved by Rob in chat. Record it in the merge commit body and a PR comment, then consolidate it into CONTRIBUTING in the next docs PR. A doc cannot name its own final commit (`agent-handoff.md:94-98`).
- Do the gate work in fresh worktrees only (`superpowers:using-git-worktrees`), as siblings of `$R` named `mindclade-vnext-<gate>`. The `$R` checkout carries untracked session `receipts/` dirs that Rob chose to keep, and these would make `candidate_tree_clean=false`.
- Name branches `claude/<gate-slug>`. Linux CI runs through the `pull_request` trigger.

## Review focus

These are failure modes that no gate's own tests exercise. Each one gets its test or check in the task named.

1. **The post-transfer governance path is untested.** An audit run with `--repository Mindclade-org/mindclade-vnext` must pass, and a case-mismatched org must fail with a clear diagnostic. Add both tests in Task 2 (G2).
2. **Artifact download may break on GitHub's 302 redirect.** Downloads use `api.github.com` and refuse redirects (`github_audit.py:659-675`), while GitHub normally redirects artifact zips. Task 2 must prove with a fixture whether this reports BLOCKED. If it does, fix it to follow only a same-origin/`*.actions.githubusercontent.com` redirect, with tests for a disallowed host.
3. **Status docs can drift from `main` after each merge.** Every gate PR updates the handoff register, maturity and README for its own gate. Task 7 runs a repo-wide sweep for superseded SHAs and PR numbers.
4. **The clean-tree claim can be contaminated.** Run all `just verify` receipts in clean worktrees. Before each claim, check that `git status --porcelain` is empty.
5. **Toolchain additions can break one host only.** Examples are protoc in B2b and the transport crate in B3b. Both Apple Silicon (local) and Linux (CI) must pass before any merge. A single-host pass is BLOCKED, not PASS.

## Work breakdown

### Execution model: per-gate cycle (applies to Tasks 1-6)

For each gate, run `.agents/workflows/foundation-development.md` steps 1-7 as follows:

- [ ] **Recover:** fetch, confirm `main` = `origin/main`, and create the worktree and branch from `main`.
- [ ] **Freeze:** the parent writes `docs/superpowers/specs/<YYYY-MM-DD of freeze>-<gate>-criteria.md`. It holds criterion IDs, owned and excluded paths, proposed interfaces copied from the gate spec, negative cases, the checks, stop conditions and any new dependencies.
- [ ] **Criteria review:** a fresh subagent that did not write the criteria reviews them against the gate spec and Review Focus. The parent fixes the findings.
- [ ] **Rob checkpoint A:** approve the frozen criteria and any new dependencies. Wait for the reply.
- [ ] **RED:** a fresh implementer subagent writes the failing tests. The parent runs the focused command and keeps a _behavioral_ failure. A missing tool does not count as RED.
- [ ] **GREEN:** the implementer makes the narrow change. The parent runs focused tests and Bazel targets, then regenerates outputs, runs `just update-tree` and runs `nix develop --no-write-lock-file -c just verify`.
- [ ] **Task review:** a fresh reviewer subagent reviews the actual diff and receipts against the frozen criteria. Fixes invalidate affected evidence; rerun it.
- [ ] **Docs:** update `docs/developer/agent-handoff.md` (register row and checkpoint), `docs/architecture/maturity.yaml`, README status and `VS001_TODO.md` for this gate only.
- [ ] **Whole-candidate review:** a fresh reviewer covers the full branch diff.
- [ ] **Integrate:** commit using the gate spec's expected subject, push, open the PR from the `.github/PULL_REQUEST_TEMPLATE.md` sections, and wait for `linux-foundation` to pass.
- [ ] **Rob checkpoint B:** approve the one-time merge exception. Then merge with `--merge`, confirm `main` CI passes, and check local, tracking and remote `main` parity.
- [ ] **Close:** remove the worktree and delete the merged branch. Keep the receipts in the worktree's evidence directory, and copy them to `$R/.superpowers/sdd/2026-09-24-<gate>/` before removing the worktree.

## Stop conditions

Stop and bring these to Rob:

- Any authority conflict between docs.
- A blocking review finding outside the gate's scope.
- A gate that cannot meet its spec without a spec amendment (for example, the B3b transport).
- A single-host-only pass.
- A red `main` CI after a merge. Do not start the next gate; fix forward in a new PR.
- Any need to edit accepted policy, CODEOWNERS or `.github` protection semantics.
- A dirty worktree at candidate time.

1. For every merged gate: record the local Apple Silicon `just verify` receipt in a clean worktree, and check that the `linux-foundation` PR run and the post-merge `main` run are both green (`gh run list -R robpearc-mindclade/mindclade-vnext --branch main --limit 3`).
