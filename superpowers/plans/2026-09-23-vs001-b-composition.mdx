This page is the VS-001 generated composition plan for Mindclade engineers and reviewers. It sequences B1 (versioned public/internal semantics), B2 (typed projection and public products), B3 (descriptor-composed RuntimeKit/TestKit service), and B4 (executable architecture and dependency enforcement).

<Warning>
  This plan grants no operational admission by itself. Written criteria review precedes implementation. Unchecked boxes here are historical task descriptions, not proof that already-implemented declaration work should be repeated.
</Warning>

## Global Constraints

- Preserve Bazel 9.1.1, Rust 1.96.1, TypeSpec compiler/HTTP 1.16.0, Node 22.23.2, pnpm 12.3.4, Python 3.12.14, and the committed Nix lock baseline.
- Nix supplies tools; Bazel owns product compilation and tests. No downloads or package installation within build/test actions.
- Architecture YAML remains authoritative. Planned JSON architecture placeholders remain inactive.
- Update SemanticInput@v1 and MindcladeGraph@v1 in place, as explicitly directed by the user on 2026-09-23. Do not introduce parallel v2 APIs or schemas. Record canonical changes and compatibility results explicitly; retain the foundation fixture as a regression case, not a permanent schema freeze.
- Generated clients must not depend on internal execution contracts. RuntimeKit contains lifecycle/transport infrastructure, not domain execution policy.
- Preserve scaffold. Require local Apple Silicon/Linux execution; Intel Mac is untested.
- Shared locks, ownership transitions, generated inventory and integration follow the [delivery plan](2026-09-23-vs001-delivery.md).

## Review Focus

1. A public operation referring transitively to an internal type must be rejected (B1).
2. Unsupported TypeSpec decorators and response alternatives must retain source locations (B1).
3. Client runtime decoding and compile-time types must agree, including optional fields and errors (B2).
4. YAML duplicate keys/aliases, secret values, bad references and invalid composition must fail before service startup (B3).
5. Body/resource limits, disconnects, identity spoofing and unresolved/forbidden dependencies must not bypass public/runtime boundaries or advertise fake durability (B2-B4).

## Task B1: Versioned public/internal semantics

**Interfaces:** Evolve `SemanticInputV1::from_json(&[u8], &str) -> Result<Self, Vec<Diagnostic>>` and `Compiler::compile(&SemanticInputV1) -> Result<MindcladeGraph, Vec<Diagnostic>>` in place. V1 includes `visibility: public|internal` per declaration, named enums, tagged unions, integer/string literals, validation constraints, HTTP response alternatives, optional HTTP binding for internal operations, and descriptor inputs with source locations. Graph serialization remains `MindcladeGraph@v1`. No public deserialization bypasses builder validation. This supersedes the original v2 expansion requirement, not the semantic or qualification requirements.

Internal reference DTOs contain validated Identity and Digest, plus an exact literal target kind. Generated Rust bridges them to sealed `Reference<T>` markers.

### Required records in authored TypeSpec (with closed enum/discriminated union fields rather than free-form state strings)

| Record | Required semantic fields |
| --- | --- |
| WorkPacket | identity, capability/implementation/policy/criteria references, input digest, owned scope, schema/workflow versions, maximum attempts |
| Admission | tenant/environment identities, capability reference, requestId, packet reference, canonical input digest and public Echo request |
| Dispatch | event identity, Run reference, packet reference, schema/workflow versions |
| Lease | Run reference, attempt identity, positive generation, owner identity, expiry |
| Attempt | identity, Run reference, generation, fault classification, causal event references |
| Completion | lease, result/artifact digest, canonical artifact bytes, evidence references |
| CancelRequest | Run reference, reason, requesting identity, expected version |
| CancelConfirmation | Run reference, attempt/generation, supervisor identity, termination observation digest |
| ArtifactRecord | identity/digest, media type, producer Run/Attempt, provenance reference |
| EvidenceRecord | identity/digest, subject reference, producing Run, observed result, evaluator/criteria references |
| ReplayRecord | capsule identity/digest, input/event/output inventories, schema/workflow references |
| Assessment | candidate/base, all bound digests, independent assessor identity, criterion observations and outcome |
| Decision | identity, Claim/Policy/Assessment references, closed outcome and reason codes |

Represent wire timestamps as recorded strings with validated format; no floating-point canonical fields. Keep generation counters in a bounded positive int32 range and fail on exhaustion rather than wrap. The fake artifact payload is canonical UTF-8 JSON represented as a string on the internal wire and validated before conversion to byte storage; arbitrary binary codecs are excluded. TypeSpec reference models are explicit named models, not generic type support. Assessment/capsule/replay references reuse the existing Artifact marker. Public and internal entrypoints define visibility in a build-bound input inventory; user-supplied visibility cannot relabel a source without changing its bound source policy.

## Task B2: Public products and generated Rust DTOs

**Interfaces:** Define a compiler-private `TargetBundle` containing typed public operations/models, internal Rust DTO definitions, and protocol metadata. `lower(graph: &MindcladeGraph) -> Result<TargetBundle, Vec<Diagnostic>>`; `emit(bundle: &TargetBundle) -> Result<Publication, Vec<Diagnostic>>` uses A1's owned publisher.

Generated TypeScript exports `EchoRequest`, `EchoResponse`, `EchoError`, and:

```typescript
export function createEchoClient(options: {
  baseUrl: string;
  fetch?: typeof globalThis.fetch;
}): {
  echo(requestId: string, body: EchoRequest,
       options?: { signal?: AbortSignal }): Promise<EchoResponse>;
};
```

Generated Rust exports `EchoRequest`, `EchoResponse`, `EchoError`, internal DTOs and:

```rust
pub trait EchoCapability: Send + Sync {
  fn echo(&self, request_id: &str, request: EchoRequest) -> Result<EchoResponse, EchoError>;
}
```

Private server composition implements this trait. No public TypeScript Run/Lease/database options.

## Task B3: Descriptor-composed RuntimeKit service

**Interfaces:** RuntimeKit defines `Clock::now_millis() -> u64`, `IdentityProvider::identity() -> Identity`, and `ShutdownSignal::requested() -> bool`, all Send+Sync. It accepts generated `ServiceConfig` and an EchoCapability implementation through:

```rust
serve(config: ServiceConfig, capability: Arc<dyn EchoCapability>, lifecycle: Lifecycle)
  -> Result<RunningService, RuntimeError>
```

Codegen's internal `CompiledServiceDescriptor` never becomes a RuntimeKit dependency; exact configuration and lifecycle types are defined in the completion companion. `RunningService` exposes bound address and `shutdown(self) -> Result<(), RuntimeError>`. `RuntimeError` distinguishes config, identity, bind, transport, and shutdown failures.

TestKit implements ManualClock (`advance(u64)`), FixedIdentity, and named FaultBarrier (`arrive(name)`/`release(name)`).

`services/foundation_echo/src/ports.rs` defines:

```rust
pub trait AdmissionPort: Send + Sync {
  fn execute(
    &self,
    context: &AdmissionContext,
    request_id: &str,
    request: EchoRequest
  ) -> Result<EchoResponse, EchoError>;
}
```

`AdmissionContext` contains trusted tenant/environment/identity and compiled descriptor digest. The service's EchoCapability wrapper obtains this context from composition, never caller-controlled headers.

B3 supplies a deterministic in-memory collaborator explicitly named `TestAdmission`. C5 replaces it with the durable implementation for accepted end-to-end evidence.

- [ ] Add failing descriptor tests for duplicate YAML keys, aliases/tags, unknown sections, embedded secret values, invalid path/capability references, unsupported protocol and public/internal mismatch. Choose and pin a maintained YAML parser whose node/event API can reject duplicates before deserialization; record that dependency decision. Do not accept lossy serde conversion that has already discarded duplicate keys.

Admit a pinned tiny_http version only after the B3b slow-body/deadline/shutdown capability tests pass; otherwise obtain a reviewed transport-spec amendment. Compile generated Rust transport into the service; lifecycle code owns sockets and shutdown, domain code owns execution.

## Task B4: Executable architecture and dependency enforcement

**Why added:** The supplied foundation audit confirms that `scripts/validate_repository.py` checks structural inventory, not semantic import layering. The four named architecture/dependency/descriptor/provenance validators are still exit-2 stubs. B4 closes this plan gap for activated VS-001 components; it does not claim independent ownership or full-platform enforcement.

**Files:** Extend `docs/architecture/model/architecture.yaml` through a reviewed schema extension and teach Codegen's B3 YAML adapter to validate it. Add `codegen/src/boundaries.rs`, `codegen/tests/cases/boundaries.rs`, `tools/build/dependency_facts.bzl`, `tools/validation/dependency_facts.py`, `tools/validation/typescript_facts.mjs`, and `tools/validation/test_boundary_entrypoints.py`. Replace exactly the existing `arch-lint.py`, `dependency-lint.py`, `descriptor-lint.py`, and `generated-provenance.py` stubs through manifest transitions. Modify compiler CLI/inventory/BUILD, justfile and CI policy tests. Do not activate `architecture.v1.json`, `ownership.v1.json` or `dependencies.v1.json`.

**Interfaces:**

```rust
struct DependencyFactsV1 {
  candidate: String,
  source_inventory_digest: Digest,
  configurations: Vec<String>,
  edges: Vec<ObservedDependency>,
}

struct ObservedDependency {
  from: String,
  to: String,
  kind: DependencyKind,
  configuration: String,
  origin: SourceLocation,
}
```

`DependencyKind` is Production, Build, or Test. The strings identify exact configured targets/packages/modules declared in the model, not arbitrary filesystem shortcuts.

```rust
fn check_boundaries(graph: &MindcladeGraph, facts: &DependencyFactsV1)
  -> Result<BoundaryReport, Vec<Diagnostic>>
```

Report contains sorted located violations, model/graph/facts digests and covered configurations, and `is_passing()` is false if any violation exists. Input/coverage failure returns diagnostics rather than an empty passing report.

CLI: `check-boundaries --input PATH --architecture PATH --facts PATH --out PATH` compiles the graph and applies authored rules; exit 0 passing, 2 violations, 1 invalid input/coverage/I/O. Facts are observations, not permission grants. An independent assessor regenerates them rather than trusting candidate-supplied facts.

- [ ] Add `BoundaryFixture::runtimekit_depends_on_service() -> BoundaryFixture` in the new Rust test module, with fields `graph` and `facts`. Build the graph through Compiler from an allowed YAML model; inject the disallowed observed edge only in facts. First regression:

```rust
#[test]
fn runtimekit_cannot_depend_on_domain_service() {
    let fixture = BoundaryFixture::runtimekit_depends_on_service();
    let report = check_boundaries(&fixture.graph, &fixture.facts).unwrap();
    assert!(!report.is_passing());
    assert!(report.violations.iter().any(|v| v.code == "forbidden-dependency"));
}
```

Define `BoundaryViolation { code: String, from: String, to: String, location: SourceLocation, reason: String }` and use this exact field in `BoundaryReport`. Add a permitted service-to-RuntimeKit positive control so rejecting everything cannot pass.
