**Goal:** Establish enforceable authority for supervised agent development.

**Architecture:** Git owns technical authority, Linear owns engineering work, and Notion holds context and outcome links. Codegen remains the sole semantic compiler. A work packet is neither permission to execute nor a concurrency lock.

**Execution:** Fresh implementer and reviewer per bounded task, then a fresh whole-branch review and Rob's acceptance. The parent runs all local validation commands and owns any Codex Process Jobs; workers never launch or monitor jobs.

**Stack:** Existing pinned Nix, Bazel, Rust, TypeSpec foundation, Python standard library for non-semantic governance checks, GitHub CLI for read-only API facts.

**Basis:** The user-approved plan in this task, AGENTS.md, accepted ADRs, current architecture YAML, and the reviewed Notion WF-01 principles.

## Global ConstraintGlobal Constraints

- Preserve concurrent VS-001 work. Do not edit another agent's checkout or adopt its unreviewed source. Consume its B4 boundary checker; do not duplicate it.
- YAML architecture remains authoritative; placeholder JSON registries stay inactive.
- No hand-edits to generated outputs or blanket resealing of scaffold stubs.
- Separate source verification, remote CI, protected review, runtime, scientific, release, and deployment claims. Missing evidence is BLOCKED, never PASS.
- Agents cannot accept their own work or relax policy in the same candidate.
- Rob accepts scope and merges; fresh agent review is not organizationally independent scientific or release assurance.
- Private GitHub Enterprise Cloud destination: `Mindclade-org/mindclade-vnext`. SAML authorization, entitlement, permissions, and inherited access are prerequisites.
- No coding or documentation App bypass, standing admin token in worker environments, vendor purchases, duplicate backlog, or automatic production publication.
- n8n and Mintlify are follow-on pilots, not prerequisites or installations here.

## Tasks

1. **Agent procedures and authority reconciliation:** populate roles, lifecycle, and security policy; replace the PR stub; add Linear work template and operator runbooks. Reconcile factual stale docs without importing unfinished VS-001.
2. **Admission:** strict versioned work packets and revision-bound reports, immutable accepted-policy inputs, approved packet digest, safe owned paths, stale-source rejection, and focused negative tests. Commands in packets are data, never eval.
3. **Remote governance and evidence:** read-only GitHub audit with API failure handling, exact-revision, check, and approval validation, local digest-bound evidence bundles, tamper verification, and operator-only immutable-release archival instructions.
4. **Integration:** activate only implemented scaffold paths, regenerate the mechanical tree, add merge_group CI, run focused and pinned verification, and independent review.
5. **Connected acceptance:** preflight and private transfer; scope the GitHub App; protect main, then activate queue only after merge_group runs. Test denials on a disposable protected probe. Complete one Linear-to-main-to-evidence loop.
6. **Documentation completeness:** provide the complete proposed engineering-system blueprint, document map, and requirements and evidence traceability. Distinguish implemented source, blocked operating gates, and optional future adapters; elaborate the existing platform blueprint without redesigning its semantics.
