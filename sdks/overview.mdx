MindClade's official client libraries let you integrate the full API surface into your application without hand-crafting HTTP requests. Both the JavaScript and Python SDKs wrap every endpoint, handle authentication, surface typed responses, and take care of transient failures — so you can focus on building features rather than infrastructure.

## What the SDKs Provide

Both libraries share a consistent set of capabilities built on top of the MindClade REST API:

- **Typed responses** — every method returns a fully typed object, giving you autocomplete and compile-time safety in TypeScript or Python type-checked projects.
- **Automatic retry on 429 and 500** — transient rate-limit errors and server faults are retried with exponential back-off before surfacing to your code.
- **Environment switching** — swap between `sandbox` and `production` with a single constructor option; no URL management required.
- **Promise / async support** — the JavaScript SDK is promise-native; the Python SDK ships both synchronous and `async/await` clients.
- **Webhook signature helpers** — built-in HMAC-SHA256 verification so you can validate incoming webhook payloads in one line.

## Choosing a Version

<Note>
  Always use the latest stable release of both SDKs. MindClade follows semantic versioning — patch and minor upgrades are backward-compatible. Check the [npm page for `@mindclade/sdk`](https://www.npmjs.com/package/@mindclade/sdk) or the [PyPI page for `mindclade`](https://pypi.org/project/mindclade/) for the current stable version before starting a new project.
</Note>
