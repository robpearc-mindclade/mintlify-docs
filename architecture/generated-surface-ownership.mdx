This page records the accepted target and partial source boundary for generated surface ownership in the Mindclade monorepo. It is an explanatory ownership reference, not an activation of generators or an allocation of a second copy of an output. ADR-002, ADR-003, ADR-013, and the [output policy](/architecture/generated-output-policy) govern.

<Warning>
  Status: explanatory ownership reference, 2026-09-23. This records the accepted target and the partial source boundary; it does not activate generators or allocate a second copy of an output.
</Warning>

## Protobuf is generated for TypeSpec-owned APIs

For VS-001 and TypeSpec-owned APIs, the authored interface is TypeSpec. Codegen consumes the official frontend's normalized input, seals `MindcladeGraph`, and lowers its validated meaning to Protobuf alongside OpenAPI and other projections. Do not hand-maintain a matching `.proto` contract, generate TypeSpec back from that output, or use emitted Proto as an additional semantic input for the same contract. The default [layered image](/architecture/platform-diagram) therefore shows Protobuf only among generated bindings and projections.

The original blueprint also reserves `contracts/protobuf/` and `codegen/frontend/protobuf/` for a **planned optional Protobuf-first frontend**. That is permitted only where a reviewed ownership decision intentionally chooses Protobuf as the authored authority for a distinct contract. It is not implemented by the current TypeSpec frontend, and an empty directory does not select it. Such a contract must still enter `SemanticInput` and the same Codegen/graph pipeline. No contract may have competing authored TypeSpec and Protobuf definitions. Published Proto can be a validated projection or published copy of a Proto-first contract; its publication destination is never a second authored owner.

`protocols/graphql/` and event projection directories are reserved target surfaces; their presence selects no GraphQL runtime or duplicate event authority. Any future activation must establish authored ownership and the same controls before use.

## Generated does not mean every machine-written file

Three mechanisms must not be conflated:

1. **Semantic products:** Codegen owns normalization, graph meaning, target IR, emitted semantic projections and their provenance. It may orchestrate pinned target tools; those tools do not rediscover Mindclade semantics.
2. **Mechanical maintenance:** the full repository tree is enumerated by `scripts/validate_repository.py`; lockfiles are produced by approved package tools; build intermediates come from the pinned build. These have no independent semantic authority and are not claims of a completed Codegen architecture view.
3. **Observed execution evidence:** receipts, test reports and external build/signing records describe actual execution. Canonical output hashes and variable receipt envelopes are distinct. `WorkPacket@v1` and `GovernanceReport@v1` are non-semantic engineering records, never generated capabilities or self-authorizing grants.

## Required control before activating any target

Each generator must declare its authored inputs, exact generator/tool and source identities, semantic graph, owner, complete output inventory, byte hashes, provenance, regeneration command, read-only drift check, and stale-file deletion policy. Remove only reviewed owned placeholders; never reseal changed stubs. Keep authored extension points outside disposable output zones. A missing output, unowned path, ambiguous authority, or unexplained drift is non-passing.

`nix develop --no-write-lock-file -c just generate-foundation` emits the owned foundation pair. `nix develop --no-write-lock-file -c just generate-vs001` emits the fourteen-file VS-001 composition catalog through the same compiler, binding the explicit architecture input, frontend descriptor inventory, and current/previous proto field-number registries. `just verify-generated` inside the pinned shell checks both inventories without repair. These commands emit only the VS-001 `generated/vs001/public/*` Proto/OpenAPI/MCP/README products, not the reserved `generated/protobuf/`, `protocols/`, `generated/openapi/`, or `generated/mcp/` destinations, or the planned infra catalogue.

The integration owner executes generation and consumer checks when authorized. See the [developer start here](https://github.com/Mindclade-org/mindclade-internal-monorepo/blob/main/docs/developer/start-here.md) for prerequisites and ownership.
