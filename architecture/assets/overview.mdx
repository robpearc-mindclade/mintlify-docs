### Image production and edits

The raster was produced by the image-generation tool, refined in the preceding alignment task, then edited here to resolve Protobuf authorship ambiguity. The initial layout guidance (38%/42%/20% column widths) appeared as unwanted labels; the retained edit removes those labels and decorative slogans. They were never implementation or completion percentages.

The previous four-responsibility poster remains recoverable in Git history; these responsibilities now appear as cross-cutting laws rather than replacing platform layers. The final focused edit shows TypeSpec, Domain IRs, and Source Models as authored inputs; Protobuf appears among generated bindings/projections. A future optional Protobuf-first contract requires distinct authored ownership, documented in the [ownership ledger](../generated-surface-ownership).

Image-model output is not claimed reproducible byte-for-byte.

### Editable Mermaid source

The [system-overview.mmd](https://github.com/Mindclade-org/mindclade-internal-monorepo/blob/main/docs/architecture/assets/system-overview.mmd) file is an authored editable Mermaid explanation of the same architecture. It is not the input used by the image model and does not regenerate the raster byte-for-byte. The [platform diagram](../platform-diagram) embeds the editable flow, explains arrow semantics, and provides a text equivalent.

## Status and accessibility

[Coverage](../foundations/blueprint-coverage) maps boxes to owners and maturity. Both text and labels communicate status without requiring color perception. The raster preserves the original target-reference checkpoint. The Mermaid and text views now also show the implemented bounded B2a TypeScript/Rust consumer subpath; the raster footer predates that work and is not current maturity evidence.

For future edits, change the explanatory sources together and visually review their agreement. Do not hand-edit files under `docs/architecture/generated/` to make this illustration seem compiler-produced. The planned architecture model, Codegen views, and provenance controls must first be implemented and verified.
