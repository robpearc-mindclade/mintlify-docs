This page records the 2026-09-23 partial B1 source review. Scope: `a561f18` relative to product base `0d5bba1`, then the combined candidate against governance main `86d125c`. This is fresh agent source review, not independent acceptance, protected review or qualification. Governance source/policies/CI are unchanged from main; only the mechanical inventory conflicted during merge.

## Findings and resolution

| Finding | Severity | Resolution and regression |
| --- | --- | --- |
| R1: HTTP body normalization discarded internal response-envelope ownership | P1 | Check resolved return types, including union alternatives, before envelope erasure. Frontend regression rejects an internal envelope around a public body with a located diagnostic. |
| R2: Explicit public-to-internal graph edges bypassed payload-reference checks | P1 | Sealing validates explicit edges against declaration visibility, with the source declaration location. Direct-builder regression rejects the edge. |
| R3: Serialized field roles were not checked against types and bindings | P2 | Validate status/body roles, required model bodies, numeric status literals, unique model metadata, internal value parameters and exact HTTP parameter roles. Hostile-input and valid-envelope regressions cover rejection and supported behavior. |

The parent observed the R1 frontend test fail by producing semantic input when rejection was expected. The R2/R3 Rust tests failed by successfully sealing the hostile input. A test-only type inference error was corrected before observing those behavioral failures; compilation failure was not counted as reproduction.

After the fixes, all ten declaration-focused Rust tests and all 30 frontend tests passed through the pinned Nix toolchain. The Rust body fixture now uses the official frontend's `body` role instead of the previously unchecked `value`. No expectations were relaxed and no v2 API/schema was introduced.
