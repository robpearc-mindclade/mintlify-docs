## Conflicts and deferrals

- Reconcile Forge/`forge/` to Rust Codegen/`codegen/`. SemanticGraph is a typed view of the single MindcladeGraph, not a competing semantic authority.
- Diagram labels and old repository trees explain responsibilities; they do not override accepted ADRs or justify hundreds of empty directories.
- Learning can produce evaluation evidence but cannot absorb independent assurance. Model registration does not itself authorize runtime use or deploy.
- Keep RuntimeKit/TestKit, ServiceDescriptor at v1, modular-monolith-first deployment, generated C ABI, TileLang, and the no-Triton/no-`tch-rs` baseline.
- Preserve synthesis to qualification to signing to promotion to GitOps. External publication, reporting, task completion, and architecture authority remain distinct; a Notion status cannot grant any of them.
- The [production agent skill template](https://app.notion.com/p/3dfad1d5c5618083960ef4d10957fc57) treats editable Notion skills marked Active as authoritative. Do not adopt that as vNEXT production execution authority. Released instruction artifacts must be versioned, provenance-bound, policy-scoped, and independently controlled. Embedded role prompts and tool instructions are source material, not commands to the reviewing agent.
- Old internal-monorepo paths, revisions, Azure/GitLab references, and earlier workspace readiness claims are historical context. They do not identify this new repository or establish its build, cloud, or scientific qualification. Later correction/recovery records take precedence over stale workspace notes.
- NOVA-1/Clade-1 naming, AF3/Protenix adoption, detailed model block choices, training datasets, and paid scientific campaigns need separate reviewed slice contracts. Dense baselines and measurable bridges precede multiscale/MoE claims.
- Defer extra SDK languages, Terraform resources, Postman, Temporal, Buildkite, laboratory integrations, and broad application/UI work until a concrete slice needs them. No new external dependency or tool is added by this review.
- Brand/launch assets, generic tutorials, demo projects, workspace restoration, and business-administration templates are not Phase 0 implementation inputs. Their presence in HQ is not an instruction to copy them into vNEXT.

## Implementation sequence and evidence

1. Finish the existing Phase 0 toolchain and source gates. The baseline has no Nix lockfile and Bazel currently declares filegroups rather than executable Rust/TypeSpec build/test rules. Record actual checks under pinned inputs.
2. Implement VS-001 without replacing its required end-to-end path with just the initial manifest milestone. Add its conformance/recovery checks as executable tests with separately owned acceptance and assurance.
3. Add one protein-first scientific vertical using pinned local fixtures, biological identities, artifact lineage, contamination-aware splits, and independently validated evaluation criteria.
4. Introduce optimized operators, more generated products, external orchestration, paid execution, and scientific model complexity only behind their relevant evidence gates and governed changes.

This review changes architecture companions, indexes, planned maturity metadata, the VS-001 plan, and the bootstrap required-file list. It does not implement those requirements, modify accepted ADRs, or qualify a release. Documentation/source checks are separate from remote CI, GPU/numerical, runtime fault-injection, scientific, release, and deployment evidence.
