## Standards findings

Two P2 documented-standard findings, both corrected:

1. **Anonymous response envelopes bypassed metadata validation.** The adapter now rejects unnamed response models before lowering, with located diagnostics. Named response envelopes remain supported. This enforces the explicit-failure rule in `docs/architecture/developer-products.md`.
2. **Malformed source-policy records could throw or silently select the compact frontend.** The adapter now validates the collection, entry and path types; explicitly supplied invalid policies fail with located diagnostics.

One labelled heuristic, possible Duplicated Code: route syntax validation was duplicated between compact and declaration inputs. Both now call one borrowed parser, retaining representation-specific binding checks. A table-driven test checks the same valid/invalid routes against both input forms. No speedup is claimed; this reduces duplicate logic and temporary string ownership.

## Spec findings

Three P2 findings, all corrected within v1:

1. **Anonymous response metadata was silently omitted**, contrary to the durable capability design requirement to reject unrepresented decorators. Frontend tests cover decorated, optional-body and plain anonymous envelopes.
2. **Internal operation parameter `@path` and `@body` metadata was erased**, contrary to B composition's requirement to represent resolved decorator meaning. These now fail with located `unsupported-http` diagnostics.
3. **Literal values contradicting their own constraints could seal.** Rust now checks integer bounds, Unicode-scalar string-literal length and the two admitted pattern forms against the literal, enforcing B composition's invalid limit rejection. This is not full runtime string/array validation.

These axes intentionally retain their overlapping finding rather than combining or reranking them. Missing authored contracts, build-bound CLI inventory, expanded compatibility, descriptors and downstream execution remain explicitly partial B1-D4 scope, not newly completed work.
