## Implemented source boundary

The official TypeSpec frontend inventories explicitly declared descriptor paths and exact bytes. The Bazel action supplies declared inputs; it does not interpret YAML. Rust Codegen alone owns the bounded event-based YAML parser, architecture ownership validation, closed Foundation Echo TestAdmission descriptor profile, operation resolution, and immutable final graph binding. Architecture and service views borrow the same graph rather than creating another semantic authority.

The parser checks decoded duplicate keys, document count, scalar/key types, forbidden aliases/anchors/tags/merge keys, UTF-8/NUL, and input/depth/node/scalar limits. Diagnostics are located and redact authored scalar values and vendor messages. Exact input rules remain at [ServiceDescriptor@v1](../service-descriptor-v1) and the [architecture profile](../architecture-source-profile).

The explicit `compile-vs001-services` route accepts SemanticInput, an architecture source path, source root, and output path. It verifies descriptor inventory and byte digests, binds source ownership, and validates the candidate before publication. Bounded Unix file reads require regular files within the declared source root; source directories must remain stable during the build. These checks do not claim to sandbox adversarial concurrent ancestor-directory replacement.

The service profile extends the five checked language products plus graph and manifest with `service/descriptor.json` and `service/config.rs`: nine files total, with eight non-manifest output digests. The manifest also binds architecture and descriptor input digests. The descriptor-free route retains seven files for isolated compatibility tests. Both routes use the existing recoverable owned publisher. Missing service outputs are failures, not an accepted partial catalog.

The inspection projection and checked RuntimeKit constructor do not implement RuntimeKit, generated HTTP transport, a listener, readiness, or finite shutdown. The reviewed [configuration ABI](../service-config-v1) is the integration contract for later B3b work. RuntimeKit, TestKit, and the service remain planned in implementation maturity. Other original blueprint descriptors remain sealed stubs.
