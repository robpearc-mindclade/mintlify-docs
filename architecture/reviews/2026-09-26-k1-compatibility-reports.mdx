They are not a baseline acceptance, a waiver or a qualification. Every report returned exit 2 and is **non-passing**. Contract-owner acceptance of the B1 baseline remains **pending Rob**.

## Policy change

K1-12 (Track B, `65d6560`) changed one line of the compatibility policy (`POLICY` in `codegen/src/compatibility.rs`). The line `expanded-declarations=directional; mixed-representation=unsupported` became two lines: `expanded-declarations=directional` and `mixed-representation=compact-lifted-to-expanded(public,intrinsic-bounds,one-success-alternative)`. A compact public declaration is now lifted to the expanded form before it is compared, so a namespace move or a representation change no longer hides a public narrowing.

### K1-12: the public narrowing, itemized

The renamed foundation fixture declares the same public `EchoRequest`, `EchoResponse` and `echo` as the current contract, so they are matched rather than reported as removed. The report itemizes these breaking changes:

- `EchoRequest`: `message` gains `max_length` 4096; `tags` gains `max_items` 128; `tags[]` gains `max_length` 64; `tags` changes type from `string[]` to `Tag[]`.
- `echo`: `requestId` gains the pattern `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`, `max_length` 128 and `min_length` 1; the resolved HTTP response alternatives change (`http-alternatives-changed`, the new 400, 409 and 503 alternatives).

`EchoResponse.message` gaining `max_length` 4096 is response-domain narrowing: compatible by policy, and still itemized. No `EchoRequest`, `EchoResponse` or `echo` change is reported as `declaration-removed` or `unsupported-representation-change`. The `official_frontend_tests` test `k1_12_renamed_foundation_fixture_itemizes_public_narrowing_as_breaking` asserts the same items.

### K1-31: capability on Admission

The post-B1a → post-K1 report has one change: `Mindclade.Internal/Admission`, `unclassified-field-added` (field `capability`), class `unsupported`. `Admission` is an internal record that no operation references, so its use direction is unclassified and the addition fails closed. This is the admission-key change Rob decided (tenant, environment, capability, requestId). It is not a waiver.

## Inputs

[Input digests](https://github.com/Mindclade-org/mindclade-internal-monorepo/blob/main/docs/architecture/reviews/evidence/k1/input-digests.json) bind the four semantic inputs:

- `foundation-input.json`: the official `//codegen/frontend/typespec:echo` output. Its digest equals the B1a foundation input.
- `post-b1a-input.json`: the official `//codegen/frontend/typespec:vs001` output for the contract sources at main `72b762d`. Its digest equals the B1a post-B1a input; the vs001 contract sources did not change from B1a to `72b762d`.
- `post-k1-input.json`: the official `//codegen/frontend/typespec:vs001` output for this branch's contract sources, including K1-31's `execution.tsp` (`sha256:2522f19a848146d21690569d54de8d3fe47dbaf3844b7f6d4b285e023e1fd715`).
- `renamed-foundation-input.json`: `foundation-input.json` with two exact text replacements, the same transformation the K1-12 test applies. Every `"namespace":"Mindclade.Foundation"` becomes `"namespace":"Mindclade.Public"`, and the package `{"namespace":"mindclade","name":"foundation","version":"v1"}` becomes the current package `{"namespace":"mindclade","name":"vs001","version":"v1"}`.

To reproduce, build the official frontend targets at each revision, apply the replacements, and run `mindclade-codegen compat --old-input OLD --new-input NEW --direction old-client-new-server --out REPORT`. Compare the report, graph and policy identities above. These inputs are evidence, not additional authored contracts.
