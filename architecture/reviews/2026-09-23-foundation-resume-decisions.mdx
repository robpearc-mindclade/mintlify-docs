## B2a preserved decisions and implemented checkpoint

The following reviewed choices constrained B2a generation and are preserved for recovery. The [checked-product record](2026-09-23-vs001-products) identifies the implemented target IR, generated clients/DTOs, tests, and source checkpoint `041b62e`. B1a reference rules remain implemented; contract-owner acceptance of the non-passing wire/baseline transition is still separate and pending. Historical proposal wording below records design decisions, not a claim that these APIs are still absent.

1. **Transport profile representation.** Represent the reviewed transport profile explicitly in compiler-private `codegen/src/target_ir.rs` as `Vs001TransportProfile` with fixed profile identity `VS001TransportProfile@v1` and inclusive `max_body_bytes = 65536`. Populate it explicitly when lowering this bounded VS-001 product; never infer it from a scalar name or pretend TypeSpec supplied it. Bind `target_ir` bytes in the generator fingerprint and profile identity/value in the VS-001 manifest. B3 descriptor compilation must compare its limit to this same profile. This is a reviewed transport constraint from the design, not a new semantic compiler.
2. **HTTP base URL and media-type behavior.** Adopt proposed origin-only absolute http/https baseUrl behavior and urgent omitted/undefined/false behavior. Use compact JSON with no final LF for HTTP requests. Response media-type grammar: trim optional ASCII SP/HTAB around the whole header and separator; case-insensitive `application/json`; optional single semicolon parameter `charset=utf-8`, permitting SP/HTAB around equals and optional double quotes around utf-8; reject any other whitespace/control, parameter, duplicates, or trailing separator. Freeze examples before implementation. Redirect option is error; no automatic redirects/retries. TS strict type checking also enables `exactOptionalPropertyTypes`; model optional urgent explicitly as `boolean | undefined` so the declared runtime allowance is reflected in types.
3. **Public TS and Rust error classes.** `EchoError` with readonly `kind="api"`, status/code as the exact correlated authored alternatives, and message. `EchoValidationError` with `kind="validation"`. `EchoProtocolError` with `kind="protocol"`. `EchoTransportError` with `kind="transport"`, readonly `cause` holding the identical original rejection/reason, and readonly `aborted` boolean. Pre-aborted signal rejects before fetch as `EchoTransportError` with `cause` identical to `signal.reason` and `aborted=true`. A fetch rejection wraps its original cause; abort classification must use the supplied signal state, not turn an HTTP 503 into an abort. Rust `EchoError` has the three exact proposed domain variants and fixed status/code mapping; no transport variant. No new wire variant.
4. **Exact generated catalog for B2a.** Public `client.ts`, `rust/mod.rs`, `rust/public.rs`, `rust/internal.rs`, `rust/wire.rs`, `graph.json`, `manifest.json` below `generated/vs001`. Shared generated Rust wire routines and module glue avoid duplicated parsers and keep authored consumer wrappers outside emitter ownership. Compiled JS stays in Bazel output/runfiles. `emit(bundle)` returns deterministic product outputs in the existing Publication container; projection integration adds graph and exact source-bound manifest before publisher/verify. It must never submit an incomplete container to publication. No ambient filesystem reads in lower/emit. Existing foundation products and publisher checks remain intact.
5. **Generated Rust type signatures.** Generated Rust types expose checked `from_json(&[u8])`, `validate(&self)`, and `to_json(&self)` returning a generated `WireError`; explicit null for optional urgent rejects. Kernel conversions use checked `TryFrom<GeneratedRef>` into the matching sealed kernel reference, no retagging. Prefer private fields plus validating constructors/accessors so serde serialization cannot bypass invariants; if fields remain public, `Serialize`/`Deserialize` and every transport/bridge path must enforce validation. Freeze concrete consumer calls before emitters; no assumption that constructing a Rust struct validates it. Internal artifact text-to-bytes conversion must validate its unchanged canonical inner text before returning UTF-8 bytes.

Parent independently computed the two escaped-body fixture lengths using compact UTF-8 JSON: exactly 65536 and 65537 bytes; no product implementation used. These checks do not constitute generated-client execution.

## Why the B2 constraints matter

The explicit profile prevents transport policy being invented from scalar names. A narrow origin/media-type grammar and correlated errors keep transport behavior predictable without changing authored wire alternatives. Checked constructors, JSON paths, and reference bridges prevent serialization or struct construction from bypassing kernel invariants. A complete deterministic publication container avoids partial generation weakening the existing recoverable publisher. B3 must use the same admitted body limit; descriptor composition must not introduce a competing runtime YAML compiler. These are constraints on future reviewed work, not conformance results or accepted contract baselines.

## B2a interface freeze for the real vertical

Source implementation proposal, 2026-09-23. This resolves the three questions in the independently prepared B2a acceptance corpus before emitter work; it does not adopt an expanded compatibility baseline or grant operational acceptance.

- Adopt the recommended checked Rust signatures and private fields exactly: `from_json(&[u8]) -> Result<Self, WireError>`, `validate(&self) -> Result<(), WireError>`, `to_json(&self) -> Result<Vec<u8>, WireError>`; validating `new` constructors and read-only accessors from the corpus. Reference constructors fix the authored literal target; conversions use checked kernel constructors. No unchecked serde entry point. Internal record constructors accept their nonliteral fields in the sealed graph's canonical field-name order, documented in emitted source; public Echo constructors retain the exact named signatures in the corpus. Literal schema/workflow/kind fields are fixed by constructors and checked on deserialization.
- Invalid client factory input throws `EchoValidationError` synchronously, with zero fetch calls. Require a raw absolute HTTP(S) origin plus at most one root slash. Reject raw whitespace/control, backslash, credentials, non-root paths, and any query/fragment delimiter before WHATWG URL normalization. Scheme/host case and default-port normalization use `URL.origin`; output route is origin plus the authored route. The URL is not limited to loopback. Validate fetch availability at construction; do not require a global fetch when an injected function exists.
- A rejected body read is `EchoTransportError`, preserving the identical reason and supplied signal state. A successfully read malformed body is protocol error. For combined failures: validate requestId/body and byte size first, then check a pre-aborted signal, then invoke fetch once. A returned valid authored HTTP error remains an API error even if the signal becomes aborted afterward. No retries.

All other frozen behavior comes from the independently reviewed B2a acceptance corpus, the tracked foundation resume decisions and B2a plan. Runtime products derive contract types/constraints from the sealed graph; constants in the independently authored test corpus do not become a second compiler or production schema. Body limit remains explicit `VS001TransportProfile@v1` policy, not a type-name inference.

## Additive Rust interface review

Reviewed 2026-09-23: approve these additions as consistent with the B2a corpus:

```rust
pub enum EchoError {
    InvalidInput { message: String },
    IdempotencyConflict { message: String },
    Unavailable { message: String },
}
// Borrowing accessors on EchoError:
// status(&self) -> u16
// code(&self) -> &'static str
// message(&self) -> &str
// Checked accessor on the generated Completion model:
// artifact_json_bytes(&self) -> Result<Vec<u8>, WireError>
```

The generated status/code mapping must derive from the authored HTTP alternatives and literal codes (400/invalid_input, 409/idempotency_conflict, 503/unavailable), not a second runtime table or independent emitter schema. A variant cannot carry a caller-selected mismatching code/status. No transport variant or error-message length limit is added; existing checked serialization/decoding obligations remain.

Emit the artifact accessor from the field's effective canonical-JSON format, including any resolved scalar alias constraints, rather than the model/field display name. It validates the unchanged inner string and returns its exact UTF-8 bytes, including the single canonical terminal LF. Invalid inner text returns `WireError`; it must never be repaired, reordered, or normalized. Shared generated wire helpers may implement this check without a runtime dependency on Codegen. The method is a byte conversion, not verification that a separate claimed digest matches those bytes or proof of artifact storage/qualification.

This is interface/criteria approval only; no implementation or commands beyond scratch-file reading/writing were performed.
