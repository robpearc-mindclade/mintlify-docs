## Product boundary

The official TypeSpec frontend and sole Rust Codegen build one sealed graph. Compiler-private target lowering borrows that snapshot, checks public audience closure and returns the bounded VS-001 transport profile. The profile has an inclusive 65536-byte serialized request limit; standalone domain DTOs do not inherit that transport limit.

Codegen owns exactly seven files under `generated/vs001/`:

| File | Purpose |

## Fail-closed target and publication rules

The bounded projection accepts a POST with one required component-pattern path, a public model body and one supported JSON success alternative. Safe static route segments and a single whole-segment placeholder are checked before interpolation. Unsupported optional/array literals, reserved/capturing target names and duplicate error-model variants fail with located diagnostics before any output changes. Required model literals, ordinary optional primitives, model-valued arrays and body-bearing status 201 remain supported controls.

Every promised response is terminal and body-bearing. Informational 1xx, 204, 205 and 304 alternatives fail before publication, consistent with [HTTP content semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-6.4.1), [205 semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.3.6) and [Fetch null-body statuses](https://fetch.spec.whatwg.org/#null-body-status). The general graph can represent a broader HTTP vocabulary; this consumer profile must reject what its generated API cannot represent.

The shared publisher validates prior and new inventories, digests and overlapping or case-folded alias paths before mutation. It removes only exact, previously owned obsolete regular files; modified files, symlinks and unknown content are preserved by rejection. A recovery journal retains the previous manifest and deletion plan, with all preflight checks before mutation and the manifest installed last. Existing v1 journals without the optional deletion fields retain their canonical format. No separate cleanup process or recursive deletion path was introduced.
