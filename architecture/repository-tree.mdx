## Complete Responsibility Map

This table covers existing boundaries and planned platform responsibilities. `present` means the root has pre-existing bootstrap source, not that the capability works. `scaffolded` means only approved placeholders exist; implementation maturity stays planned. Owner labels are responsibilities, not proof of separate reviewer identities. CODEOWNERS currently routes review to the repository owner. Activation gates describe the introducing slice's acceptance obligations. A reviewed first contract/test/implementation can make a root present while its maturity and unsatisfied qualification gates remain explicitly open.

## Change Rules

1. Keep original-blueprint placeholders explicitly marked and manifest-listed.
2. Update the layout, maturity and slice contract together. Activating a planned root requires a reviewed state change, its owner and concrete acceptance gate.
3. Preserve independent assurance; directory names and CODEOWNERS alone cannot enforce it.
4. Refresh this inventory and run `just verify`. Changes to architecture laws additionally require ADR review. Scaffolding never proves implementation.
