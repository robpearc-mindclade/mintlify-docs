This is the architecture package for the greenfield repository. The authority order in [AGENTS.md](https://github.com/Mindclade-org/mindclade-internal-monorepo/blob/main/AGENTS.md) governs it; explanations and diagrams do not override accepted ADRs or implementation maturity.

Start with the [foundations reading guide](/architecture/foundations/overview) for the complete target system, the [system design](/architecture/system-design) for a single-page overview, or the [layered platform diagram](/architecture/platform-diagram) for visual orientation. The [blueprint coverage map](/architecture/foundations/blueprint-coverage) connects all 20 original sections and every image layer to owned paths and detailed references. The [documentation index](/index) separates design from developer and operator procedures.

## Active ADRs

- [ADR-015](/architecture/adr/adr-015-original-blueprint-scaffold-alignment) (Accepted): bounded explicit scaffold exception
- [ADR-016](/architecture/adr/adr-016-postgresql-outbox-durable-execution) (Accepted): PostgreSQL plus the transactional outbox as the durable execution substrate, with the rejected alternatives and the triggers for revisiting them
- [ADR-017](/architecture/adr/adr-017-runtimekit-transport-engine) (Accepted): RuntimeKit's transport engine moves to hyper on tokio behind the existing `Handler` interface before C5
- [ADR-018](/architecture/adr/adr-018-biosecurity-and-dual-use-controls): **Proposed** draft making hazard screening a precondition for generative-design capabilities and laboratory adapters
- [ADR-019](/architecture/adr/adr-019-pytorch-training-substrate): **Proposed** PyTorch training substrate
- [ADR-020](/architecture/adr/adr-020-kernel-adoption-and-operator-binding): **Proposed** kernel adoption and operator binding
- [ADR-021](/architecture/adr/adr-021-clade-adopt-or-build-gate): **Proposed** adopt-or-build gate for Clade representation and structure
- [ADR-022](/architecture/adr/adr-022-evaluation-and-data-split-standards): **Proposed** evaluation artifacts and data-split standards
- [ADR-023](/architecture/adr/adr-023-model-organization): **Proposed** model organization under `models/`

## Provenance and Qualification Companions

- [Execution reliability](/architecture/execution-reliability): identity, retries, ownership, budgets, recovery, independent acceptance, and reporting boundaries
- [Compiler and developer products](/architecture/developer-products): semantic parity, compatibility, audience closure, consumer tests, and release-set recovery

The architecture is allowed to evolve, but only through reviewed ADR changes and evidence-backed vertical slices.

## Engineering System

Read the [supervised system blueprint](/architecture/engineering/supervised-system-blueprint) for the complete proposed engineering workflow and its connection to the platform. The [requirements map](/architecture/engineering/requirements-traceability) connects each implementation-plan requirement to source, procedures and required acceptance evidence. [Governance status](/architecture/engineering/governance-status) records observed blockers without treating a proposed design as deployed. The [agent handoff](/developer/agent-handoff) records the working branch, verification/review state, preserved concurrent work and ordered resume steps.

The [developer guide](/developer/supervised-development), [packet contract](/developer/work-packet-v1), [governance tool contract](/developer/governance-tools) and [operator runbook](/operations/github-governance) own their detailed interfaces and procedures. The [Eve assessment](/architecture/reviews/2026-09-23-eve-factory) is pinned source analysis, not vendor adoption or execution qualification.
