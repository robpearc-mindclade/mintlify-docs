Every state change that occurs in your MindClade account — a resource being created, updated, or deleted — is recorded as an immutable event. The Events API gives you a queryable audit log of this activity, making it straightforward to debug integration issues, build activity feeds, replay historical state, or verify that your webhooks fired as expected. Events are read-only: you observe them, you do not create them directly.

<Note>
  Events are retained for **90 days**. Entries older than 90 days are automatically purged and cannot be recovered. If you need long-term storage, forward events to your own data store using [webhooks](/api-reference/endpoints/webhooks).
</Note>

---

## List events

`GET /events`

Retrieve a paginated list of events across your account. Filter by resource, event type, or combine both to narrow down to exactly the activity you're looking for. Results are returned in reverse-chronological order.

### Query parameters

<ParamField query="limit" type="integer" default="50">
  Maximum number of events to return per page. Accepts values between `1` and `100`.
</ParamField>

<ParamField query="cursor" type="string">
  Pagination cursor returned as `next_cursor` in the previous response. Omit to start from the most recent events.
</ParamField>

<ParamField query="resource_id" type="string">
  Filter events to only those associated with a specific resource. For example, `res_9gU4lXnYqRoM2wAb`.
</ParamField>

<ParamField query="type" type="string">
  Filter events by type. Accepted values: `resource.created`, `resource.updated`, `resource.deleted`, `event.triggered`. See the [Event Types](#event-types) section for descriptions of each.
</ParamField>

### Request example

<CodeGroup>
```bash cURL
curl "https://api.mindclade.com/v1/events?limit=20&resource_id=res_9gU4lXnYqRoM2wAb&type=resource.updated" \
  -H "Authorization: Bearer mk_live_4xKz9mPqRtL2vNwY8cJdB3sH"
```

```javascript JavaScript
import MindClade from "@mindclade/sdk";

const client = new MindClade({ apiKey: "mk_live_4xKz9mPqRtL2vNwY8cJdB3sH" });

const page = await client.events.list({
  limit: 20,
  resource_id: "res_9gU4lXnYqRoM2wAb",
  type: "resource.updated",
});

for (const event of page.data) {
  console.log(event.id, event.type, event.created_at);
}

if (page.has_more) {
  const nextPage = await client.events.list({ cursor: page.next_cursor });
}
```

```python Python
import mindclade

client = mindclade.MindClade(api_key="mk_live_4xKz9mPqRtL2vNwY8cJdB3sH")

page = client.events.list(
    limit=20,
    resource_id="res_9gU4lXnYqRoM2wAb",
    type="resource.updated",
)

for event in page.data:
    print(event.id, event.type, event.created_at)

if page.has_more:
    next_page = client.events.list(cursor=page.next_cursor)
```
</CodeGroup>

### Response fields

<ResponseField name="data" type="array">
  Array of Event objects matching the applied filters.
</ResponseField>

<ResponseField name="next_cursor" type="string | null">
  Cursor to pass as the `cursor` query parameter to fetch the next page of results. Returns `null` when you have reached the oldest available event.
</ResponseField>

<ResponseField name="has_more" type="boolean">
  `true` when at least one additional page of results exists.
</ResponseField>

#### Event object

<ResponseField name="id" type="string">
  Unique identifier for the event, prefixed with `evt_`. Use this ID to cross-reference events with your webhook delivery logs.
</ResponseField>

<ResponseField name="type" type="string">
  The event type that was triggered. One of `resource.created`, `resource.updated`, `resource.deleted`, or `event.triggered`.
</ResponseField>

<ResponseField name="resource_id" type="string">
  The ID of the resource this event is associated with, prefixed with `res_`.
</ResponseField>

<ResponseField name="payload" type="object">
  A structured object describing what changed. For update events this includes `previous` and `current` sub-objects showing the before and after state. For creation and deletion events this contains the full resource snapshot at the time of the action.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the event was recorded. This reflects the moment the state change occurred, not when a webhook was delivered.
</ResponseField>

## Event types

MindClade emits four event types. Every event in the API and in webhook payloads uses one of these values in its `type` field.

| Event type | Triggered when |
|---|---|
| `resource.created` | A new resource is successfully created via `POST /resources`. |
| `resource.updated` | An existing resource's `name` or `metadata` is modified via `PATCH /resources/{id}`. |
| `resource.deleted` | A resource is permanently removed via `DELETE /resources/{id}`. |
| `event.triggered` | A custom platform-level event is emitted by MindClade on your account's behalf (for example, a scheduled job completing or a threshold being crossed). |

<Tip>
  Use the `type` filter on `GET /events` alongside `resource_id` to narrow your query to exactly the lifecycle moment you care about — for example, all `resource.deleted` events on a specific resource to audit its removal history.
</Tip>
