Every request to the MindClade API must be authenticated with an API key. Keys are associated with your account and carry scoped permissions, so you should treat them as secrets — never commit them to source control or expose them in client-side code. Manage all your API keys from the [MindClade dashboard](https://app.mindclade.com).

## API Key Format

MindClade issues two types of keys, distinguished by their prefix:

- **`mk_live_`** — Production keys. These authenticate requests against `https://api.mindclade.com/v1` and affect real data.
- **`mk_test_`** — Sandbox keys. These authenticate requests against `https://sandbox.api.mindclade.com/v1` and are safe to use during development and testing.

A typical key looks like `mk_live_4kTzYqN8mPwXrJsM2vBcQd`. Keys are 40 characters long after the prefix. If you accidentally expose a key, rotate it immediately from the dashboard — revoked keys stop working within seconds.

<Warning>
  Never use a production key (`mk_live_`) in development or test environments. Sandbox keys (`mk_test_`) are isolated and will not affect production data.
</Warning>

## Authorization Header

Pass your API key in the `Authorization` header using the `Bearer` scheme on every request. There is no session-based or cookie-based authentication — each request is independently verified.

```
Authorization: Bearer mk_live_xxxxxxxxxxxx
```

The examples below show how to set this header across common HTTP clients:

<CodeGroup>

```bash curl
curl https://api.mindclade.com/v1/resources \
  -H "Authorization: Bearer mk_live_xxxxxxxxxxxx"
```

```javascript JavaScript (fetch)
const response = await fetch("https://api.mindclade.com/v1/resources", {
  method: "GET",
  headers: {
    "Authorization": "Bearer mk_live_xxxxxxxxxxxx",
    "Content-Type": "application/json",
  },
});

const data = await response.json();
console.log(data);
```

```python Python (requests)
import requests

response = requests.get(
    "https://api.mindclade.com/v1/resources",
    headers={
        "Authorization": "Bearer mk_live_xxxxxxxxxxxx",
        "Content-Type": "application/json",
    },
)

data = response.json()
print(data)
```

</CodeGroup>

<Tip>
  If you're using the official SDKs (`@mindclade/sdk` for npm or `mindclade` for PyPI), pass your key during client initialization and the SDK handles the `Authorization` header automatically on every request.
</Tip>

## Error Responses

When authentication fails, the API returns a `401` or `403` response with a JSON error body. The table below lists every authentication-related error code, its HTTP status, and what it means.

| Error Code | HTTP Status | Meaning |
|------------|-------------|---------|
| `missing_api_key` | 401 Unauthorized | No `Authorization` header was included in the request. |
| `invalid_api_key` | 401 Unauthorized | The API key was provided but is not recognized — it may be malformed or revoked. |
| `invalid_key_environment` | 403 Forbidden | A sandbox key (`mk_test_`) was used against the production endpoint, or vice versa. |
| `insufficient_permissions` | 403 Forbidden | The key is valid but does not have the required scope to perform this action. |

An authentication error response looks like this:

```json
{
  "error": {
    "code": "invalid_key_environment",
    "message": "This key is a sandbox key and cannot be used with the production endpoint.",
    "details": {}
  }
}
```

If you encounter `insufficient_permissions`, check the key's scope settings in the [dashboard](https://app.mindclade.com) and ensure the key has been granted access to the relevant resource type and operation.
