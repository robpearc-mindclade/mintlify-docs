MindClade's REST API gives you full programmatic access to your resources, events, and webhooks over HTTPS. Every request and response uses JSON, making it straightforward to integrate with any language or toolchain. This page covers the foundational concepts — environments, request shape, response format, and versioning — so you can start making calls with confidence.

## Base URLs

MindClade provides two isolated environments. Use the sandbox for development and testing, and switch to production when you're ready to go live. API keys are environment-specific and will not work across environments.

| Environment | Base URL |
|-------------|----------|
| Production  | `https://api.mindclade.com/v1` |
| Sandbox     | `https://sandbox.api.mindclade.com/v1` |

## Request Format

All requests must be made over HTTPS — plain HTTP connections are rejected. When sending a request body (for example, `POST` or `PATCH` requests), set the `Content-Type` header to `application/json` and provide a valid JSON payload. Query string parameters are used for filtering and pagination on `GET` endpoints.

```http
POST /resources HTTP/1.1
Host: api.mindclade.com
Authorization: Bearer mk_live_xxxxxxxxxxxx
Content-Type: application/json

{
  "name": "My Resource",
  "type": "document"
}
```

## Response Format

Every API response is a JSON object. Successful responses return the requested or modified data directly. When you create a resource, the response always includes an `id` field that you can use in subsequent requests. Collections are returned under a `data` array alongside pagination metadata.

```json
{
  "id": "res_4kTzYqN8mPwX",
  "name": "My Resource",
  "type": "document",
  "created_at": "2024-11-01T12:00:00Z"
}
```

## Versioning

The current API version is **v1**, encoded directly in the URL path (for example, `https://api.mindclade.com/v1/resources`). MindClade does not use header-based versioning. When a new major version is introduced, it will be available at a new path prefix (e.g., `/v2`) while the previous version remains supported during a documented deprecation window.

## Making a Request

The example below fetches your first page of resources using `curl`. Replace `mk_live_xxxxxxxxxxxx` with your actual production API key, available in the [MindClade dashboard](https://app.mindclade.com).

```bash
curl https://api.mindclade.com/v1/resources \
  -H "Authorization: Bearer mk_live_xxxxxxxxxxxx"
```

A successful response looks like this:

```json
{
  "data": [
    {
      "id": "res_4kTzYqN8mPwX",
      "name": "My Resource",
      "type": "document",
      "created_at": "2024-11-01T12:00:00Z"
    }
  ],
  "next_cursor": "cur_9xBvLp2QrJsM",
  "has_more": true
}
```
