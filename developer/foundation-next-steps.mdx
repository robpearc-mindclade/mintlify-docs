## Earlier sequence and design decisions (history)

### B2b: public protocol products

B2b is implemented per the [frozen criteria](/superpowers/specs/2026-09-24-b2b-criteria); the notes below are the design decisions it followed. It originally remained a proposal requiring independently reviewed, frozen tracked criteria before implementation. The retained external draft is not required to recover these decisions; the following corrections supersede its conflicting text:

- Current and previous registries need distinct logical input paths and exact byte-hash bindings. Equal initial bytes are allowed. Remove the draft physical inode/alias distinction: inode separation does not establish an independently accepted baseline. Preserve bounded regular-file reads, confinement and declared input checks; do not confuse relaxing this extra identity restriction with permission for undeclared or escaping inputs.
- Allow fresh output and valid complete seven-file or nine-file predecessors to upgrade directly to the thirteen-file protocol profile. Do not require an unnecessary seven to nine to thirteen publication sequence.
- Use a closed internal profile enum for the legacy, service and protocol modes; avoid accumulating interacting booleans and optional inputs.
- Enforce profile downgrade rejection under the existing publisher lock and during journal recovery preflight, before replacement or removal. An older mode must not silently delete newer protocol products. Retain the existing transaction/lock authority and exact catalog validation; no second publisher.

Retain TypeSpec authority and derive public payload closure from resolved request and response bodies. The initial five messages are EchoRequest, EchoResponse, InvalidInput, IdempotencyConflict and Unavailable. HTTP response envelopes remain metadata, not payload messages or registry entries. Do not filter them by a name denylist. Initial protocol mode is v1-only; reject incompatible opaque revisions rather than relabeling them as `mindclade.public.v1`.

The explicit current/previous field-number registries supply compatibility numbers, not duplicate type definitions. Existing fields keep their numbers; removed fields reserve both old name and number; old reservations persist; new fields cannot reuse reserved numbers. Error `code=1` and `message=2` are active assignments, not reservations. Whole-message removal remains unsupported. This comparison proves numbering compatibility only, not full semantic compatibility or owner acceptance of the baseline.

Add four products from the same checked target representation: `public/openapi.json`, `public/echo.proto`, `public/mcp.json` and `public/README.md`. Thirteen files means twelve non-manifest output hashes. Proto is a messages-only projection, with optional-bool presence preserved; it does not encode every JSON requiredness/constraint and is not a runtime ingress validator. MCP is explicit custom tool metadata, not a running MCP server. Use actual pinned protoc and its decoded descriptor set for conformance; a mock, emitter JSON or checked-in binary fixture is not equivalent evidence. Freeze the remaining report/API/MCP/OpenAPI shapes and negative criteria before parent-run RED and implementation.

### B3b: actual RuntimeKit, TestKit and Echo composition

Status 2026-09-26: Stages A/B are integrated at `0d44a36` per the [frozen B3b criteria](/superpowers/specs/2026-09-24-b3b-criteria); Stages C/D (Codegen-emitted adapter, TestKit, non-durable composed Echo) merged through PR #18 at `72b762d` as non-durable partial VS-001. The notes below are the historical pre-criteria audit; the frozen criteria govern (std::net + httparse transport; tiny_http rejected).

The B3b readiness audit found the following interface gaps. These are proposed amendments, not implementation or approved transport dependencies. Resolve them through reviewed, frozen criteria before coding:

- RuntimeKit consumes a generic protocol-neutral handler. Echo-specific capability composition belongs in `services/foundation_echo`; RuntimeKit must not import generated Echo DTOs, service modules, Codegen, YAML or TestKit.
- A generated HTTP adapter is currently missing. Codegen must emit request/route/media/DTO and typed-response adaptation from resolved operation/profile data. Do not hand-maintain an Echo route/schema authority in the service.
- An arbitrary synchronous callback cannot be forcibly cancelled in-process. Closing the listener, cancelling socket I/O or detaching a thread does not prove that callback termination or finite shutdown occurred. Explicitly admit bounded cooperative TestAdmission with cancellation-aware waits, or review a different execution-isolation design. Hard termination requirements cannot be satisfied by pretending abandoned threads stopped.

Implement the pure checked RuntimeKit configuration ABI first after independent criteria and observed RED; compile the actual generated `service/config.rs` against the real crate. Then freeze listener/socket ownership, pre-header concurrency admission, absolute request/write/shutdown deadlines, bounded HTTP framing, trusted identities, readiness/control protocol and telemetry. Select and pin transport dependencies only after exact-source review and real capability probes. tiny_http suitability remains unestablished; cached alternatives are not approved by their presence.

Real-socket tests must exercise the generated client, bounds, malformed framing, slow requests, capacity, disconnects and shutdown, with guaranteed owned-process teardown. TestAdmission is non-durable. Client disconnection does not become cancellation of a future durable Run.
