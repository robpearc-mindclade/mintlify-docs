## Commands and check selection

The following commands belong to the authorized integration owner at the actual checkout root. Follow [start here](/developer/start-here#access-and-first-commands) for the pinned Nix launcher, features, supported hosts and provisioning. Do not replace missing inputs with global installs or host tools. `--offline` is useful only after the committed inputs are available; it is not a fresh-clone promise.

```bash Terminal
# Discover recipes without running a build, then diagnose local prerequisites.
nix develop --no-write-lock-file -c just
nix develop --no-write-lock-file -c just doctor

# A docs-only task may select this loop after reviewing its actual scope.
# Refresh the mechanical inventory only when paths changed.
nix develop --no-write-lock-file -c just update-tree
nix develop --no-write-lock-file -c just check
```

Doctor is a read-only diagnostic; dirty source blocks its clean-candidate claim and remains untouched. `check` runs fast, scaffold and tree/link checks, including Rust formatting and clippy. It runs no Bazel, generated drift or boundary check. `verify` is the full aggregate required for bootstrap work and run by CI. A scoped docs task must state why narrower local checks apply; it cannot waive remote CI.

| Changed area | Focused feedback and final selection |
| --- | --- |
| Prose/navigation | `verify-tree`, `verify-scaffold`; inspect wide/narrow rendering. `update-tree` for path changes; `check` for the fast aggregate. |
| Rust behavior | Relevant existing `just test <targets>` targets and `fmt-check`; select the full aggregate and behavioral evidence required by the task. |
| TypeSpec/frontend/compiler | Frontend, compiler and affected consumer/conformance targets; compatibility and deterministic regeneration for affected products. Follow the regeneration runbook before full verification. |
| Generator/build-bound input | Regenerate each affected catalog, inspect provenance/output diffs, then `verify-generated` and applicable build/boundary checks. |
| Toolchain/build graph/locks | Doctor, applicable flake/build/boundary checks and affected regeneration; reassess host and CI evidence. |

`just verify-generated` checks drift without repairing it. `just generate-foundation` and `just generate-vs001` actually write their owned catalogs; the parent follows the [regeneration runbook](/runbooks/regenerate-generated-outputs). `update-tree` only refreshes the repository inventory. The [local verification runbook](/runbooks/local-verification) explains each recipe and receipt; the [justfile](https://github.com/Mindclade-org/mindclade-internal-monorepo/blob/main/justfile) is executable command truth.

## Find the contract or codegen owner

Trace a change through the existing pipeline before assigning edits:

1. Authored [TypeSpec](https://github.com/Mindclade-org/mindclade-internal-monorepo/blob/main/contracts/typespec/README.md) defines the interface.
2. The [official frontend adapter](https://github.com/Mindclade-org/mindclade-internal-monorepo/blob/main/codegen/frontend/typespec/README.md) produces `SemanticInput@v1` (`SemanticInputV1` in Rust), with resolved language and HTTP data. Its descriptor inventory carries path, digest and location.
3. Rust [Codegen](https://github.com/Mindclade-org/mindclade-internal-monorepo/blob/main/codegen/README.md) receives descriptor bytes separately as `DescriptorSource`; [the compiler](https://github.com/Mindclade-org/mindclade-internal-monorepo/blob/main/codegen/src/pipeline.rs) checks a duplicate-free inventory/byte-source bijection and matching digests. It seals one immutable `MindcladeGraph` with borrowed typed views.
4. The bounded target IR, [`TargetBundle<'a>`](https://github.com/Mindclade-org/mindclade-internal-monorepo/blob/main/codegen/src/target_ir.rs), borrows that graph. Emitters and the recoverable publisher produce owned products and provenance; generated files never become authored truth.

| Symptom | Inspect the authored owner |
| --- | --- |
| Wrong declared operation/type/visibility | `contracts/typespec/` and its reviewed contract; do not patch the SDK. |
| Missing resolved TypeSpec/HTTP data | `codegen/frontend/typespec/src/`; the adapter does not replace the official compiler or build the semantic graph. |
| Wrong semantic validation, graph or compatibility | `core/` primitives and `codegen/src/{pipeline,graph,compatibility}*`; inspect the boundary that owns the rule. |
| Wrong generated serialization/client/adapter | `codegen/src/target_ir.rs` and `codegen/src/emit/`, then regenerate and test the actual consumer. |
| Publication/drift failure | `codegen/src/{projection,publication}*`, generator inputs and manifests; use the recovery runbook before another writing run. |
| Service behavior or lifecycle | `services/foundation_echo/` domain behavior or `platform/runtimekit/` infrastructure; generated DTOs do not implement durability. |

For TypeSpec-owned APIs, Protobuf is generated; the planned Proto-first boundary cannot co-own that contract. MCP metadata is not an MCP server, and the bounded Echo TypeScript client is not a complete multi-language SDK. Use the [surface ownership ledger](/architecture/generated-surface-ownership), [Echo reference](/api/vs001-echo) and [runtime foundations](/architecture/foundations/overview) for exact limits.

## Recover without repeating completed work

For an unknown recipe, use bare `just` in the pinned shell and select an existing recipe. For a doctor/toolchain failure, retain the sanitized output and follow [troubleshooting](/developer/troubleshooting); preserve locks and source while the owner resolves prerequisites. After a real source failure, reproduce the relevant failure, fix its owner and rerun affected checks before the final gates.
