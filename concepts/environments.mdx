MindClade gives you two completely independent environments — **sandbox** and **production** — so you can build, test, and iterate without any risk to live data or billable operations. Each environment has its own base URL, its own set of API keys, and its own isolated data store. Nothing you do in sandbox ever touches production, and vice versa.

## Environment Differences

The two environments are intentionally kept similar in behavior but differ in the ways that matter for safe development:

| | Sandbox | Production |
|---|---|---|
| **Base URL** | `https://sandbox.api.mindclade.com/v1` | `https://api.mindclade.com/v1` |
| **API key prefix** | `mk_test_` | `mk_live_` |
| **Rate limit** | 100 req/min | 1,000 req/min |
| **Data persistence** | Test data only — may be periodically reset | Fully persistent |
| **Billing** | No charges incurred | Billed per your plan |
| **Webhooks** | Delivered to registered endpoints | Delivered to registered endpoints |

Use sandbox throughout development, CI, and QA. Switch to production only when you are ready to go live with real users.

## Using the Right Environment

Switching environments requires exactly two changes: the **base URL** you point your client at, and the **API key** you pass in the `Authorization` header. The key prefix (`mk_test_` vs `mk_live_`) acts as a second line of defense — the API will reject a test key sent to the production endpoint, and a live key sent to the sandbox endpoint.

Retrieve your keys from the [MindClade Dashboard](https://app.mindclade.com) under **Settings → API Keys**.

<CodeGroup>

```javascript JavaScript
import MindClade from "@mindclade/sdk";

// Sandbox — safe for development and testing
const sandboxClient = new MindClade({
  apiKey: "mk_test_4xRqV7mNpL2sZdT9",
  baseUrl: "https://sandbox.api.mindclade.com/v1",
});

// Production — use only in your live environment
const productionClient = new MindClade({
  apiKey: "mk_live_9sT3kVwPqL8nZdR2",
  baseUrl: "https://api.mindclade.com/v1",
});

// Recommended: drive the choice from an environment variable
const client = new MindClade({
  apiKey: process.env.MINDCLADE_API_KEY,
  baseUrl: process.env.MINDCLADE_BASE_URL,
});
```

```python Python
import mindclade
import os

# Sandbox — safe for development and testing
sandbox_client = mindclade.Client(
    api_key="mk_test_4xRqV7mNpL2sZdT9",
    base_url="https://sandbox.api.mindclade.com/v1",
)

# Production — use only in your live environment
production_client = mindclade.Client(
    api_key="mk_live_9sT3kVwPqL8nZdR2",
    base_url="https://api.mindclade.com/v1",
)

# Recommended: drive the choice from an environment variable
client = mindclade.Client(
    api_key=os.environ["MINDCLADE_API_KEY"],
    base_url=os.environ["MINDCLADE_BASE_URL"],
)
```

</CodeGroup>

<Warning>
  Never commit production API keys (`mk_live_...`) to source control or use them in local development environments. A compromised production key can modify live data and trigger real billing. Store all keys in environment variables or a secrets manager and load them at runtime.
</Warning>

<Tip>
  Set `MINDCLADE_API_KEY` and `MINDCLADE_BASE_URL` in a `.env` file locally, and use your CI/CD platform's secrets store for staging and production deployments. This pattern means you never need to change application code when promoting between environments.
</Tip>

## Environment Isolation

Sandbox and production environments are fully isolated at the data layer. Resources, events, and webhooks created in sandbox are never visible in production, and the reverse is equally true.

This isolation has a few practical implications to keep in mind:

<Accordion title="Resources and events do not sync between environments">
  A resource you create with `POST /resources` in sandbox will have a different `id` than any corresponding object you later create in production. If your application stores MindClade resource IDs, make sure your own database records are scoped to the environment they came from.
</Accordion>

<Accordion title="Webhook endpoints must be registered separately per environment">
  Registering a webhook via `POST /webhooks` in sandbox only delivers events from sandbox. You must register your production endpoint separately using a production API key. This ensures that test traffic never leaks into your live webhook handler.
</Accordion>

<Accordion title="Sandbox data may be periodically reset">
  MindClade reserves the right to reset sandbox data during major platform updates. Do not rely on sandbox resources or events existing indefinitely — always seed test data programmatically at the start of your test runs so your test suite is self-contained and repeatable.
</Accordion>
