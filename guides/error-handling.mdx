Every API call can fail — network issues happen, inputs can be invalid, and rate limits get hit. MindClade returns structured, machine-readable error responses so your application can react intelligently to each failure mode instead of crashing or silently swallowing problems. This guide explains the error format, walks through every status code you'll encounter, and shows you how to build resilient retry logic.

## Error Response Format

When a request fails, MindClade returns a JSON body with a single top-level `error` object. This structure is consistent across all endpoints and error types:

```json
{
  "error": {
    "code": "resource_not_found",
    "message": "No resource with ID res_8aHq3mPzLxYwKdNvTcBe exists in your account.",
    "details": {
      "resource_id": "res_8aHq3mPzLxYwKdNvTcBe"
    }
  }
}
```

| Field | Type | Description |
|---|---|---|
| `error.code` | string | A stable, machine-readable error identifier you can `switch` on |
| `error.message` | string | A human-readable description of what went wrong |
| `error.details` | object | Optional extra context — field names, conflicting IDs, limits, etc. |

<Tip>
  Log the `error.code` field (not just the HTTP status) in your error tracking system. Codes like `rate_limit_exceeded` or `invalid_field_value` pinpoint the exact problem far faster than a bare `429` or `400` during an incident.
</Tip>

## HTTP Status Codes

MindClade uses standard HTTP status codes. Here is what each one means in practice and the most common causes you'll encounter:

<AccordionGroup>
  <Accordion title="400 Bad Request">
    The request was malformed or contained invalid field values. Check the `error.details` object for a list of which fields failed validation and why. Common causes:

    - A required field is missing from the request body
    - A field value is the wrong type (e.g., a string where a number is expected)
    - An enum field contains an unrecognized value

    These errors are **not safe to retry** without fixing the request first.
  </Accordion>

  <Accordion title="401 Unauthorized">
    The `Authorization` header is missing or the API key is invalid. Verify that:

    - The header is formatted as `Authorization: Bearer mk_live_...` or `Authorization: Bearer mk_test_...`
    - The key has not been revoked in the [dashboard](https://app.mindclade.com)
    - You are using the correct key for the environment (sandbox keys won't work against the production base URL)

    These errors are **not safe to retry** without correcting the credentials.
  </Accordion>

  <Accordion title="403 Forbidden">
    The API key is valid but does not have permission to perform this action. This typically means the key's scope doesn't include the requested operation. Check the key's permissions in the dashboard under **API Keys → Manage**.

    These errors are **not safe to retry** — you need to use a key with the appropriate permissions.
  </Accordion>

  <Accordion title="404 Not Found">
    The resource ID in the URL does not exist, or has been deleted. Double-check the ID in your request. If you are using a cursor from a paginated response, it may have expired (cursors are valid for 24 hours).

    These errors are **not safe to retry** without confirming the resource exists.
  </Accordion>

  <Accordion title="409 Conflict">
    The request conflicts with existing data — for example, attempting to create a resource with a name that must be unique, or updating a resource that has been modified since you last read it. Check `error.details` for the conflicting value.

    These errors are **not safe to retry** without resolving the conflict.
  </Accordion>

  <Accordion title="429 Too Many Requests">
    Your application has exceeded the rate limit for the current environment: **1,000 req/min** in production or **100 req/min** in sandbox. Read the `X-RateLimit-Reset` header to determine when the limit resets and back off until then.

    These errors are **safe to retry** after the reset window. See [Handling 429 Rate Limits](#handling-429-rate-limits) below.
  </Accordion>

  <Accordion title="500 Internal Server Error">
    An unexpected error occurred on the MindClade side. These are rare but can happen. The response body will include an `error.code` of `internal_error` and a request ID you can share with [MindClade support](https://app.mindclade.com/support).

    These errors are **safe to retry** with exponential backoff, as the issue is typically transient.
  </Accordion>
</AccordionGroup>

## Handling 429 Rate Limits

When you receive a `429`, do not retry immediately — wait until the rate limit window resets. MindClade includes three headers on every response to help you manage this:

| Header | Description |
|---|---|
| `X-RateLimit-Limit` | Total requests allowed per minute |
| `X-RateLimit-Remaining` | Requests remaining in the current window |
| `X-RateLimit-Reset` | Unix timestamp (seconds) when the window resets |

Read `X-RateLimit-Remaining` proactively on every response, not just on `429` errors — this lets you slow down before hitting the limit rather than after.

<CodeGroup>
```javascript JavaScript
async function requestWithRateLimitHandling(fn, maxRetries = 3) {
  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    const response = await fn();

    if (response.status !== 429) {
      return response;
    }

    if (attempt === maxRetries) {
      throw new Error("Rate limit exceeded and max retries reached.");
    }

    const resetAt = parseInt(response.headers.get("X-RateLimit-Reset"), 10);
    const now = Math.floor(Date.now() / 1000);
    const waitMs = Math.max((resetAt - now) * 1000, 1000); // at least 1 second

    console.warn(`Rate limited. Retrying in ${waitMs}ms (attempt ${attempt + 1}/${maxRetries})...`);
    await new Promise((resolve) => setTimeout(resolve, waitMs));
  }
}
```

```python Python
import time
import math

def request_with_rate_limit_handling(fn, max_retries=3):
    for attempt in range(max_retries + 1):
        response = fn()

        if response.status_code != 429:
            return response

        if attempt == max_retries:
            raise RuntimeError("Rate limit exceeded and max retries reached.")

        reset_at = int(response.headers.get("X-RateLimit-Reset", 0))
        now = math.floor(time.time())
        wait_seconds = max(reset_at - now, 1)  # at least 1 second

        print(f"Rate limited. Retrying in {wait_seconds}s (attempt {attempt + 1}/{max_retries})...")
        time.sleep(wait_seconds)
```

## Retrying Safely

Not all errors should be retried. Retrying a `400` with the same payload will always produce the same `400`, wasting quota and adding latency.

| Status | Safe to retry? | Strategy |
|---|---|---|
| `400` | No | Fix the request payload first |
| `401` | No | Correct or rotate the API key |
| `403` | No | Use a key with the right permissions |
| `404` | No | Confirm the resource exists |
| `409` | No | Resolve the conflict before retrying |
| `429` | Yes | Wait for `X-RateLimit-Reset`, then retry |
| `500` | Yes | Retry with exponential backoff |

For `429` and `500` errors, use **exponential backoff with jitter** — doubling the wait time between each attempt and adding a small random offset prevents all clients from hammering the API again at exactly the same moment.

## Complete Error-Handling Wrapper

The following example wraps the MindClade client with a full retry loop that handles rate limits, transient server errors, and non-retryable failures in one place:

<CodeGroup>
```javascript JavaScript
const RETRYABLE_STATUSES = new Set([429, 500]);
const BASE_DELAY_MS = 500;

async function mindCladeRequest(fn, maxRetries = 4) {
  let lastError;

  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    try {
      return await fn();
    } catch (err) {
      lastError = err;
      const status = err?.response?.status;

      // Do not retry client errors (except 429)
      if (status && !RETRYABLE_STATUSES.has(status)) {
        const code = err?.response?.data?.error?.code ?? "unknown_error";
        throw new Error(`MindClade API error [${status}] ${code}: ${err.message}`);
      }

      if (attempt === maxRetries) break;

      // For 429, respect the reset header; for 500, use exponential backoff
      let delayMs;
      if (status === 429) {
        const resetAt = parseInt(err.response.headers["x-ratelimit-reset"], 10);
        const now = Math.floor(Date.now() / 1000);
        delayMs = Math.max((resetAt - now) * 1000, BASE_DELAY_MS);
      } else {
        const jitter = Math.random() * 200;
        delayMs = BASE_DELAY_MS * Math.pow(2, attempt) + jitter;
      }

      console.warn(
        `Attempt ${attempt + 1} failed with ${status}. Retrying in ${Math.round(delayMs)}ms...`
      );
      await new Promise((resolve) => setTimeout(resolve, delayMs));
    }
  }

  throw lastError;
}

// Usage
const resource = await mindCladeRequest(() =>
  client.resources.create({ name: "Resilient Resource" })
);
```

```python Python
import time
import random
import math

RETRYABLE_STATUSES = {429, 500}
BASE_DELAY_SECONDS = 0.5

def mindclade_request(fn, max_retries=4):
    last_error = None

    for attempt in range(max_retries + 1):
        try:
            return fn()
        except Exception as err:
            last_error = err
            status = getattr(getattr(err, "response", None), "status_code", None)

            # Do not retry client errors (except 429)
            if status and status not in RETRYABLE_STATUSES:
                error_body = getattr(err, "response", None)
                code = "unknown_error"
                if error_body:
                    try:
                        code = error_body.json()["error"]["code"]
                    except Exception:
                        pass
                raise RuntimeError(f"MindClade API error [{status}] {code}: {err}") from err

            if attempt == max_retries:
                break

            # For 429, respect the reset header; for 500, use exponential backoff
            if status == 429:
                reset_at = int(err.response.headers.get("X-RateLimit-Reset", 0))
                delay = max(reset_at - math.floor(time.time()), BASE_DELAY_SECONDS)
            else:
                jitter = random.uniform(0, 0.2)
                delay = BASE_DELAY_SECONDS * (2 ** attempt) + jitter

            print(f"Attempt {attempt + 1} failed with {status}. Retrying in {delay:.1f}s...")
            time.sleep(delay)

    raise last_error


# Usage
resource = mindclade_request(
    lambda: client.resources.create(name="Resilient Resource")
)
```
