Webhooks let your application react to MindClade events the moment they happen, without polling the API. When a resource is created, updated, or deleted — or when an event is triggered — MindClade sends an HTTP `POST` request to a URL you specify, carrying a signed JSON payload that describes exactly what changed. This guide covers everything from registering your first endpoint to verifying signatures and handling delivery retries reliably.

## Registering a Webhook

Call `POST /webhooks` to tell MindClade where to send event notifications. Provide a publicly reachable `url` and an array of `events` you want to subscribe to. You can subscribe to any combination of the four available event types.

<CodeGroup>
```javascript JavaScript
const webhook = await client.webhooks.create({
  url: "https://app.example.com/webhooks/mindclade",
  events: [
    "resource.created",
    "resource.updated",
    "resource.deleted",
    "event.triggered",
  ],
});

console.log("Webhook registered:", webhook.id); // wh_5rNqBmYzLvPkXdTcHfGa
```

```python Python
webhook = client.webhooks.create(
    url="https://app.example.com/webhooks/mindclade",
    events=[
        "resource.created",
        "resource.updated",
        "resource.deleted",
        "event.triggered",
    ],
)

print("Webhook registered:", webhook.id)  # wh_5rNqBmYzLvPkXdTcHfGa
```

```bash cURL
curl -X POST https://api.mindclade.com/v1/webhooks \
  -H "Authorization: Bearer mk_live_9vBpWxRqMnKdYcLzTjHe" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://app.example.com/webhooks/mindclade",
    "events": [
      "resource.created",
      "resource.updated",
      "resource.deleted",
      "event.triggered"
    ]
  }'
```
</CodeGroup>

The `url` field must be an HTTPS endpoint accessible from the public internet. The `events` array determines which event types trigger a delivery — subscribe only to the events your application actually handles to reduce unnecessary traffic.

| Event | Triggered when |
|---|---|
| `resource.created` | A new resource is created in your account |
| `resource.updated` | Any field on a resource is modified |
| `resource.deleted` | A resource is permanently deleted |
| `event.triggered` | A platform-level event fires on a resource |

## Webhook Payload Structure

Every webhook delivery is a `POST` request with a JSON body. The top-level fields are consistent across all event types, with event-specific data nested inside `payload`.

```json
{
  "id": "evt_3kMwQpZxLyRvNbTdCgJa",
  "type": "resource.updated",
  "resource_id": "res_8aHq3mPzLxYwKdNvTcBe",
  "payload": {
    "previous": {
      "name": "My First Resource",
      "metadata": { "reviewed": false }
    },
    "current": {
      "name": "My First Resource (Revised)",
      "metadata": { "reviewed": true }
    }
  },
  "created_at": "2024-06-12T15:04:22Z"
}
```

| Field | Type | Description |
|---|---|---|
| `id` | string | Unique identifier for this delivery attempt |
| `type` | string | The event type, e.g. `resource.created` |
| `resource_id` | string | ID of the affected resource |
| `payload` | object | Event-specific data; shape varies by event type |
| `created_at` | string | ISO 8601 timestamp when the event was generated |

<Note>
  Respond with any `2xx` status code within **10 seconds** of receiving a delivery. If your handler takes longer, offload the work to a background queue and return `200` immediately — MindClade treats any response outside the 10-second window as a failure and will retry.
</Note>

## Verifying Signatures

MindClade signs every webhook delivery with HMAC-SHA256 using your webhook's secret key. The signature is sent in the `X-MindClade-Signature` header as a hex digest. Always verify this signature before processing the payload — it guarantees the request genuinely came from MindClade and has not been tampered with.

<Warning>
  Always verify the `X-MindClade-Signature` header in production. Skipping this check exposes your endpoint to spoofed events from any caller who knows your URL.
</Warning>

Retrieve your webhook secret from the [MindClade dashboard](https://app.mindclade.com) under **Webhooks → Settings**, then compute the expected signature and compare it to the header:

<CodeGroup>
```javascript JavaScript
import crypto from "crypto";

function verifyWebhookSignature(rawBody, signatureHeader, secret) {
  const expectedSig = crypto
    .createHmac("sha256", secret)
    .update(rawBody, "utf8")
    .digest("hex");

  // Use timingSafeEqual to prevent timing attacks
  const expected = Buffer.from(expectedSig, "hex");
  const received = Buffer.from(signatureHeader, "hex");

  if (expected.length !== received.length) {
    throw new Error("Signature length mismatch — rejecting request.");
  }

  if (!crypto.timingSafeEqual(expected, received)) {
    throw new Error("Invalid webhook signature — rejecting request.");
  }

  return true;
}

// Express example
app.post("/webhooks/mindclade", express.raw({ type: "application/json" }), (req, res) => {
  const signature = req.headers["x-mindclade-signature"];
  const secret = process.env.MINDCLADE_WEBHOOK_SECRET;

  verifyWebhookSignature(req.body, signature, secret);

  const event = JSON.parse(req.body);
  console.log("Verified event:", event.type, event.resource_id);

  res.sendStatus(200);
});
```

```python Python
import hashlib
import hmac
import os

def verify_webhook_signature(raw_body: bytes, signature_header: str, secret: str) -> bool:
    expected_sig = hmac.new(
        secret.encode("utf-8"),
        raw_body,
        hashlib.sha256,
    ).hexdigest()

    # Use compare_digest to prevent timing attacks
    if not hmac.compare_digest(expected_sig, signature_header):
        raise ValueError("Invalid webhook signature — rejecting request.")

    return True


# Flask example
from flask import Flask, request, abort
import json

app = Flask(__name__)

@app.route("/webhooks/mindclade", methods=["POST"])
def handle_webhook():
    signature = request.headers.get("X-MindClade-Signature", "")
    secret = os.environ["MINDCLADE_WEBHOOK_SECRET"]

    verify_webhook_signature(request.get_data(), signature, secret)

    event = request.get_json()
    print(f"Verified event: {event['type']} {event['resource_id']}")

    return "", 200
```
</CodeGroup>

<Tip>
  Always read the raw request body before parsing it as JSON. Parsing first and re-serializing can change whitespace or key ordering and cause signature verification to fail.
</Tip>

## Retries and Reliability

If your endpoint returns a non-`2xx` status code, times out, or is unreachable, MindClade automatically retries the delivery up to **three additional times** using exponential backoff:

| Attempt | Delay after previous failure |
|---|---|
| 1st retry | 1 minute |
| 2nd retry | 5 minutes |
| 3rd retry | 30 minutes |

After four total attempts (the original plus three retries), MindClade marks the delivery as failed and stops retrying. You can inspect failed deliveries and manually replay them from the [dashboard](https://app.mindclade.com) under **Webhooks → Delivery Logs**.

To maximize reliability:

- Return `200` immediately and process the event asynchronously in a background job.
- Make your handler idempotent using the event `id` field — retries deliver the same `id`, so you can safely deduplicate.
- Log the raw payload before processing so you can replay events locally if your handler has a bug.

## Deleting a Webhook

Remove a webhook registration with `DELETE /webhooks/{id}`. MindClade stops sending deliveries to that endpoint immediately.

<CodeGroup>
```javascript JavaScript
await client.webhooks.delete("wh_5rNqBmYzLvPkXdTcHfGa");
console.log("Webhook deleted.");
```

```python Python
client.webhooks.delete("wh_5rNqBmYzLvPkXdTcHfGa")
print("Webhook deleted.")
```

```bash cURL
curl -X DELETE https://api.mindclade.com/v1/webhooks/wh_5rNqBmYzLvPkXdTcHfGa \
  -H "Authorization: Bearer mk_live_9vBpWxRqMnKdYcLzTjHe"
```
</CodeGroup>

A successful deletion returns HTTP `204 No Content`. Any in-flight delivery attempts that were already queued before the deletion may still arrive at your endpoint, so keep your handler running briefly after deleting a webhook if ordering matters.
